# Технический долг (debt)

Принцип: **каждый срезанный угол записывается в тот же PR**, жёстким форматом. Не «потом вспомним», а «записали сейчас». Перед завершением PR открой этот файл и добавь всё, что не доделал.

Формат записи: `- [ ] <что не доделано> — <где (пути файлов)> — <когда вернуться/контекст>`.
Закрытая запись **удаляется** из файла в том же PR (не помечается `[x]`): краткое резюме закрытия — в body коммита, знание — в профильном `docs/features|contracts`.

Работает, потому что raw-ресурса с именем `default` в проекте нет; если такой ресурс когда-нибудь появится (например, `android/app/src/main/res/raw/default.*`), канал начнёт играть его вместо системного звука. - [ ] **Android < 8.0 (API < 26): каналы не существуют, звук управляется контентом.** `src/pages/playlist/lib/PlaylistOfflineNotifications.ts`, `src/pages/playlist/lib/playlistChannelIds.ts` — на Android 7.x (minSdk 24) `setNotificationChannelAsync` не создаёт каналы, и `content.sound` управляет звуком напрямую (`ArgumentsNotificationContentBuilder.shouldPlayDefaultSound`): прогресс использует `sound: false` (тихо и там), завершение/ошибка — `sound: true` (системный звук — совпадает с интентом alert-канала). Остаточный риск: если прогресс-уведомление перестанет передавать `sound: false` (например, вернётся `null`), на Android 7.x оно снова зазвучит. Ничтожная база пользователей — вернуться при жалобах с Android 7.x.

Вернуться при репортах о пропадании метаданных на медленных устройствах.
- [ ] **Застывшее audio-focus/MediaSession состояние на Android 15.** На Android 15+ нельзя запросить audio focus из фона (`expo/expo#46957`), застрявший фокус чистится только перезагрузкой ОС (`androidx/media#1928`). Вернуться, если жалобы на «застрявший звук» умножатся.
- [ ] **Context-only переключение плейлиста не пересобирает нативную очередь.** Та же проповедь продолжает играть, но текущим становится другой плейлист без вызова player-service → нативная очередь хранит прежний порядок, и следующий авто-переход пойдёт по нему, а не по новому плейлисту. — `src/entities/player/lib/PlayerService` (`native/queueContext.ts`, путь `setCurrentPlaylistAction` в `playNewSermonAsync`) — вернуться, если сценарий «та же проповедь в другом плейлисте» станет пользовательским.

Частично митигировано (2026-08-24): возврат в foreground триггерит `reassertLockScreenMetadata` (`useForegroundPlaybackReconcile` → `LockScreenControls.reassertMetadata`), который всегда проходит полный путь активации `setActiveForLockScreen(true)` и перепривязывает сервис — уведомление восстанавливается при следующем открытии приложения с играющим плеером. Остаётся сценарий «свайп + долгий фон без возврата в foreground» — вернуться при репортах «уведомление пропало после свайпа и не вернулось».

Вернуться при массовых жалобах (варианты: health-check инстансов с кэшем и периодическим пересчётом, авто-наполнение админ-списка из `https://api.invidious.io/instances.json`, свой инстанс в настройках).
- [ ] **Импорт через InnerTube сломается, когда YouTube поменяет приватный API или заблокирует `ANDROID_VR`.** — `src/features/sermon-audio-import/lib/youtubeSource/index.ts`, `lib/youtubeClients.ts` (клиент `ANDROID_VR`, itag 140, сессия без плеера) — `youtubei.js` неофициальная библиотека. ## Поиск

- [ ] **Голосовой ввод на iOS не реализован.** `src/features/sermon-search/lib/useVoiceInput.ts`, `src/features/sermon-search/lib/webSpeechRecognition.ts` — микрофон теперь виден на iOS всегда (при пустом запросе), но нажатие показывает информационный диалог «Голосовой ввод недоступен на этом устройстве»: `isVoiceInputAvailable` возвращает true только для web/android. Вернуться при появлении iOS-сборок: нужен нативный speech-модуль или `SFSpeechRecognizer` через config-плагин (prebuild) плюс разрешения `NSSpeechRecognitionUsageDescription`/`NSMicrophoneUsageDescription`. Web уже работает через Web Speech API, Android — через системный `RECOGNIZE_SPEECH` intent (`expo-intent-launcher`).
- [ ] **Патч `expo-intent-launcher` — временный обход краша на extras результата активности.** `patches/expo-intent-launcher+58.0.3.patch`, `node_modules/expo-intent-launcher/android/src/main/java/expo/modules/intentlauncher/IntentLauncherModule.kt`, проба в `scripts/check-patches.mjs` — MIUI-распознаватель речи кладёт в extras результата `android.app.ActivityOptions$ActivityOptionsInjector`; конвертер expo-modules-core не умеет превращать его в `WritableMap` и бросает `IllegalArgumentException` на main-потоке, приложение падает по FATAL до того, как промис дойдёт до JS (JS-обработка не спасает). Патч копирует в ответ только конвертируемые значения (String/примитивы/вложенные Bundle/коллекции). Вернуться при обновлении `expo-intent-launcher`: если апстрим научился фильтровать extras (issue в `expo/expo` про «Could not put ... to WritableMap») — удалить патч, пробу и эту запись.
