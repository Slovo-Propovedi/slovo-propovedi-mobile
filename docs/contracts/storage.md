# AsyncStorage — ключи и форматы

Локальное хранилище приложения — `@react-native-async-storage/async-storage` (key/value, строки). Хранит: JWT-токены (на native — в защищённом `expo-secure-store`), кэш секций, состояние плеера, реестр офлайн-проповедей, настройки сервера и темы, флаг кеширования проповедей, версию последнего уведомления об обновлении.

Константы ключей лежат в `src/shared/config/` (`player-storage-keys.ts`, `cache-storage-keys.ts`, `server-storage-keys.ts`) и реэкспортируются через `src/shared/config/index.ts`. Ключи, принадлежащие сущностям, объявлены внутри самих сущностей: `OFFLINE_SERMONS_REGISTRY`/`_SEEDED` — `src/entities/offline-cache/lib/storageKeys.ts`, `CACHED_SECTIONS` — `src/entities/section/lib/sections-cache/cacheKey.ts`, `MY_PLAYLISTS` — `src/entities/playlist/model.ts`. Ключи токенов объявлены прямо в `src/shared/api/axiosInstance.ts`.

## Формат

- **Структурированные данные** (аудио, плейлист, секции, результаты поиска) хранятся как **JSON-строки** через `JSON.stringify` / `JSON.parse`.
- **Простые скаляры** (позиция, громкость, длительность, режим повтора, тема, флаги) хранятся как строки через `String(...)`.
- **Безопасный парсинг JSON — через `getParseJsonWithSchema(schema)`** (`src/shared/model/getParseJsonWithSchema.ts`): оборачивает Zod-схему (`customZ.jsonSchema(...).safeParse`) и возвращает `undefined` при отсутствии/невалидности данных. Универсальные обёртки для кэша — `getCachedJson(key, schema)` / `setCachedJson(key, value)` (`src/shared/lib/cache/`): читают/пишут JSON под ключом с тем же безопасным парсингом. Используются для восстановления `AudioPlayerData`/`PlaylistData` (`src/entities/player/lib/initializePlayer.ts`), секций (`src/entities/section/lib/sections-cache/getCachedSections.ts`), результатов поиска (`src/features/sermon-search/lib/searchCache.ts`) и подсказок поиска (`src/features/sermon-search/lib/distinctValuesCache.ts`).
- Доменные Zod-схемы для восстановления: `entities/sermon/model/sermon.ts` (`sermonSchema`/`booksArraySchema`), `entities/sermon/model/audioPlayerData.ts` (`audioPlayerDataSchema`), `entities/playlist/model.ts` (`playlistDataSchema`, локальная `localPlaylistDataSchema`) и `entities/section/model.ts` (`sectionSchema`). `src/shared/model/domain/common.ts` держит только структурные формы (`SermonShape`/`PlaylistShape`/`SectionShape`).

## Жизненный цикл

- **Токены**: пишутся при входе/refresh (`secureTokenStorage.setTokens`, `performTokenRefresh`), читаются request-interceptor'ом и `performTokenRefresh`, чистятся при logout / неудачном refresh (`secureTokenStorage.clearTokens` в `axiosInstance.ts`). На native — `expo-secure-store`, на web — шифрованное IndexedDB-хранилище (AES-GCM/WebCrypto); кэш профиля (`SECURE_USER_KEY`) пишется `signIn`/`restoreSession` (`entities/auth`) и чистится при выходе.
- **Плеер** (`currentAudio`, `currentPlaylist`, позиция, громкость, скорость, режим повтора, длительность, баланс, pitch, эквалайзер): пишутся в Reatom-экшенах `src/entities/player/model.ts`, `src/entities/player/playback-rate.ts`, `src/entities/player/audio-settings.ts` и `PlayerService/*`; восстанавливаются при старте через `src/entities/player/lib/initializePlayer.ts` (multiGet + Zod-парсинг; настройки звука — через `restoreAudioSettings` → `audioEffectsPreferences`, нативные эффекты пере-присоединяются при каждой загрузке трека через локальный модуль `audio-effects`).
- **Crash-guard старта** (`playerStartupAttempts`): счётчик **подряд неудачных** стартов. `initializePlayer` читает его первым делом: при значении >= 3 восстановление плеера пропускается целиком (нативные вызовы не выполняются, атомы остаются пустыми), счётчик сбрасывается в 0; иначе счётчик инкрементируется и запись **await-ится до** любых нативных вызовов. Успешное восстановление (даже частичное: нет трека или трек не прошёл валидацию) сбрасывает счётчик в 0; инкремент остаётся только при брошенном исключении — поэтому порог == 3 означает три подряд неудачных старта. Ручной старт воспроизведения (`playNewSermonAsync`) тоже сбрасывает счётчик. При здоровом аптайме 30с `scheduleStartupGuardReset` (`src/entities/player/lib/startupGuard.ts`, вызывается один раз в `app/_layout.tsx`) сбрасывает счётчик в 0. Данные плеера/истории/кэша при пропуске не удаляются.
- **Кэш секций** (`cachedSections`): пишется после успешной загрузки с сети (online-first, fire-and-forget) и читается как фолбэк при недоступности сети. Логика — `src/entities/section/lib/fetchAllSections.ts` (`fetchAllSections`) + `src/entities/section/lib/sections-cache/`.
- **Локальные плейлисты** (`myPlaylists`): читаются при монтировании секции «Мои плейлисты» (`MyPlaylistsSlider`) и экрана `/listen/my-playlists` (`MyPlaylistsScreen`) через `loadMyPlaylists` с zod-валидацией (`myPlaylistsArraySchema`); невалидные данные трактуются как отсутствующие. При отсутствии ключа засеивается `[FAVORITES_PLAYLIST]` (`persistMyPlaylists`). Приводится к инварианту «Избранные первые» и кладётся в `myPlaylistsAtom`. Переупорядочивание drag-and-drop на экране «Мои плейлисты» сохраняет новый порядок тем же `persistMyPlaylists` (`reorderMyPlaylists`, локально, без сервера). Логика — `src/entities/playlist/model.ts` (`localPlaylists.ts` — схема/типы/инвариант), подробнее — [features/my-playlists.md](../features/my-playlists.md).
- **Кэш поиска проповедей** (`cachedSermonSearch:<query>`, `cachedSermonSearch:index`): пишется после успешного ответа `sermonControllerFindAll` (online-first, fire-and-forget в `fetchSearchResults`), читается как фолбэк при сетевой ошибке. Ключ запроса нормализуется (`trim` + `toLowerCase`). Пустые результаты не кэшируются. Индекс хранит до 30 последних ключей; при переполнении самые старые удаляются (`AsyncStorage.multiRemove`). Логика — `src/features/sermon-search/lib/searchCache.ts`.
- **Кэш подсказок поиска** (`cachedDistinctValues`): пишется после успешного ответа `sermonControllerGetDistinctValues` (online-first, fire-and-forget в `fetchDistinctValues`), читается как фолбэк при сетевой ошибке. Zod-валидация при чтении через `distinctValuesSchema`; невалидный кэш трактуется как отсутствующий. Логика — `src/features/sermon-search/lib/distinctValuesCache.ts`.
- **Реестр офлайн-проповедей** (`offlineSermonsRegistry`, `offlineSermonsRegistrySeeded`): пишется через `registerOfflineSermon`/`removeOfflineSermon`/`clearOfflineRegistry` (`src/entities/offline-cache/lib/offlineSermonsRegistry.ts`, fire-and-forget с сериализованной promise-цепочкой — последняя запись побеждает), читается при старте через `hydrateOfflineRegistry`. Одноразовый бэкфилл `seedOfflineSermons` (`src/features/offline-sermons/lib/seedOfflineSermons.ts`) заполняет реестр из легаси-источников (история/секции/поиск/текущий плейлист) и пишет флаг `offlineSermonsRegistrySeeded` только после успеха (сбой → повтор на следующем старте). Новые завершённые скачивания синхронизируются через watcher на `cachedUrlsAtom` (`useOfflineRegistrySync` в `app/_RootLayout.tsx` → `syncOfflineSermon`). Удаление из кэша (`markUrlEvicted`) и полная очистка (`clearCachedUrls`) чистят реестр синхронно. Подробнее — [features/audio-cache.md](../features/audio-cache.md) → «Реестр офлайн-проповедей».
- **История прослушивания** (`listeningHistory`): пишется через `writeHistory` (сериализация через `setCachedJson` с Zod-валидацией `listeningHistorySchema`; невалидные данные → сброс в `[]`). Пишется **по событиям и каждые 10с при воспроизведении** (тик `usePlaybackProgressSaver` → `flushHistoryProgressAction`): старт воспроизведения (`recordPlaybackStartAction` — позиция 0), flush при паузе (`flushHistoryProgressAction` — `PlaybackController.pause`, `WebPlayerService.pause`), flush при stop/unload (`PlaybackController.stop`, `WebPlayerService.stop`/`unload` — pre-stop позиция), flush при seek (`PlaybackController.seekTo` нативный и `WebPlayerService.seekTo` веб — общий debounced `scheduleHistoryFlush`, 400мс), переключение трека (`recordSermonSwitchAction` — из `usePlayNewSermon` и авто-перехода). Помечается как завершённая при окончании трека (`markHistoryCompletedAction` — `positionMs = durationMs`, длительность из атома), вызывается из `TrackAutoAdvanceService.handleTrackEnd` ДО ветвления путей. Удаляется per-item (`removeHistoryEntryAction`) и полностью (`clearHistoryAction`) из экрана истории. Загружается при старте приложения (`loadHistoryAction` в `app/_layout.tsx`), при этом `reconcileOnHydration` мержит мини-снапшот `listeningProgressSnapshot` в каталог. Массив дедуплицируется по `getEntrySermon(entry).id` и обрезается до 100 записей (`sortAndCapEntries`). Логика — `src/entities/listening-history/`.
- **Мини-снапшот прогресса** (`listeningProgressSnapshot`): **LEGACY** — больше не пишется при воспроизведении (писатель `writeLiveProgressSnapshot` из `usePlaybackProgressSaver` удалён; каталог `listeningHistory` теперь единственный источник). Хранится только для одноразовой миграции старых on-disk снапшотов при гидрации (`reconcileOnHydration`): мержится в совпадающую запись каталога (только если запись не завершена), `durationMs = max(entry, snapshot)`; осиротевший снапшот дропается. Чистится при каждом **реальном** flush каталога (`flushHistoryProgressAction`; no-op flush — позиция/длительность не изменились — выходит раньше и пропускает и запись, и очистку) и при reconcile/remove/clear — инвариант: «снапшот всегда не новее каталога; каждый реальный flush каталога чистит снапшот». Логика — `src/entities/listening-history/lib/liveProgressStorage.ts`, `reconcileOnHydration.ts`.
- **Сервер URL** (`server-url`): пишется при смене в Настройках, читается при старте (`initServerUrlAction`).
- **Тема** (`theme_mode`, `dynamic_colors`): пишутся при изменении, читаются при старте (`loadThemeMode`, `loadDynamicColors`).
- **Виброотклик** (`haptics_enabled`): пишется при переключении в Настройках (`setHapticsEnabled`), читается при старте (`loadHapticsEnabled`). Глобальный переключатель: выключает и тик перемотки, и haptic-отклик кнопок.
- **Кеширование проповедей** (`sermon_caching_enabled`, Issue #77): пишется при переключении `Switch` в шапке экрана «Офлайн» (`setSermonCachingEnabled`), читается при старте (`loadSermonCachingEnabled`) — **внутри** стартовой цепочки `app/_layout.tsx`, шагом **перед `initializePlayer()`** (и, следом, `reEnqueuePartialDownloads`): оба шага ставят закачки через гейт очереди, который читает атом, поэтому при дефолтном `true` холодный старт запустил бы фоновую закачку, даже если настройка выключена. Отсутствие ключа = кеширование включено (совместимость со старыми установками). Значение `false` — единственный источник истины для гейтов очереди закачек (`enqueueCache`/`enqueueCacheMany`) и для скрытия индикаторов/кнопок кэша. `setSermonCachingEnabled` работает оптимистично: per-ctx флаг `isSermonCachingUserTouchedAtom` и атом переключаются **синхронно, до** `AsyncStorage.setItem`, поэтому UI и гейты очереди реагируют сразу, без ожидания storage-round-trip; при провале `setItem` атом откатывается к предыдущему значению, а ошибка пробрасывается вызывающему (её логирует `.catch` в тумблере). Если пользователь нажал тумблер, пока стартовый `getItem` ещё в полёте, запись считается протухшей: тот же флаг заставляет `loadSermonCachingEnabled` вернуть прочитанное значение, но **не перезаписывать атом** — иначе позднее чтение откатывало бы тумблер к состоянию до нажатия. Семантика флага — «пользователь трогал тумблер» (а не «запись успешно сохранена»): откат при провале тоже не даёт гидрации перезаписать атом. Подробности — [features/audio-cache.md](../features/audio-cache.md) → «Отключение кеширования (#77)» и «Гонки переключателя».
- **Версия уведомления об обновлении**: пишется после показа, читается перед проверкой.
