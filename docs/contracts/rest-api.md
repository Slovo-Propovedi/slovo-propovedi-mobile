# REST API — «Слово.Проповеди»

Внешний контракт REST API приложения. **Подробный список эндпоинтов, типов и Zod-схем — в сгенерированном клиенте** `src/shared/api/generated/` (Orval из OpenAPI v0.2.0 «Admin API»); этот документ не дублирует его, а фиксирует **настройку фронта** и **карту реального использования** эндпоинтов. См. также [storage.md](./storage.md) (токены) и [local-db.md](./local-db.md) (временный источник данных для раздела книг).

## Base URL

- По умолчанию: `https://api.slovo-propovedi.ru` — константа `DEFAULT_API_URL` в `src/shared/config/config.ts`.
- `axiosInstance` создаётся с этим base URL в `src/shared/api/axiosInstance.ts` (`axios.create({ baseURL: DEFAULT_API_URL })`).
- **Можно менять в Настройках**: атом `serverUrlAtom` (`src/entities/settings/model.ts`). Экшены `setServerUrlAction` / `initServerUrlAction` синхронизируют `axiosInstance.defaults.baseURL` с выбранным URL и персистят его в AsyncStorage (ключ `SERVER_URL`, см. [storage.md](./storage.md)).

## Аутентификация — Bearer JWT

Реализация — `src/shared/api/axiosInstance.ts`:

- **Request-interceptor** читает access-токен из AsyncStorage (`ACCESS_TOKEN_KEY`) и добавляет заголовок `Authorization: Bearer <accessToken>`.
- **Response-interceptor**:
  - при успешном ответе отмечает сервер доступным (`reportServerReachable(ctx)`, см. `src/shared/model/network`);
  - при сетевой ошибке (сервер не ответил) отмечает недоступным (`reportServerUnreachable(ctx)`);
  - при `401` (кроме запроса refresh) помечает запрос `_retry` и вызывает `performTokenRefresh()`: отправляет `POST /auth/refresh` **сырым `axios.post`** с refresh-токеном, сохраняет новую пару токенов в AsyncStorage, повторяет оригинальный запрос с новым access-токеном;
  - при неудачном refresh очищает токены (`AsyncStorage.multiRemove([ACCESS_TOKEN_KEY, REFRESH_TOKEN_KEY])`) и отклоняет запрос. TODO: переход на экран логина не реализован (см. комментарий в `axiosInstance.ts`).

> ⚠️ `POST /auth/refresh` вызывается **напрямую axios**, а не через сгенерированную обёртку `authControllerRefresh`. Это единственный «живой» auth-эндпоинт.

## Хранилище токенов — `tokenStorage`

`src/shared/api/axiosInstance.ts`, объект `tokenStorage`:

- `setTokens(accessToken, refreshToken)` — сохраняет обе пары в AsyncStorage (`@access_token`, `@refresh_token`).
- `getAccessToken()` — возвращает access-токен.
- `clearTokens()` — удаляет обе пары (`multiRemove`).

Ключи: `@access_token` (`ACCESS_TOKEN_KEY`), `@refresh_token` (`REFRESH_TOKEN_KEY`). Подробно — [storage.md](./storage.md).

## Генерация клиента (Orval)

- **Команда:** `yarn api:generate`.
- **Источник:** OpenAPI-спецификация v0.2.0 «Admin API — Слово.Проповеди» — **находится вне этого репозитория** (в репозитории бэкенда/admin-панели). В проекте лежит только результат генерации.
- **Сгенерировано:** `src/shared/api/generated/` — **не редактировать вручную** (все файлы помечены «Generated by orval, Do not edit manually»).
- **Реэкспорт наружу:** `src/shared/api/index.ts` (`export * from './generated'`).
- **Типы:** все TS-интерфейсы — в `src/shared/api/generated/adminAPI.schemas.ts`, реэкспортированы как `APITypes`. Основные: `SermonEntity`, `PlaylistEntity`, `SectionEntity`, `UserResponse`, `StreamUrlResponse`, `AllSectionsResponse`, `AllSermonsResponse`, `AllPlaylistsResponse`, `AllFilesResponse` и DTO (`Create*Dto`, `Update*Dto`, `Reorder*Dto`). За актуальными полями обращайся к файлу напрямую.
- **Zod-схемы (runtime-валидация):** в `src/shared/api/generated/model/` (по модулям). Доменные Zod-схемы приложения — в `src/shared/model/domain/common.ts` (`sectionSchema`, `sermonSchema`, `playlistSchema`), см. [storage.md](./storage.md).

### Структура `src/shared/api/generated/`

```
generated/
├── index.ts                 # Агрегатор: authApi, sermonsApi, playlistsApi, sectionsApi, filesApi, APITypes
├── adminAPI.schemas.ts      # Все TS-интерфейсы (APITypes)
├── auth/auth.ts             # getAuth() → authControllerSignIn/Refresh/GetProfile
├── sermons/sermons.ts       # getSermons() → CRUD + stream-url
├── playlists/playlists.ts   # getPlaylists() → CRUD + reorder sermons
├── sections/sections.ts     # getSections() → CRUD раздела
├── section/section.ts       # getSection() → reorder разделов и плейлистов
├── files/files.ts           # getFiles() → upload, list, stream-url, file url
├── default/default.ts       # getDefault() → healthControllerCheck
└── model/                   # Zod-схемы для runtime-валидации (по модулям)
```

Каждый модуль экспортирует фабрику (`getAuth()`, `getSermons()` и т.д.), возвращающую функции-обёртки над `customInstance` из `src/shared/api/axiosInstance.ts`. `customInstance` пробрасывает конфиг в `axiosInstance` и возвращает `response.data`.

> ⚠️ `getDefault` (health) и `getSection` (reorder) **не реэкспортируются** из `generated/index.ts` — недостижимы из `shared/api`.

## Карта использования эндпоинтов

Из 29 функций-обёрток сгенерированного клиента в рантайме **реально вызывается только одна** — `sectionControllerFindAll`. Остальные определены «на вырост» и не задействованы.

| --------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| sections  | `sectionControllerFindAll`                                                                 | `GET /section`                                    | ✅ используется                  | `src/pages/listen/model.ts:22` (главный экран, `fetchAllSections`, online-first с фолбэком на кэш `shared/lib/sections-cache`) |
| auth      | `POST /auth/refresh` (сырой axios)                                                         | `POST /auth/refresh`                              | ⚠️ эндпоинт жив, обёртка мёртвая | `src/shared/api/axiosInstance.ts:23` — **сырым `axios.post`** в интерцепторе на 401 (не через `authControllerRefresh`)         |

| sections  | `sectionControllerCreate/FindOne/Update/Remove`                                            | `POST/GET/PATCH/DELETE /section*` (кроме FindAll) | ❌ мёртвые                       | нет admin-UI                                                                                                                   |
