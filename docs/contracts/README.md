# docs/contracts — Внешние контракты данных

Папка `contracts/` описывает **внешние контракты данных** приложения «Слово.Проповеди» (React Native/Expo): то, что находится за пределами приложения и с чем оно обменивается данными. Это:

- **REST API** — `https://api.slovo-propovedi.ru` и сгенерированный Orval-клиент (`[rest-api.md](./rest-api.md)`).
- **AsyncStorage** — локальное хранилище ключ/значение: токены, кэш, состояние плеера, настройки (`[storage.md](./storage.md)`).
- **Встроенная локальная БД** — захардкоженные массивы, используемые **только в разделе книг** `/read` (таб заблокирован, временно — до готовности бэкенда книг). Основной сценарий (слушать проповеди) берёт данные с REST API — `[local-db.md](./local-db.md)`.
- **Native-модули** — граница передачи данных из JS в нативные модули (expo-audio, expo-asset): что обязано выглядеть как валидный URI, где оборачивать вызовы в try-catch, почему AsyncStorage — нелегитимный ввод (`[native-modules.md](./native-modules.md)`).

От «схем» (например, `screens/`, `features/`) контракты отличаются тем, что описывают **протоколы и форматы данных**, а не экраны или бизнес-логику.

## Правила

1. **При изменении API/хранилища обновляй соответствующий файл в том же PR.**
   Изменение кода (эндпоинт, ключ AsyncStorage, формат значения, тип ответа API) без обновления `contracts/` считается неполным. Это же правило действует при регенерации клиента через `yarn api:generate`.

2. **Все эндпоинты / ключи / схемы — точный источник истины; код обязан им соответствовать.**
   Если агент обнаруживает расхождение между кодом и `contracts/`, он должен привести код в соответствие с контрактом **или** (если код намеренно изменился) обновить контракт — и в любом случае зафиксировать разницу.

3. **Не выдумывай факты.** Если данные неизвестны, проверь через `read`/`grep` в коде, либо пометь `<!-- TODO -->`. Сомнительные места помечай в `[../debt.md](../debt.md)`.

4. **Следи за «временным» слоем.** Сейчас часть данных берётся из встроенной БД (`src/shared/api/db/`), а не из API. Контракты обеих систем документированы, чтобы переход на реальный бэкенд был безопасным.
