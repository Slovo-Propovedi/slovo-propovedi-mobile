# Экран «Поиск»

**Маршрут:** `/search` — отдельный маршрут группы `(tabs)` (`app/(tabs)/search/`), зарегистрированный в таб-навигаторе, но **не** показанный как слот нижней панели: в баре всегда три вкладки, а в `/search` ведёт поисковая пилюля. Это собственный вложенный стек `Stack`: `index` — без шапки (`headerShown: false`), а детали — с нативной шапкой стека поиска (кнопка «Назад», фолбэк `/search`). `index.tsx` — сама страница поиска (`SearchTabScreen` из `src/pages/search/ui/SearchTabScreen.tsx`), `playlist.tsx` и `preacher.tsx` — реэкспорты страниц плейлиста и проповедника (`pages/playlist`, `pages/preacher`), поэтому навигация из выдачи пушит деталь **внутри маршрута поиска** (`/search/playlist`, `/search/preacher`) и «Назад» возвращает выдачу нетронутой.

Открытость поиска — производная состояния навигации: пока текущий путь (`usePathname`) — `/search` (или вложенный `/search/*`), `SearchTabScreen` пишет `isSearchOpenAtom = true`; отдельного ручного переключателя нет. Пиллюля и «✕» дополнительно пишут флаг оптимистично до навигации: морф стартует из подписки на атом, и эффект после коммита маршрута опаздывал бы на кадр; эффект лишь сверяет значение (no-op) и закрывает пути «Назад»/смены таба. Экран смонтирован постоянно (таб-навигатор хранит все маршруты), поэтому уход на другой маршрут и возврат не перемонтируют его.

**Файлы:** `app/(tabs)/search/_layout.tsx` → `src/pages/search/ui/SearchTabScreen.tsx` → `src/pages/search/ui/SearchScreen.tsx`
**Статус:** готов

## Что делает

Поиск по проповедям, плейлистам и проповедникам сервера. Поле ввода живёт не на странице, а в нижней строке — в морфящем поисковом компоненте `SearchIslandMorph` (`widgets/search-island`), поэтому страница описывает только область контента и реагирует на состояние поля: фокус и запрос читаются из атомов фичи `features/sermon-search` ([features/navigation.md](../features/navigation.md) → «Кастомный таб-бар»). Тап по любой точке раскрытой пилюли (кроме микрофона и ⊗) фокусирует поле ввода; тап по закрытому кругу, как и раньше, открывает поиск.

## Что показывается

Страница имеет два состояния, различаемых только по длине запроса: главная страница (обрезанный запрос короче `MIN_RESULTS_VIEW_LENGTH = 3`, `src/pages/search/lib/searchThresholds.ts`) и поза выдачи (от 3 символов). Фокус поля на содержимое больше не влияет: главная страница одинакова при любом фокусе — клавиатура поднимается и опускается, но ничего не скрывается и не размонтируется. Запрос уходит уже с 2 символов (`MIN_QUERY_LENGTH`), просто сервер на двухсимвольные запросы отвечает пустым массивом. Диалоги поиска (очистка истории, заблокированная область «Читать») не трогают фокус поля вовсе: они не удерживают его и не возвращают — открытие и закрытие ничего не делает с фокусом.

1. **Главная страница (запрос короче 3 символов, любой фокус)** — крупный заголовок «Поиск» (`ScreenTitleRow`, `accessibilityRole='header'`); ниже сегментированный переключатель области поиска (`SearchScopeTabs` на общем `PillTabs` в режиме `stretch`): **«Слушать»** | **«Читать»** — один серый трек на всю ширину страницы, сегменты делят её ровно пополам; ниже — секция **«Недавние поиски»** (`RecentSearchesSection`). Если история поиска пуста, секция не рендерится. При выбранной области «Читать» вместо «Недавних поисков» под заголовком показывается заглушка `EmptyState` «Раздел «Читать» скоро появится», переключатель области остаётся на месте.
2. **Поза выдачи (запрос от 3 символов)** — заголовка «Поиск» нет: переключатель области поиска и «Недавние поиски» скрыты целиком, остаётся только строка сегментов-групп (`PillTabs variant='results'` без `stretch`): **«Проповеди»** | **«Плейлисты»** | **«Проповедники»** — трек по ширине контента, горизонтально прокручиваемый (выбран ровно один сегмент), под ним дополнительный отступ `INDENTS.medium` до полного пагинируемого списка выбранной группы (`SearchResultsList`). Смена фокуса при активном запросе состояние не меняет: выдача остаётся на экране, а очистка запроса возвращает главную страницу.

**Оформление переключателей.** Строка области (`SearchScopeTabs`) использует вариант по умолчанию: `PillTabs` рисует один трек-контейнер (чистая заливка `COLORS.white` в светлой теме / `COLORS.black` в тёмной, `RADIUSES.round`, высота 48, внутренний отступ 3, внешняя тень — тёмная копия пилюли + blur-слой, без `boxShadow`/`elevation`; на web этих двух слоёв нет: react-native-web не переводит array-форму `filter` в CSS, а expo-blur там только `backdrop-filter` в 1px, поэтому та же геометрия тени (сдвиг 18, размытие 22 и плотность `rgba(0,0,0,0.13)` — заметнее нативных 10/0.09, потому что CSS `box-shadow` размазывает одну полупрозрачную фигуру по всему радиусу, а нативный RenderEffect размывает непрозрачное тело, сохраняя плотность) отрисовывается CSS-`box-shadow` прямо на треке — `trackWebShadow` в `PillTabs.styles.ts`). Строка результатов (`variant='results'`) — плоский трек без тени, выбранный сегмент залит `theme.primary` с меткой `theme.onPrimary`. В варианте по умолчанию выбранный сегмент — серая плоская пилюля (`withAlpha(theme.text, 0.1)` в светлой, `0.18` в тёмной), метка `theme.text` полужирная (600); в results — акцентная, метка обычного начертания. **Невыбранные сегменты залиты цветом окружающей поверхности** (трек для scope, `theme.background` для results): на глаз они невидимы, но Android проводит touch по всей площади view только при наличии реального background drawable (прозрачный/около-невидимый фон ведёт себя как отсутствующий — проверено на устройстве). Радиосемантика прежняя: ровно один `accessibilityState.selected`, `onChange` при выборе. **Disabled-сегмент «Читать»** красится `theme.textMuted`, но НЕ получает `accessibilityState.disabled`: RN 0.88 маппит этот флаг в нативный `View.setEnabled(false)`, после чего `TouchTargetHelper` исключает view из hit-testing (`BOX_NONE`) и тапы ловит только текст. Цена — скринридер не объявляет сегмент disabled; состояние передают приглушённая метка и информационный диалог (см. [debt.md](../debt.md) → «Поиск»).

Детали состояния 3:

- Строки проповедей — `SearchResultsRow`/`SermonSearchRow` на `TracksListItem` (`entities/track-list`): обложка, заголовок, сабтайтл «проповедник • книга+глава+стих» (`formatScripture`), бейдж кэша, полоса прогресса прослушивания и затемнение завершённых (`entities/listening-history`), сердечко «в избранном». Меню строки — `buildHistoryMenuActions` («Добавить в плейлист», «Пометить прослушанной»/«Удалить из истории»), к нему добавляется пункт **«Удалить из истории поиска»** (иконка `search-outline`).
- Строки плейлистов — `SearchPlaylistRow` на `SearchListItem` (artwork, название, описание); строки проповедников — `SearchPreacherRow` теперь на том же `TracksListItem`, что и проповеди (обложка-плейсхолдер, заголовок, высота и геометрия строки): трейлинг-слот «⋯» не рендерится, потому что у артиста нет аудио и меню было бы пустым. Тап по строке открывает экран проповедника, а не переписывает запрос.
- При прокрутке вниз список дозагружает следующую страницу (порог `onEndReachedThreshold = 0.4`), в футере виден `ActivityIndicator`. Прокрутка списков страницы (выдачи и недавних) **не** сворачивает нижний бар: пока маршрут поиска активен, `isSearchBarCollapseSuspendedAtom` приостанавливает драйвер `useBarCollapseOnScroll` на любой запрос — и на пустой тоже (см. [listen.md](./listen.md) → «Поиск»). При этом оба списка ставят `keyboardDismissMode='on-drag'`: драг опускает клавиатуру и одновременно продолжает прокрутку. Это безопасно, потому что позы страницы от фокуса не зависят — главная страница и выдача не меняются, опускается только клавиатура. `keyboardShouldPersistTaps='handled'` сохранён, поэтому тап по строке не теряется; клавиатуру также закрывают явные пути — ⊗, «✕», `Escape` и тап по пустой области страницы (`Keyboard.dismiss`).
- **Недавние поиски** — до 20 записей, новые сверху; пустая история секцию скрывает. Кнопка «Очистить» в заголовке секции открывает локальный `ConfirmDialog` («Очистить историю поиска?»): состояние диалога живёт в `RecentSearchesSection`. Диалог не трогает фокус поля: секция ничего не удерживает и не возвращает, нижний бар остаётся в том расположении, которое диктует реальный фокус клавиатуры (заблурённое поле — обычная строка с табом и пилюлей, без «✕»). Каждый путь закрытия (кнопка «Отмена», системный «Назад» через `Modal.onRequestClose`, `Escape` на web — backdrop-нажатия у `ConfirmDialog` нет) просто закрывает диалог. Подтверждение очищает историю целиком; после опустевшей истории секция скрывается, остаётся переключатель области.

**Область «Читать» гейтится фича-флагом `read`** (`useFeatureFlag`): пока флаг выключен или не загружен, сегмент «Читать» показан, но disabled, а нажатие открывает тот же информационный диалог, что и заблокированный таб («Скоро будет доступно») — поле при этом не перефокусируется. Когда флаг включён, выбор области «Читать» показывает заглушку `EmptyState` «Раздел «Читать» скоро появится» — и на главной странице, и при активном запросе; сетевых запросов в этой области нет — страница запрашивает данные только для «Слушать».

## Откуда данные

- Состояние поля и запроса — `src/features/sermon-search/model.ts` (`searchQueryAtom`, `isSearchOpenAtom`, `searchInputRequestAtom`) и `model-searchField.ts` (`isSearchFieldFocusedAtom` — реальный фокус поля — и чистая `isSearchQueryActive`). Видимость пилюли и приостановка бара считаются от `isSearchOpenAtom` (путь — `/search` или `/search/*`) через `isSearchFieldVisibleAtom` и `isSearchBarCollapseSuspendedAtom`. Поза страницы зависит только от длины запроса; хром нижнего бара читает тот же `isSearchFieldFocusedAtom`, и никто, кроме реального фокуса клавиатуры, его не меняет: скрытая фокусом пилюля мини-плеера после приземления тюка убирается из дерева, чтобы её play/pause не перехватил клик по полю. Локальные состояния страницы: выбранная область (`'listen' | 'read'`) и группа результатов (`'sermons' | 'playlists' | 'preachers'`) — `useState` внутри `SearchScreen`; они живут, пока смонтирован экран, — в том числе пока открыта деталь поверх (пуш внутри маршрута поиска не сбрасывает сессию).
- Пагинация — `usePagedSearch` (`src/pages/search/lib/usePagedSearch.ts`) поверх сетевых функций `src/features/sermon-search/lib/searchSources.ts`:
  - проповеди — keyset-курсор: `sermonControllerFindAll({ search, take: 20, cursor? })`, следующая страница по `nextCursor`;
  - плейлисты — офсетные страницы: `playlistControllerFindAll({ search, page, limit: 20 })`, конец — по `count`;
  - проповедники — производные **клиент-сайд** от накопленных страниц проповедей (`collectMatchingPreachers`, `src/features/sermon-search/lib/composeSearchResults.ts`): уникальные `artist`, чьё имя содержит запрос; своя дозагрузка тянет следующую страницу проповедей.
- Первая страница обеих групп грузится параллельно (`fetchFirstPage`, `src/pages/search/lib/fetchFirstPage.ts`) после дебаунса **400 мс**; устаревший ответ отбрасывается счётчиком `requestId`, сброшенным на смене запроса. Дозагрузка дополнительно гейтится флагом «в полёте», чтобы `onEndReached` не дублировал страницу.
- Офлайн-фолбэк — только для **первой** страницы: при сетевой ошибке читаются per-query кэши фичи (`cachedSermonSearch:q:<query>` / `cachedPlaylistSearch:q:<query>`, см. [contracts/storage.md](../contracts/storage.md)); последующие страницы при ошибке возвращают пустой результат. Успешная первая страница пишется в кэш fire-and-forget (пустые результаты не кэшируются). Сетевые функции не реджектят: ошибки логируются (`console.error`).
- Недавние поиски — сущность `src/entities/search-history/`: записи `{ sermon: AudioPlayerData, savedAt }`, ключ `searchHistory` ([contracts/storage.md](../contracts/storage.md)), лимит 20, дедупликация по `sermon.id` (побеждает более свежий `savedAt`). Гидратация — при старте приложения (`app/_layout.tsx`) и на монтировании страницы (`loadSearchHistoryAction`, только пока `isSearchHistoryLoadedAtom === false`). Запись — тап по проповеди в выдаче или в недавних (`addSearchEntryAction`, дата = момент тапа), удаление одной записи — пункт меню, полная очистка — `clearSearchHistoryAction`. Формат и семантика — [features/settings-backup.md](../features/settings-backup.md) (секция входит в резервную копию).

## Заголовок и навигация

- Нативной шапки нет только у экрана результатов (`headerShown: false` на `index`; верхний safe-area инсет снимает `SafeAreaView` экрана). Крупный заголовок «Поиск» (`ScreenTitleRow`) рисуется на главной странице при любом фокусе, пока запрос короче 3 символов; в позе выдачи заголовка нет — место занимает строка сегментов-групп.
- Детали `/search/playlist` и `/search/preacher` рендерят нативную шапку стека поиска с кнопкой «Назад» (фолбэк `/search`): на плейлисте шапка прозрачная (`headerTransparent: true`, `title: ''`), заголовок и правый хром задаёт страница (см. [playlist.md](./playlist.md)); на проповеднике заголовок — имя проповедника (`useHeaderTitle`, см. [preacher.md](./preacher.md)).
- Внешний «✕» у пилюли снова есть: он виден, пока поле в фокусе или запрос непустой, и закрывает поиск целиком — `resetSearchSession` + `Keyboard.dismiss` + `router.back()`; под вложенной деталью `/search/*` (`back()` снял бы только её и оставил поиск открытым), а также когда `/search` — первая запись истории, вместо этого сразу `router.navigate('/listen')`. Уход с маршрута также возможен сменой таба в нижней строке или системным «Назад»: `router.back()` возвращает на предыдущий таб, а хук `useClearSearchOnLeave` (`src/pages/search/lib/useClearSearchOnLeave.ts`) в этот же момент сбрасывает сессию одной транзакцией — `searchQueryAtom`, `isSearchFieldFocusedAtom`, канал ввода (`resetSearchSession`) и клавиатура (`Keyboard.dismiss`); бамп `searchSessionNonceAtom` ремонтирует `SearchScreen`, чтобы область, группа и загруженные страницы вернулись к состоянию первого визита. Очистка привязана к смене **пути** (`usePathname` роутера), а не к blur-эффекту: blur срабатывает и на пуш детали внутри поиска, и не должен ничего сбрасывать.
- Пуш детали `/search/playlist`, `/search/preacher` происходит внутри маршрута поиска, поэтому `isSearchOpenAtom` остаётся истинным: поле, запрос и загруженные страницы живут под деталью и возвращаются по «Назад» мгновенно. Пуш оптимистично помечает переход (`isScreenTransitioningAtom`) и гвардится `useNavigationGuard` против двойного тапа.

## Куда можно перейти

- Проповедь → воспроизведение (без перехода) через общий `useSermonPlayback`; при неоднозначном контексте сначала открывается пикер `SermonPlaylistPicker` (см. [listen.md](./listen.md) → «Поиск»). Тап также пишется в недавние поиски.
- Строка в «Недавних поисках» → воспроизведение тем же путём; запись обновляется (переезжает наверх).
- Плейлист → `/search/playlist?playlist=<id плейлиста>` (`onPlaylistPress` → навигация с `useNavigationGuard`, живёт в `useSearchNavigation`). Деталь рендерит тот же `PlaylistScreen` внутри маршрута поиска; «Назад» возвращает выдачу нетронутой.
- Проповедник → `/search/preacher?artist=<имя проповедника>` (`onPreacherPress` → навигация с `useNavigationGuard`, живёт в `useSearchNavigation`): экран со всеми проповедями этого проповедника пушится поверх поиска внутри маршрута поиска; сессия остаётся нетронутой под ним (см. [preacher.md](./preacher.md)).
- «Читать» при выключенном флаге → информационный диалог «Скоро будет доступно».

## Состояния

- Загрузка: `SearchResultsSkeleton` (`src/pages/search/ui/SearchResultsSkeleton.tsx`) — 6 строк `TracksListItem.Skeleton`, пока первая страница группы в полёте.
- Пусто: `EmptyState` «Ничего не найдено» (`ListEmptyComponent`) — только когда обрезанный запрос ≥ 3 символов: сервер фактически отдаёт пустой массив на двухсимвольные запросы, поэтому сообщение о промахе там было бы ложным (запрос всё равно уходит при ≥ `MIN_QUERY_LENGTH = 2`, при 1–2 символах область просто пустая); пустая история поиска просто не рендерит секцию недавних.
- Дозагрузка: спиннер в футере списка (`isLoadingMore`).
- Офлайн: первая страница — из per-query кэша (кап 30 запросов), дальнейшие страницы не грузятся; UI-индикатора источника данных нет (см. [debt.md](../debt.md)).
- Ошибка сети: `console.error`, затем кэш первой страницы; без кэша — пустая выдача.
- Область «Читать»: заглушка `EmptyState` и на главной странице, и при активном запросе, сеть не дёргается.
