# Экран «Список плейлистов секции»

**Маршрут:** `/listen/playlist-list?sectionId=<строка>`
**Файлы:** `app/(tabs)/listen/playlist-list.tsx` → `export { PlaylistListScreen as default }` из `pages/playlist-list` (тело списка — в виджете `widgets/playlist-list`)
**Статус:** готов

## Что делает

Вертикальный список плейлистов конкретной секции. Открывается по тапу на заголовок секции на главном экране «Слушать».

## Что показывается

- Схлопывающаяся шапка с заголовком секции (`useCollapsingHeader` из `src/widgets/playlist-list/lib/useCollapsingHeader.ts` + `useCollapsingNavbarDriver` из `shared/ui/collapsing-navbar-driver`). Заголовок навбара появляется и фон достигает полной непрозрачности, когда ЦЕНТР контентного заголовка достигает низа навбара — тот же момент передачи, что на экране плейлиста (≈ верхний отступ 80px + половина высоты заголовка); до последних 80px перед порогом фон остаётся полностью прозрачным (как на экране плейлиста). Порог вычисляется детерминированно (верхний отступ + половина высоты заголовка), а не из layout y.
- Вертикальный список плейлистов — общий виджет `PlaylistList` (`src/widgets/playlist-list/ui/PlaylistList.tsx`), строки рендерит `PlaylistListItem` (`src/widgets/playlist-list/ui/PlaylistListItem.tsx`): обложка через `CoverImage` (при отсутствии artwork — плитка-буква `PlaylistLetterAvatar` стандартного размера `getListItemCardArtworkSize(useLayoutBaseWidth())`, то есть слот обложки обязателен и высота строки не схлопывается), название — многострочное (`Text` без `numberOfLines`), видно целиком; описание — одна строка с обрезанием. Тело списка вынесено в виджет, чтобы его переиспользовал просмотровый режим «Мои плейлисты» (см. [my-playlists.md](./my-playlists.md)); страница оставила только резолвинг секции и её состояния.
- Кнопка «?» в шапке стека «Слушать» (`screenOptions.headerRight` в `app/(tabs)/listen/_layout.tsx`) — онбординг/обзор возможностей (см. [../features/onboarding.md](../features/onboarding.md)).

## Откуда данные

Резолвинг плейлистов происходит в два этапа:

1. **Atom** (`dynamicSectionsAtom` из `entities/section`): поиск секции по `sectionId` — мгновенно, без сериализации/парсинга. Это основной путь, когда пользователь открывает список сразу после загрузки главного экрана.
2. **Холодный старт** (fallback): если atom пуст (приложение только запущено, секции ещё не загружены), экран показывает краткое состояние загрузки и запрашивает `getCachedSections()` из AsyncStorage. При нахождении — список рендерится. При отсутствии — центрированное сообщение «Секция не найдена».

Параметры маршрута: `sectionId` (строка, идентификатор секции). Заголовок секции для шапки берётся из `dynamicSectionsAtom`/кэша AsyncStorage, а не из параметров маршрута.

## Куда можно перейти

- Тап на плейлист → `/listen/playlist?playlist=<id плейлиста>` (`handlePlaylistPress` → `router.push`).

## Состояния

- Загрузка: кратковременный спиннер при холодном старте (atom пуст, чтение кэша).
- Пусто: `ListEmptyComponent` — «Нет плейлистов».
- Секция не найдена: центрированное сообщение «Секция не найдена» (если ни atom, ни кэш не содержат секцию с нужным `sectionId`).
- Офлайн: работает из кэша (`getCachedSections()`), если atom пуст.
