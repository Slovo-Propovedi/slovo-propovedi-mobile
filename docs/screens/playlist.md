# Экран плейлиста

**Маршрут:** `/listen/playlist?playlist=<id плейлиста>`
**Файлы:** `app/(tabs)/listen/playlist.tsx` → `export { PlaylistScreen as default }` из `pages/playlist`
**Статус:** готов

## Что делает

Показывает один плейлист: обложку (при отсутствии artwork — фолбэк-обложка иконкой приложения, `IMAGE_PLACEHOLDER`), название, описание, кнопку «Слушать всё» (умная: «Начать прослушивание плейлиста» или «Продолжить прослушивание плейлиста», см. ниже) и список треков (проповедей). Поддерживает скачивание плейлиста целиком через контекст-меню.

## Что показывается

- Схлопывающаяся шапка (`PlaylistHeader`, `src/pages/playlist/ui/PlaylistHeader.tsx` + `useCollapsingHeader` из `src/pages/playlist/lib/useCollapsingHeader.ts`). Обложка шапки — через `CoverImage` (eager, фолбэк `IMAGE_PLACEHOLDER`), поверх — блюр 70% (`BlurView` из `expo-blur`, `tint='dark'`) и затемняющий оверлей (`COLORS.black`, opacity 0.3) под заголовком. На Android блюр не работает без `blurTarget`: обложка обёрнута в `BlurTargetView` с `ref`, который передаётся в `BlurView` (`blurMethod='dimezisBlurViewSdk31Plus'` — реальный блюр на Android 12+, на более старых версиях тихий фолбэк на полупрозрачную заливку без блюра).
- Кнопка «Слушать всё» (`PlaylistHeader` → `handlePressPlayAll`). Подпись и цель кнопки вычисляются хуком `usePlaylistPlaybackTarget` (`src/pages/playlist/lib/usePlaylistPlaybackTarget.ts`) по истории прослушивания: если в плейлисте ещё ничего не слушали — **«Начать прослушивание плейлиста»** и первый трек с `audioUrl`; иначе — **«Продолжить прослушивание плейлиста»**, цель — последний прослушанный трек (если он не завершён — `playNewSermon` возобновит с сохранённой позиции `getResumePosition`), следующий трек с `audioUrl` после него (если завершён) или первый трек (если завершённый был последним — старт заново). «Последний прослушанный» определяется чистой функцией `findLastListenedSermon` (`entities/listening-history`) по максимальному `lastPlayedAt` среди записей истории, чья проповедь входит в плейлист.
- Список треков `TracksList`/`PlaylistTrackItem` (`src/pages/playlist/ui/PlaylistTrackItem.tsx`) с иконками «играет»/«кэш» и контекст-меню; у каждой строки слева от «⋯» — сердечко «в избранном» (`FavoriteSermonButton`, снапшот через проп `sermon`, обёртка первой строки — через `renderFavoriteButton`; см. [features/my-playlists.md](../features/my-playlists.md) → «Точки переключения избранного»); обложка трека рендерится через `TracksListItem` (`entities/track-list`, `CoverImage` с фолбэком `IMAGE_PLACEHOLDER`). Каждый трек показывает тонкую полосу прогресса прослушивания (сохранённая позиция из `entities/listening-history` через `useHistoryProgressMap`); полоса обновляется **только по событиям** (старт, пауза/flush, переключение, завершение, удаление) — без live-тикания в реальном времени (live-чтение убрано). Завершённые треки (`progress >= 1`) затемняются (`TracksListItemContent`: обложка opacity 0.5 + приглушённый заголовок, см. [features/listening-history.md](../features/listening-history.md) → «Затемнение завершённых»). Контекст-меню трека (`usePlaylistActions.buildMenuActions`) содержит пункты истории из `buildHistoryMenuActions`: **«Добавить в плейлист»** (иконка `add-circle`, первым, см. [features/add-to-playlist.md](../features/add-to-playlist.md)), **«Удалить из плейлиста»** (иконка MCI `playlist-remove`, сразу после «Добавить в плейлист»; только для плейлистов, присутствующих в «Мои плейлисты» (`myPlaylistsAtom`) — «Избранные», созданные вручную, импортированные, включая uuid-id; видимость даёт хук `useIsLocalPlaylist`, с подтверждением `ConfirmDialog` → `togglePlaylistSermon(ctx, playlist.id, sermon, false, { suppressPlayerReset: true })`; если удаляемая проповедь сейчас играет из этого плейлиста (`currentPlaylistAtom`/`currentAudioAtom`, снапшот в момент открытия диалога), в сообщение добавляется «Плеер будет закрыт.», а после удаления открывается шторка «Где продолжить прослушивание?» (`features/continue-playback`): выбор плейлиста продолжает воспроизведение в нём (плеер остаётся открыт), «Закрыть плеер»/фон вызывают `resetPlaybackAction` — плеер (нотификейшн-бар, миниплеер) закрывается; если подходящих плейлистов нет, плеер закрывается сразу), **«Пометить прослушанной»** (для незавершённых) и **«Удалить из истории»** (если проповедь в истории). Модалка мультивыбора монтируется на экране (`useAddToPlaylistModal`), одна на весь список. Под заголовком каждого трека — подпись «книга глава:стихи» (например «Бытие 1:1-5»); автор в списке не показывается — он вынесен в оверлей «Подробнее» полноэкранного плеера. Формируется через `formatSermonReference` из `src/entities/sermon/lib/formatSermonReference.ts`; в ходе миграции на спецификацию API v0.15.1 форматтер расширяется на диапазоны глав/стихов (см. [contracts/rest-api.md](../contracts/rest-api.md) → «Главы и стихи»).
- Индикаторы скачивания: прогресс плейлиста, системные уведомления (`src/pages/playlist/lib/PlaylistOfflineNotifications.ts`, `notificationConstants.ts`). Итог скачивания: при полном успехе — «Добавлено в офлайн N проповедей»; при частичной неудаче — уведомление ошибки с текстом «Не удалось добавить в офлайн X из N» (неудачные треки остаются с иконкой «облако»); при потере сети посреди прогона — прогон прерывается, уведомление «Нет подключения к интернету» (трактуется как сетевая ошибка — без алерта). **Отменённый прогон не показывает уведомлений** (остановка через «Остановить добавление в офлайн» — тихая).
- Меню шапки (`PlaylistHeaderMenu`/`PlaylistHeaderMenuDropdown`, `src/pages/playlist/ui/`): верхний пункт — **«Поделиться плейлистом»** (`PlaylistShareMenuItem`, `share-outline`): закрывает меню шапки и открывает модалку `PlaylistShareModal` (`src/pages/playlist/ui/`, `Modal` из `shared/ui/modal`) с QR-кодом (`react-native-qrcode-svg`). QR кодирует **только ссылку** (без текста «название — ссылка»): для серверного плейлиста это `https://<EXPO_PUBLIC_WEB_HOSTNAME>/listen/playlist?playlist=<id>` (`buildPlaylistShareUrl`) — та же App Links-ссылка, что перехватывает Android-приложение (см. [features/deep-links.md](../features/deep-links.md)); для локального («Мои плейлисты», кроме «Избранных») — упакованная inline-ссылка с проповедями (`buildCustomPlaylistShareUrl`, см. [features/deep-links.md](../features/deep-links.md) → «Локальные (пользовательские) плейлисты»). Ссылку и состояние модалки держит `usePlaylistShare`. Если ссылка длиннее `MAX_QR_URL_LENGTH` (1000 символов) — например, кастомный плейлист на 200 проповедей (~4.4 КБ) превышает ёмкость QR в байтовом режиме (~2953 байта) и генерация кода упала бы при рендере, — карточка с QR скрывается, остаются только строки действий. Внутри модалки строка **«Отправить ссылку»** (иконка `share-outline`) рендерится **только** когда шаринг поддерживается (`isShareSupported`, `src/shared/lib/isShareSupported.ts`/`.web.ts`: всегда на нативе, на web — лишь при наличии `navigator.share`), и вызывает общий флоу `shareLink` (`src/shared/lib/shareLink.ts`) с текстом «название — ссылка»; его web-семантика не изменилась и живёт в `src/shared/lib/shareLink.web.ts` (при наличии Web Share API — системный `navigator.share`; иначе копирование в буфер обмена с тостом **«Ссылка скопирована»**; падение вызова — тост ошибки **«Не удалось поделиться. Попробуйте ещё раз»** без копирования; закрытие шита пользователем (`AbortError`) не копирует и не показывает тост — кроме внутренних ошибок Chromium «Share failed»/«Permission denied»; повторный тап, пока предыдущий вызов висит, сериализуется модульным guard'ом 30 с и трактуется как отмена). Строка **«Копировать ссылку»** (иконка `copy-outline`) показывается **всегда** — копирует «название — ссылка» через `expo-clipboard` и показывает тост **«Ссылка скопирована»**; сбой копирования и сбой шаринга показывают тост ошибки **«Не удалось поделиться. Попробуйте ещё раз»** (`showToast`/`toastAtom`, 2 с). Модалка закрывается по тапу на фон и по Android-«Назад». Пункт неактивен, пока плейлист не загружен (id-заглушка `default` не является UUID). Пункты кэша — во время кеширования «Добавить все в офлайн» сменяется на **«Остановить добавление в офлайн»** (иконка `stop-circle-outline`), который живёт на месте «Добавить все в офлайн» и **всегда активен — включая офлайн** (отмена не требует сети). Подмена реактивная по атому `isCachingPlaylistAtom`. После остановки: активная закачка прерывается только если она принадлежит исключительно этому прогону (иностранные джойнеры manual/auto не задеваются), run-контроллер прерывается, оставшиеся записи очереди очищаются. Пункты истории (`usePlaylistHistoryMenu`, `PlaylistHistoryDialogs`): **«Пометить все прослушанными»** (иконка `checkmark-done`, виден когда есть playable-проповедь не завершённая) и **«Удалить проповеди из истории»** (иконка `trash-outline`, виден когда хотя бы одна проповедь плейлиста есть в истории) — оба с диалогом подтверждения; массовые экшены `markSermonsListenedAction`/`removeSermonsFromHistoryAction` (см. [features/listening-history.md](../features/listening-history.md) → «Массовые операции плейлиста»). **То же меню доступно в шторке плейлиста полноэкранного плеера** — кнопка `⋮` рядом с названием плейлиста (`PlaylistBottomSheet`, виджет `widgets/expandable-player`, см. [features/player.md](../features/player.md) → `ui/PlaylistBottomSheet/`). Виджет не может импортировать `pages`, поэтому меню внедряется слоем `app`: `app/(tabs)/_layout.tsx` передаёт адаптер `PlaylistSheetMenu` (`src/pages/playlist/ui/PlaylistSheetMenu.tsx`), который переиспользует `PlaylistHeaderMenu` и собирает `tracksData` через `buildTracksListData(playlist.sermons, playlist.artwork)`. Набор пунктов, диалоги подтверждения, модалка ошибки и гейтинг идентичны экрану; отличие одно — цвет иконки: в шторке он всегда из темы, на экране переключается по скроллу (гистерезис).
- Пункт **«Удалить из офлайн все»** дизейблится, когда `cachedCount === 0` **или** очередь непуста (реактивно по `cacheQueueAtom`) **или** есть идущая закачка (реактивно по `activeCacheUrlAtom`). Дополнительно press-time guard'ы `handleClearCacheOption`/`handleClearCacheConfirm` перепроверяют `hasInflightCacheDownloads()` (belt-and-suspenders на деструктивной очистке). От сети не зависит.
- **Глобальный стоп из развёрнутого плеера:** кеширование можно остановить не только из меню кэша плейлиста, но и из полноэкранного плеера — кнопка **«Остановить все закачки»** в правом верхнем углу (`HeaderOverlay` → `StopAllCachingButton` → `useStopAllCaching` → `cancelAllCacheDownloads`). Видна, когда очередь непуста или есть активная закачка; всегда активна, в т.ч. офлайн. Прерывает плейлист-прогон (тихо, без ложного «Добавлено в офлайн N из N»), отменяет активную закачку и дренирует очередь. Подробнее — [features/audio-cache.md](../features/audio-cache.md) → «Глобальный стоп».
- Статус-бар и цвет иконок шапки адаптируются к скроллу (`usePlaylistHeader`, `usePlaylistNavigationOptions`). `headerRight` — `PlaylistHeaderActions`: для локального **не-избранного** плейлиста слева от меню-кнопки показывается карандаш (`PlaylistEditButton`, «Редактировать плейлист»), который **навигирует** на отдельный экран редактирования `/listen/playlist-edit?playlist=<id>` (`router.push`), где живут переименование («Сохранить») и удаление («Удалить плейлист» с подтверждением `ConfirmDialog`; после удаления — `router.back()`). «Избранные» редактировать нельзя. Карандаш включается только шапкой экрана (`isEditEnabled`); в шторке плеера он не показывается. См. [screens/playlist-edit.md](./playlist-edit.md) и [features/my-playlists.md](../features/my-playlists.md) → «Экран редактирования и кнопка редактирования».

- Пункт **«Добавить в глобальные»** (публикация локального плейлиста) виден только для локального не-избранного плейлиста **и** при админ-сессии (`canAccessAdmin(authUser)`), поэтому обычным пользователям мёртвый пункт с логином не показывается. Открывает `/admin/playlists/create` с предзаполнением названия, id и **снапшотов** проповедей (`buildPublishSermonsParam`; для проповеди без снапшота — id-only запись), которые форма разбирает `parsePublishSermonsParam` и рендерит выбранными строками пикера (`mergeById`).

- Пункт **«Добавить все проповеди в плейлист»** (иконка `add-circle`, сразу после «Поделиться плейлистом») открывает ту же модалку мультивыбора, что и контекст-меню трека, но в **батч-режиме** — выбор целевого плейлиста сразу для всех проповедей текущего плейлиста. Виден **только на экране плейлиста** и только когда в плейлисте есть хотя бы одна проповедь (колбэк `onAddAllToPlaylist` передаёт `PlaylistScreen` через `usePlaylistNavigationOptions`; в шторке плеера `PlaylistSheetMenu` колбэка нет, поэтому там пункт отсутствует). Начальный чекбокс целевого плейлиста включён, если он уже содержит весь набор; «Сохранить» добирает недостающие проповеди (на первом достижении лимита `MAX_CUSTOM_PLAYLIST_SERMONS` (200) показывается тост «В плейлисте максимум 200 проповедей»), снятие чекбокса убирает все. Подробнее — [features/add-to-playlist.md](../features/add-to-playlist.md) → «Батч-режим».

- В модалке «Добавить в плейлист» (оба режима) в правом верхнем углу шапки, на строке с заголовком, есть иконка-кнопка **«Создать плейлист»**: она подменяет список и футер встроенной формой «Название» + «Отмена»/«Создать» (пока форма открыта, в углу — крестик возврата к списку). После создания форма возвращается к списку, новый пустой плейлист появляется в нём сразу (живая подписка на `myPlaylistsAtom`, без перезапроса), навигации нет, а уже отмеченные галочки сохраняются. Подробнее — [features/add-to-playlist.md](../features/add-to-playlist.md) → «Создание плейлиста из модалки».

- Пункт **«Удалить плейлист»** (корзина, красный `COLORS.error`) виден только для локального не-избранного плейлиста и только на экране плейлиста (`isEditEnabled`; в шторке плеера — нет). Открывает подтверждение `LocalPlaylistDeleteDialog` (`ConfirmDialog`, «Удалить плейлист?»); после подтверждения — `deleteLocalPlaylist` и `router.back()`. «Избранные» не удаляются.

- Пункт **«Очистить плейлист»** (иконка MCI `playlist-remove`, красный `COLORS.error`) виден только для локального не-избранного плейлиста и только на экране плейлиста (`isEditEnabled`; в шторке плеера — нет). Открывает подтверждение `ClearPlaylistDialog` (`ConfirmDialog`, «Очистить плейлист?», «Все проповеди будут удалены из плейлиста»); после подтверждения `clearLocalPlaylistSermons` обнуляет `sermonIds` и `sermons` плейлиста. Если очищаемый плейлист — тот, что сейчас загружен в плеере (`currentPlaylistAtom`, снапшот в момент тапа, без живой подписки), в сообщение добавляется «Плеер будет закрыт.» и после очистки вызывается `resetPlaybackAction` — нотификейшн-бар и миниплеер закрываются, активные состояния сбрасываются; экран остаётся на месте (плейлист продолжает существовать). «Избранные» очистить нельзя.
- Кнопка «?» в шапке (`OnboardingHelpRow`, слева от меню плейлиста) — онбординг/обзор возможностей (см. [../features/onboarding.md](../features/onboarding.md)). Наследует цвет шапки (`headerIconColor`: `COLORS.white` в cover-режиме, иначе `currentTheme.text`).
- **Группы пунктов меню и разделители** — меню шапки делится на группы: [«Поделиться»] → [«Добавить все проповеди в плейлист», «Добавить в глобальные»] → [офлайн: добавить/остановить, «Удалить из офлайн все»] → [история: пометить, удалить из истории] → [деструктив: «Очистить плейлист», «Удалить плейлист»]. Между группами — ровно один разделитель `PlaylistMenuDivider` (`src/pages/playlist/ui/PlaylistMenuDivider.tsx`, общий для `PlaylistHeaderMenuDropdown` и `PlaylistOfflineMenuItems`); внутри группы разделителей нет. Разделитель перед группой рендерится только когда группа непуста, поэтому пустые группы не дают двойных линий.
- **Онбординг экрана** — четыре сценария. `playlist-menu` («Экран плейлиста»): цели `playlist.playback` — кнопка «Начать/Продолжить прослушивание» (`QueueControls`) в шапке, и `playlist.menu` — кнопка-точки меню шапки (`PlaylistHeaderMenuButton` оборачивает свой корень в `OnboardingTarget`, id прокидывается из `usePlaylistNavigationOptions` → `PlaylistHeaderMenu` → `PlaylistHeaderActions`); пункты меню (шаги 3–10) помечены `skipIfMissing` (строки, отсутствующие в меню для этого плейлиста, пропускаются, а отрендеренные-но-дизейбленные, например «Удалить из офлайн все», подсвечиваются как обычно), финальный шаг «Меню проповеди» — `interactive` с карточкой без затемнения, привязанной к первой строке списка, действием `actionOnEnterId: close-playlist-menu` (закрывает меню плейлиста, открытое на шаге 2) и полупрозрачной заливкой `areaTargetIds` на первой строке, чтобы было видно, о какой строке речь; действие `close-playlist-menu` регистрирует `usePlaylistMenuTourActions` (`src/pages/playlist/lib/usePlaylistMenuTourActions.ts`) через `useTourActionRegistrar`. `playlist-share` («Поделиться плейлистом»): 8 шагов (6 карточек) — интро-карточка без цели, тур сам открывает меню плейлиста (`open-playlist-menu`), spotlight'ит пункт «Поделиться плейлистом» (`playlist.menu-share`, `skipIfMissing`) и визуализацией `open-playlist-share` открывает окно шеринга, затем три карточки внутри модалки — «QR-код» (`playlist.share-modal-qr`), «Копировать ссылку» (`playlist.share-modal-copy`), «Отправить ссылку» (`playlist.share-modal-send`) — все `presentOnTop` с целями `skipIfMissing`; финальная карточка закрывает модалку и меню (`actionOnEnterId: close-playlist-menu`). `playlist-add` («Добавление в плейлист»): 7 шагов только про добавление — начинается вводной карточкой без цели, тур сам открывает меню первой строки (`open-playlist-row-menu`), spotlight'ит пункт «Добавить в плейлист» (`playlist.row-menu-add`), нажимает его (`press-row-menu-add` — закрывает меню и открывает модалку для первой проповеди), затем действием `check-add-modal-favorites` сам ставит галочку «Избранных» (`playlist.add-modal-favorites`; в тексте поясняется, что снятие галочки = удаление из плейлиста) и финальным `interactive`-шагом подсвечивает «Сохранить» (`playlist.add-modal-save`) — сохранение выполняет пользователь, тур не сохраняет. Шаги удаления/пометки/удаления из истории из сценария убраны. `playlist-offline` («Прослушивание без интернета»): 10 шагов (6 карточек) — вводная карточка без цели, тур сам открывает меню шапки (`open-playlist-menu`) и spotlight'ит пункты офлайн-кэша (`playlist.menu-offline-add`/`-remove`), затем действием `actionOnEnterId: close-playlist-menu` закрывает меню шапки и визуализацией `open-playlist-row-menu` мигает на первой строке, spotlight'ит встроенный кэш-пункт меню строки (`playlist.row-menu-offline-add`/`-remove`, `skipIfMissing` — id пункта переключается по состоянию кэша через DI-проп `cacheActionOnboardingTargetIds`), после чего переходами входа возвращается на «Слушать» (`tab.listen`) и «Ещё» (`tab.more`) и spotlight'ит пункт «Офлайн» (`more.offline-item`). Управление меню строки устроено через dependency inversion: `entities/track-list` не импортирует `features/onboarding`, а page передаёт строке generic-пропсы `bindMenuOpener` (первый ряд отдаёт `{ open, close }` в `usePlaylistRowMenuTourActions`), `renderMenuItem` (оборачивает пункт дропдауна в `OnboardingTarget` по `onboardingTargetId`) и `cacheActionOnboardingTargetIds` (ids встроенного кэш-пункта: `add` — пока строка не в кэше, `remove` — когда в кэше); id пунктов меню проставляет `usePlaylistActions` только для первой строки. Модалку добавления обвязывает `useAddToPlaylistTour` (`src/pages/playlist/lib/useAddToPlaylistTour.tsx`): строку «Избранных», иконку-кнопку «Создать плейлист» в шапке модалки (`playlist.add-modal-create`) и кнопку «Сохранить» он оборачивает в `OnboardingTarget` через `renderRowWrapper`/`renderCreateWrapper`/`renderSaveWrapper`, а управление выбором получает через `bindControls` (тот же паттерн bind, фича `features/add-to-playlist` об онбординге не знает); `usePlaylistAddToPlaylist` связывает его с модалкой. Якорь `playlist.first-row` — `OnboardingTarget` вокруг **только первой** строки списка, её вешает `usePlaylistItemRenderer` (`src/pages/playlist/ui/usePlaylistItemRenderer.tsx`) при `index === 0`; сам ряд не меняется, обёртка — обычный `View`. Сценарий `playlists` этот экран не включает (живёт на `/listen`, `/listen/my-playlists`, `/listen/playlist-list`), см. [features/onboarding.md](../features/onboarding.md).

## Откуда данные

- Параметр маршрута `custom` (deep link на локальный плейлист, см. [features/deep-links.md](../features/deep-links.md)) имеет приоритет над `playlist`: пока он присутствует, `playlist` для резолва игнорируется, а `useCustomPlaylistImport` гидратирует `myPlaylistsAtom` (`loadMyPlaylists` — чтобы read-modify-write не шёл по негидратированному атому) и ищет **совпадение по содержимому** (тот же `title` и тот же **порядок** `sermonIds`): неизменённый плейлист открывается повторно, а переименованный/изменённый (тот же content-id, но другой title или список id) больше не перехватывает клик — создаётся новый (`createLocalPlaylist`; если производный id уже занят другим плейлистом, создание идёт с генерируемым uuid). **URL больше не заменяется**: хук возвращает id импортированного плейлиста на экран (`importedPlaylistId`), а шареные параметры остаются в адресной строке — пользователь может скопировать ссылку. Недействительная ссылка — тост «Ссылка на плейлист недействительна» и очистка `custom`. Пока импорт в полёте (`custom` присутствует, а целевой id ещё не подставлен), экран рендерит состояние загрузки (`PlaylistStatusView` без `notFound`) вместо преждевременного «Плейлист не найден».
- Параметр маршрута `playlist` — **id плейлиста** (`useLocalSearchParams<{ playlist: string }>`). Резолвится в полный `PlaylistData` хуком `usePlaylistById` (`src/pages/playlist/lib/usePlaylistById.ts`) по источникам по порядку: **tier 0** — локальный плейлист: если id равен `FAVORITES_PLAYLIST.id` (`favorites`), плейлист собирается из локального `myPlaylistsAtom` (title «Избранные», `sermons` из снапшот-листа, `artwork: null`) без сети и кэша, а при отсутствии снапшотов возвращается пустая заглушка `FAVORITES_PLAYLIST_DATA`; далее для серверных id — 1) live `dynamicSectionsAtom`, 2) кэш (`resolvePlaylistFromCache` через `getCachedSections`, ключ `cachedSections`), 3) сетевой запрос `GET /playlists/{id}` (`resolvePlaylistFromApi` через сгенерированный orval-клиент, маппер `mapPlaylistEntityToPlaylistData`). Сеть вызывается **только** при промахе секций и кэша — благодаря этому deep link на плейлист открывается на «чистой» установке (cold start), когда секции ещё не загружены (их тянет экран «Слушать»). Пока идёт резолв — `isLoading`; после исчерпания всех источников без результата — `notFound` (сетевая ошибка тоже завершает резолв в `notFound`, без бесконечного спиннера). Состояние резолва сбрасывается при смене id плейлиста (warm-start навигация на другой плейлист). Маршрут плейлиста сам гидратирует `myPlaylistsAtom` при монтировании (`loadMyPlaylists`), а `notFound` гейтится флагом `myPlaylistsLoadedAtom`: пока атом не гидратирован, локальный `custom-` id не может быть найден, поэтому экран держит загрузку, а не мигает «Плейлист не найден» (reload/холодный старт по `?playlist=custom-…`). Подробнее о локальных плейлистах — [features/my-playlists.md](../features/my-playlists.md).
- Плеер: `currentAudioAtom`, `isPlayingAtom`, `usePlayNewSermon` из `entities/player`. Индикация скачивания — внутри базовой строки `TracksListItem` (`useTrackItemCache` подписывается на `playlistDownloadProgressAtom` по URL трека); обёртки `PlaylistTrackItem`/`PlaylistSheetRow` не подписываются на скачивание. Прогресс-бар строки — через подписку на `playlistDownloadProgressAtom` (по URL трека).
- Кэш: `cacheUpdateTriggerAtom` (`entities/offline-cache`), `isCachingPlaylistAtom` из `src/pages/playlist/model.ts`.
- Скачивание: `PlaylistOfflineService` (`src/pages/playlist/lib/PlaylistOfflineService.ts`), меню `PlaylistHeaderMenu`/`PlaylistHeaderMenuDropdown` (`src/pages/playlist/ui/`).

## Куда можно перейти

- Тап на трек с `audioUrl` → `usePlayNewSermon({ playlist, sermon })` — запуск в плеере и открытие полноэкранного плеера. Повторный тап по тому же треку, пока запуск в полёте или в течение 1с после тапа, запустившего его, игнорируется (гард в `usePlayNewSermon`). Тап на уже играющий трек — no-op (Issue #99); тап на тот же трек на паузе возобновляет воспроизведение.
- «Слушать всё» (`handlePressPlayAll`) → запуск цели, вычисленной `usePlaylistPlaybackTarget` (см. описание кнопки выше); без истории — первый трек с `audioUrl`.
- Карандаш в шапке (локальный не-избранный плейлист) → `/listen/playlist-edit?playlist=<id>` — экран редактирования (переименование + порядок проповедей + удаление), см. [screens/playlist-edit.md](./playlist-edit.md).

## Состояния

- Загрузка: пока `usePlaylistById` резолвит плейлист из секций, кэша или сети (`isLoading`), пока идёт импорт по параметру `custom`, а также пока `myPlaylistsAtom` не гидратирован (`myPlaylistsLoadedAtom` — иначе локальный `custom-` плейлист не был бы найден) — `PlaylistStatusView` (спиннер); в этих состояниях `notFound` не показывается, чтобы не мигать «Плейлист не найден».
- Пусто: `ListEmptyComponent` — «Этот плейлист пустой»; для локального «Избранные» (`favorites`) — «В избранном пока пусто» (проп `emptyMessage` из `PlaylistScreen`).
- Офлайн: зависит от кэша треков (`cacheTrigger`); скачивание в офлайне недоступно — перед каждым треком проверяется подключение (`waitForOnline`, до 60с, signal-aware), при его отсутствии прогон прерывается уведомлением «Нет подключения к интернету». Пункт «Добавить все в офлайн» в меню кэша дизейблится при офлайне **или** когда все треки уже закэшированы **или** когда плейлист пуст (`isAddAllToOfflineDisabled = allCached || !isOnline || isEmpty`, `isEmpty` — `tracksData.length === 0`); **во время кеширования меню не блокируется** — вместо «Добавить все в офлайн» показывается «Остановить добавление в офлайн» (активно и офлайн). «Удалить из офлайн все» доступно офлайн (см. матрицу disabled выше); для пустого плейлиста оно тоже дизейблится (`cachedCount === 0`).
- Ошибка: плейлист не найден (нет в секциях, в кэше и по id в API) → `PlaylistStatusView` с `notFound` (заглушка); ошибки скачивания логируются и отображаются через диалоги/уведомления; одиночный трек ретраится (до 3 попыток, см. [features/audio-cache.md](../features/audio-cache.md)).
