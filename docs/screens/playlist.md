# Экран плейлиста

**Маршрут:** `/listen/playlist?playlist=<id плейлиста>`
**Файлы:** `app/(tabs)/listen/playlist.tsx` → `export { PlaylistScreen as default }` из `pages/playlist`
**Статус:** готов

## Что делает

Показывает один плейлист: обложку (при отсутствии artwork — фолбэк-обложка иконкой приложения, `IMAGE_PLACEHOLDER`), название, описание, кнопку «Слушать всё» и список треков (проповедей). Поддерживает скачивание плейлиста целиком через контекст-меню.

## Что показывается

- Схлопывающаяся шапка (`PlaylistHeader`, `src/pages/playlist/ui/PlaylistHeader.tsx` + `useCollapsingHeader` из `src/pages/playlist/lib/useCollapsingHeader.ts`). Обложка шапки — через `CoverImage` (eager, фолбэк `IMAGE_PLACEHOLDER`), поверх — блюр 70% (`BlurView` из `expo-blur`, `tint='dark'`) и затемняющий оверлей (`COLORS.black`, opacity 0.3) под заголовком. На Android блюр не работает без `blurTarget`: обложка обёрнута в `BlurTargetView` с `ref`, который передаётся в `BlurView` (`blurMethod='dimezisBlurViewSdk31Plus'` — реальный блюр на Android 12+, на более старых версиях тихий фолбэк на полупрозрачную заливку без блюра).
- Кнопка «Слушать всё» (`PlaylistHeader` → `handlePressPlayAll`).
- Список треков `TracksList`/`PlaylistTrackItem` (`src/pages/playlist/ui/PlaylistTrackItem.tsx`) с иконками «играет»/«кэш» и контекст-меню; обложка трека рендерится через `TracksListItem` (`entities/track-list`, `CoverImage` с фолбэком `IMAGE_PLACEHOLDER`). Каждый трек показывает тонкую полосу прогресса прослушивания (сохранённая позиция из `entities/listening-history` через `useHistoryProgressMap`); полоса обновляется **только по событиям** (старт, пауза/flush, переключение, завершение, удаление) — без live-тикания в реальном времени (live-чтение убрано). Завершённые треки (`progress >= 1`) затемняются (`TracksListItemContent`: обложка opacity 0.5 + приглушённый заголовок, см. [features/listening-history.md](../features/listening-history.md) → «Затемнение завершённых»). Контекст-меню трека (`usePlaylistActions.buildMenuActions`) содержит пункты истории из `buildHistoryMenuActions`: **«Добавить в плейлист»** (иконка `add-circle`, первым, см. [features/add-to-playlist.md](../features/add-to-playlist.md)), **«Пометить прослушанной»** (для незавершённых) и **«Удалить из истории»** (если проповедь в истории). Модалка мультивыбора монтируется на экране (`useAddToPlaylistModal`), одна на весь список. Под заголовком каждого трека — подпись «книга глава:стихи» (например «Бытие 1:1-5»); автор в списке не показывается — он вынесен в оверлей «Подробнее» полноэкранного плеера. Формируется через `formatSermonReference` из `src/entities/sermon/lib/formatSermonReference.ts`; в ходе миграции на спецификацию API v0.15.1 форматтер расширяется на диапазоны глав/стихов (см. [contracts/rest-api.md](../contracts/rest-api.md) → «Главы и стихи»).
- Индикаторы скачивания: прогресс плейлиста, системные уведомления (`src/pages/playlist/lib/PlaylistOfflineNotifications.ts`, `notificationConstants.ts`). Итог скачивания: при полном успехе — «Добавлено в офлайн N проповедей»; при частичной неудаче — уведомление ошибки с текстом «Не удалось добавить в офлайн X из N» (неудачные треки остаются с иконкой «облако»); при потере сети посреди прогона — прогон прерывается, уведомление «Нет подключения к интернету» (трактуется как сетевая ошибка — без алерта). **Отменённый прогон не показывает уведомлений** (остановка через «Остановить добавление в офлайн» — тихая).
- Меню шапки (`PlaylistHeaderMenu`/`PlaylistHeaderMenuDropdown`, `src/pages/playlist/ui/`): верхний пункт — **«Поделиться плейлистом»** (`PlaylistShareMenuItem`, `share-outline`): отдаёт в системный share-sheet ссылку `https://<EXPO_PUBLIC_WEB_HOSTNAME>/listen/playlist?playlist=<id>` (`buildPlaylistShareUrl`), ту же App Links-ссылку, что перехватывает Android-приложение (см. [features/deep-links.md](../features/deep-links.md)). На web (`sharePlaylist.web.ts`) при наличии Web Share API всегда используется системный `navigator.share`; копирование ссылки в буфер обмена (`navigator.clipboard.writeText`) с плавающим тостом **«Ссылка скопирована»** (`showToast`/`toastAtom`, 2 с) — **только** когда API недоступен (десктоп). Если API есть, но вызов падает (например, ограничение конкурентных вызовов на Firefox Android — второй `navigator.share` кидает `InvalidStateError`) — показывается тост ошибки **«Не удалось поделиться. Попробуйте ещё раз»** и копирования в буфер не происходит; закрытие шита пользователем (`AbortError`) не копирует и не показывает тост — кроме внутренних ошибок Chromium «Share failed»/«Permission denied», которые трактуются как ошибка. Повторный тап, пока предыдущий вызов ещё висит (guard в течение 30 с), сериализуется модульным guard'ом (`sharePlaylist.web.ts`) и сразу трактуется как отмена. Меню при этом всегда закрывается. Пункт неактивен, пока плейлист не загружен (id-заглушка `default` не является UUID, `usePlaylistShare`). Пункты кэша — во время кеширования «Добавить все в офлайн» сменяется на **«Остановить добавление в офлайн»** (иконка `stop-circle-outline`), который живёт на месте «Добавить все в офлайн» и **всегда активен — включая офлайн** (отмена не требует сети). Подмена реактивная по атому `isCachingPlaylistAtom`. После остановки: активная закачка прерывается только если она принадлежит исключительно этому прогону (иностранные джойнеры manual/auto не задеваются), run-контроллер прерывается, оставшиеся записи очереди очищаются. Пункты истории (`usePlaylistHistoryMenu`, `PlaylistHistoryDialogs`): **«Пометить все прослушанными»** (иконка `checkmark-done`, виден когда есть playable-проповедь не завершённая) и **«Удалить проповеди из истории»** (иконка `trash-outline`, виден когда хотя бы одна проповедь плейлиста есть в истории) — оба с диалогом подтверждения; массовые экшены `markSermonsListenedAction`/`removeSermonsFromHistoryAction` (см. [features/listening-history.md](../features/listening-history.md) → «Массовые операции плейлиста»). **То же меню доступно в шторке плейлиста полноэкранного плеера** — кнопка `⋮` рядом с названием плейлиста (`PlaylistBottomSheet`, виджет `widgets/expandable-player`, см. [features/player.md](../features/player.md) → `ui/PlaylistBottomSheet/`). Виджет не может импортировать `pages`, поэтому меню внедряется слоем `app`: `app/(tabs)/_layout.tsx` передаёт адаптер `PlaylistSheetMenu` (`src/pages/playlist/ui/PlaylistSheetMenu.tsx`), который переиспользует `PlaylistHeaderMenu` и собирает `tracksData` через `buildTracksListData(playlist.sermons, playlist.artwork)`. Набор пунктов, диалоги подтверждения, модалка ошибки и гейтинг идентичны экрану; отличие одно — цвет иконки: в шторке он всегда из темы, на экране переключается по скроллу (гистерезис).
- Пункт **«Удалить из офлайн все»** дизейблится, когда `cachedCount === 0` **или** очередь непуста (реактивно по `cacheQueueAtom`) **или** есть идущая закачка (реактивно по `activeCacheUrlAtom`). Дополнительно press-time guard'ы `handleClearCacheOption`/`handleClearCacheConfirm` перепроверяют `hasInflightCacheDownloads()` (belt-and-suspenders на деструктивной очистке). От сети не зависит.
- **Глобальный стоп из развёрнутого плеера:** кеширование можно остановить не только из меню кэша плейлиста, но и из полноэкранного плеера — кнопка **«Остановить все закачки»** в правом верхнем углу (`HeaderOverlay` → `StopAllCachingButton` → `useStopAllCaching` → `cancelAllCacheDownloads`). Видна, когда очередь непуста или есть активная закачка; всегда активна, в т.ч. офлайн. Прерывает плейлист-прогон (тихо, без ложного «Добавлено в офлайн N из N»), отменяет активную закачку и дренирует очередь. Подробнее — [features/audio-cache.md](../features/audio-cache.md) → «Глобальный стоп».
- Статус-бар и цвет иконок шапки адаптируются к скроллу (`usePlaylistHeader`, `usePlaylistNavigationOptions`).

## Откуда данные

- Параметр маршрута `playlist` — **id плейлиста** (`useLocalSearchParams<{ playlist: string }>`). Резолвится в полный `PlaylistData` хуком `usePlaylistById` (`src/pages/playlist/lib/usePlaylistById.ts`) по источникам по порядку: **tier 0** — локальный плейлист: если id равен `FAVORITES_PLAYLIST.id` (`favorites`), сразу возвращается заглушка (title «Избранные», пустые `sermons`, `artwork: null`) без сети и кэша; далее для серверных id — 1) live `dynamicSectionsAtom`, 2) кэш (`resolvePlaylistFromCache` через `getCachedSections`, ключ `cachedSections`), 3) сетевой запрос `GET /playlists/{id}` (`resolvePlaylistFromApi` через сгенерированный orval-клиент, маппер `mapPlaylistEntityToPlaylistData`). Сеть вызывается **только** при промахе секций и кэша — благодаря этому deep link на плейлист открывается на «чистой» установке (cold start), когда секции ещё не загружены (их тянет экран «Слушать»). Пока идёт резолв — `isLoading`; после исчерпания всех источников без результата — `notFound` (сетевая ошибка тоже завершает резолв в `notFound`, без бесконечного спиннера). Состояние резолва сбрасывается при смене id плейлиста (warm-start навигация на другой плейлист). Подробнее о локальных плейлистах — [features/my-playlists.md](../features/my-playlists.md).
- Плеер: `currentAudioAtom`, `isPlayingAtom`, `usePlayNewSermon` из `entities/player`. Индикация скачивания — внутри базовой строки `TracksListItem` (`useTrackItemCache` подписывается на `playlistDownloadProgressAtom` по URL трека); обёртки `PlaylistTrackItem`/`PlaylistSheetRow` не подписываются на скачивание. Прогресс-бар строки — через подписку на `playlistDownloadProgressAtom` (по URL трека).
- Кэш: `cacheUpdateTriggerAtom` (`entities/offline-cache`), `isCachingPlaylistAtom` из `src/pages/playlist/model.ts`.
- Скачивание: `PlaylistOfflineService` (`src/pages/playlist/lib/PlaylistOfflineService.ts`), меню `PlaylistHeaderMenu`/`PlaylistHeaderMenuDropdown` (`src/pages/playlist/ui/`).

## Куда можно перейти

- Тап на трек с `audioUrl` → `usePlayNewSermon({ playlist, sermon })` — запуск в плеере и открытие полноэкранного плеера. Повторный тап по тому же треку, пока запуск в полёте или в течение 1с после тапа, запустившего его, игнорируется (гард в `usePlayNewSermon`). Тап на уже играющий трек — no-op (Issue #99); тап на тот же трек на паузе возобновляет воспроизведение.
- «Слушать всё» → запуск первого трека с `audioUrl`.

## Состояния

- Загрузка: пока `usePlaylistById` резолвит плейлист из секций, кэша или сети (`isLoading`) — `PlaylistStatusView` (спиннер).
- Пусто: `ListEmptyComponent` — «В плейлисте нет записей»; для локального «Избранные» (`favorites`) — «В избранном пока пусто» (проп `emptyMessage` из `PlaylistScreen`).
- Офлайн: зависит от кэша треков (`cacheTrigger`); скачивание в офлайне недоступно — перед каждым треком проверяется подключение (`waitForOnline`, до 60с, signal-aware), при его отсутствии прогон прерывается уведомлением «Нет подключения к интернету». Пункт «Добавить все в офлайн» в меню кэша дизейблится при офлайне **или** когда все треки уже закэшированы (`isAddAllToOfflineDisabled = allCached || !isOnline`); **во время кеширования меню не блокируется** — вместо «Добавить все в офлайн» показывается «Остановить добавление в офлайн» (активно и офлайн). «Удалить из офлайн все» доступно офлайн (см. матрицу disabled выше).
- Ошибка: плейлист не найден (нет в секциях, в кэше и по id в API) → `PlaylistStatusView` с `notFound` (заглушка); ошибки скачивания логируются и отображаются через диалоги/уведомления; одиночный трек ретраится (до 3 попыток, см. [features/audio-cache.md](../features/audio-cache.md)).
