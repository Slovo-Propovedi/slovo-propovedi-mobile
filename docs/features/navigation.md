# Навигация (Expo Router)

**Стек:** `expo-router`, настройка — `app/`
**Статус:** готов (таб «Читать» заблокирован)

## Точка входа

`app/index.tsx` — `<Redirect href='/listen' />`. Первый экран приложения — таб «Слушать».

## Корневой стек

`app/_RootLayout.tsx` (`_RootLayout`) — содержит `Stack`:

- `index` и `(tabs)` — без шапки (`headerShown: false`);
- `settings` — заголовок «Настройки»;
- `about` — заголовок «О приложении»;
- `history` — заголовок «История прослушивания», вход из вкладки «Ещё» (`router.push('/history')`);
- `offline` — заголовок «Офлайн», вход из вкладки «Ещё» (`router.push('/offline')`);
- `share` — заголовок «Поделиться приложением» (см. [`../screens/share.md`](../screens/share.md)).
- цвет фона контента и шапки — из `currentTheme`; `headerTitleAlign: 'center'` в `screenOptions` — заголовок центрирован в шапке, а не прижат к кастомной кнопке «Назад» (см. ниже).

Список пяти под-экранов (`settings`/`history`/`offline`/`about`/`share`) — константа `SUB_SCREENS` в `src/shared/routing/rootStackScreens.ts` (вынесена из `_RootLayout.tsx`, чтобы файл уложился в лимит 130 строк ESLint).

**Кнопка «Назад» в шапке (`headerLeft`)** — кастомный `HeaderBackButton` (`src/widgets/sub-screen-header-back/ui/HeaderBackButton.tsx`) вместо стандартной кнопки react-navigation, используется в двух местах:

- пять под-экранов корневого стека (`settings`/`history`/`offline`/`about`/`share`, `_RootLayout.tsx`) — фолбэк `/more` (экран «Ещё», логический родитель всех пяти);
- стек «Слушать» (`playlist`/`playlist-list`/`my-playlists`, `app/(tabs)/listen/_layout.tsx`) — фолбэк `/listen`.

Только иконка (`Ionicons 'chevron-back'`), без текста «Назад» рядом — раньше в стеке «Слушать» использовалась нативная кнопка с `headerBackTitle: 'Назад'` (текст виден только на iOS), теперь оба стека выглядят одинаково. Контейнер 48×48 (без `hitSlop`) даёт полноразмерную область нажатия и frame для скринридеров без изменения размера иконки (24); `marginLeft: -8` сохраняет визуальное положение шеврона.

- Проп `fallbackRoute` (по умолчанию `'/more'`) задаёт, куда уходить, если истории нет — каждый стек передаёт свой через `headerLeft: props => <HeaderBackButton tintColor={props.tintColor} fallbackRoute='...' />`.
- По нажатию: если `router.canGoBack()` — `router.back()`; иначе — `router.replace(fallbackRoute)`.
- **Почему не стандартная кнопка:** на web после **полной перезагрузки страницы** (например, `F5` на `/settings`) история навигации react-navigation пуста — экран становится «корневым» в стеке, и `router.canGoBack()` возвращает `false`, поэтому системная кнопка «Назад» вообще не рендерится (react-navigation её не показывает, когда идти некуда) — пользователь не может вернуться в приложение. Кастомная кнопка рендерится всегда и в этом случае уводит на `fallbackRoute`.
- **Ограничение:** фолбэк всегда ведёт на корень стека, а не восстанавливает реальный стек навигации (например, `/listen/playlist` после релоада уйдёт на `/listen`, а не на предыдущий экран, если он был глубже). Приемлемо для текущих под-экранов; подробнее — [`debt.md`](../debt.md) → Navigation.

Глобальные элементы поверх стека: `NetworkBanner`, `ServerErrorToast`, `UpdateDialogRoot` (все — внутри `_RootLayout`).

**Аппаратная кнопка «Назад» (Android)** — обработчик `BackHandler.addEventListener('hardwareBackPress', ...)` с каскадом:

1. открыт оверлей «Подробнее» (`showDetailsAtom`) → закрыть;
2. открыто меню плеера (`showMenuAtom`) → закрыть;
3. открыты настройки звука (`showSoundSettingsAtom`) → закрыть;
4. открыта плейлист-шторка (`showPlaylistAtom`) → закрыть;
5. развёрнут плеер (`isPlayerExpandedAtom`) → `closePlayerSheetAction`;
6. есть история (`router.canGoBack()`) → `router.back()`;
7. иначе — ничего (возврат `false`).

Отдельного шага для поиска нет: «Назад» на `/search` уходит по истории на предыдущий таб, а хук `useClearSearchOnLeave` (`src/pages/search/lib/useClearSearchOnLeave.ts`) в момент смены активного маршрута сбрасывает сессию (запрос, фокус, ввод) — см. [`../screens/search.md`](../screens/search.md).

В `_RootLayout.tsx` также: подписка `subscribeToNetwork()` (модульный вызов), `checkForUpdateAction` через `setTimeout(0)` в `useEffect` (вместо `InteractionManager.runAfterInteractions`), персист позиции каждые 5с, `useUpdateNotificationResponse()`.

Провайдеры — `app/_layout.tsx`: `reatomContext.Provider` (единый `ctx`), `ThemeProvider`, `GestureHandlerRootView`, `ErrorBoundary` + `GlobalErrorHandler`. Здесь же модульные `initializePlayer()` и `initServerUrlAction(ctx)`.

### Патч expo-router: guard для `onUnhandledLinking` (удалён в SDK 58)

`patches/expo-router+57.0.28.patch` **удалён** при миграции на SDK 58: в expo-router 58.0.24 символ `onUnhandledLinking` полностью убран из сборки, поэтому и источника DEV-warning'а «Can't perform a React state update on a component that hasn't mounted yet» больше нет. В SDK 57 патч правил `build/fork/useLinking.native.js`, где `.then()` `getInitialState()` до монтирования `NavigationContainer` дёргал `onUnhandledLinking` (= `setLastUnhandledLink`, setState); патч откладывал вызов через `setTimeout(..., 0)` и пропускал его через guard `isMountedRef`. К коду приложения отношения не имел — Reatom-атомы не трогают навигационное состояние. Отдельно от этого живёт workaround cold-start гонки 150 мс — `useColdStartLinkRecovery` остаётся (см. [`../debt.md`](../debt.md) → Navigation).

## Табы

`app/(tabs)/_layout.tsx` — `Tabs` с кастомной панелью:

- 3 кнопки таба: `listen` «Слушать», `read` «Читать», `more` «Ещё» (`title` в `_layout.tsx`). Маршрут `search` зарегистрирован в таб-навигаторе (у него собственный вложенный стек), но слотом не является: `CustomTabBar` фильтрует его из списка вкладок, а открывает поиск пилюля. Пока `/search` в фокусе, активным слотом бара остаётся последний видимый таб (`useActiveTabRouteKey`): иконка и капсула не гаснут, а тап по нему возвращает на таб и закрывает поиск (см. «Кастомный таб-бар»).
- `tabBar` → `CustomTabBar` (`src/widgets/tab-bar/ui/CustomTabBar.tsx`) + `ExpandablePlayer` рендерятся поверх на всех табах. Морфящий поисковый компонент (`SearchIslandMorph` — круг ⇄ пилюля поля) смонтирован **внутри `CustomTabBar`**, а не отдельным глобальным слоем; `CustomTabBar` есть на каждом таб-экране, поэтому пилюля доступна везде. Слой `SearchGate` удалён: страница выдачи — это маршрут `search`, а «активный маршрут === search» записывается в `isSearchOpenAtom` хуком `useClearSearchOnLeave`. Плеер (`zIndex: 20`) рендерится в том же фрагменте `tabBar` следом за баром и накрывает всё, в фокусе поля опускаясь до 9 — под бар и пилюлю поиска (web-стекинг: каждый RNW-`View` сам является stacking context, поэтому плеер обязан жить в одном контексте с баром).
- Маршрут `search` — вложенный стек `Stack`: `index` (страница поиска) без шапки, `playlist` и `preacher` — реэкспорты страниц деталей с нативной шапкой стека поиска (кнопка «Назад» с фолбэком `/search`; у `playlist` шапка прозрачная, заголовок и правый хром задаёт страница); навигация из выдачи пушит `/search/playlist`, `/search/preacher` внутри маршрута, поэтому «Назад» возвращает выдачу нетронутой, а уход с активного маршрута `search` (а не blur внутри него) сбрасывает сессию поиска.
- **ВАЖНО:** таб «Читать» гейтится фича-флагом `read` — при выключенном/незагруженном флаге `CustomTabBar` показывает глобальный информационный диалог через `showInfo` («Скоро будет доступно», `useTabPress` → `shared/model/info-dialog`) и не навигирует (`isDisabled={!isTabAvailable(route.name)}`). `ReadScreen` дополнительно проверяет флаг через `useFeatureFlag` и при `false` рендерит `null` (см. [feature-flags.md](./feature-flags.md)).

## Передача параметров

Параметры передаются **строками** через `router.push({ pathname, params })` (не JSON — полный объект экран резолвит сам):

- `/listen/playlist?playlist=<UUID>` — `navigateToPlaylist` передаёт только `playlist.id`, полный `PlaylistData` экран достаёт через `usePlaylistById` (секции → кэш → API, см. [../screens/playlist.md](../screens/playlist.md));
- `/listen/playlist-edit?playlist=<UUID>` — карандаш в шапке экрана плейлиста (`PlaylistHeaderActions`) передаёт `playlist.id`; экран редактирования берёт плейлист из `myPlaylistsAtom` (см. [../screens/playlist-edit.md](../screens/playlist-edit.md));
- `/listen/playlist-list?sectionId=<строка>` — `navigateToPlaylistList` (параметр `title` в URL не передаётся, заголовок берётся из резолвнутого раздела);
- `/listen/preacher?artist=<имя>` — `useSearchNavigation` (`src/pages/search/lib/useSearchNavigation.ts`) передаёт только имя проповедника; экран парсит его (trim, непустое, ≤ 200 символов) и сам грузит проповеди (см. [../screens/preacher.md](../screens/preacher.md));
- `/listen/my-playlists` — `navigateToMyPlaylists` (без параметров) — экран редактирования порядка локальных плейлистов.

Хелперы навигации:

- `useListenNavigation.ts` (`src/pages/listen/lib/`) — `navigateToPlaylist`, `navigateToPlaylistList`, `navigateToMyPlaylists`;
- `useSearchNavigation.ts` (`src/pages/search/lib/`) — `navigateToPlaylist`, `navigateToPreacher` (пушат `/search/playlist`, `/search/preacher` внутри маршрута `search`, поверх живой сессии выдачи);
- `useReadNavigation.ts` (`src/pages/read/lib/`) — `navigateToBookReader` (`/read/book-reader`), `navigateToBooksList` (`/read/books-list`);
- `src/shared/routing/` — `useColdStartLinkRecovery.ts` (Android-only safety net холодного старта, см. «Android App Links» ниже), `launchPath.ts` (pure-хелперы разбора launch URL: `extractLaunchPath`, `shouldAttemptRecovery`), `rootStackScreens.ts` (`SUB_SCREENS` корневого стека), `useHeaderTitle.ts`.

## Кастомный таб-бар

`CustomTabBar` (`src/widgets/tab-bar/ui/CustomTabBar.tsx`) — плавающая нижняя строка в стиле Apple Music: остров табов с `BlurView` и морфящая поисковая пилюля (`SearchIslandMorph`), которая в закрытом состоянии стоит кругом справа от острова, а при открытом маршруте `/search` растягивается в поле (остров при фокусе поля уходит из строки — см. ниже). Остров ограничен `maxWidth: CONTENT_COLUMN_WIDTH` (600 px из `shared/ui/layout`): на планшетах и десктоп-web строка остаётся центрированной колонкой, на телефонах колонка шире экрана и ширина не меняется. Боковой инсет строки морфит вместе с состоянием «одна линия»: worklet `getBarSideInset(oneLineProgress)` клампит прогресс в 0..1 и интерполирует между `BAR_SIDE_INSET_EXPANDED` (= `SLIDER_REST_INSET` — линия покоя карточек слайдеров, `SLIDER_PEEK` + `INDENTS.middle` = 24; развёрнутый бар с отцепленной пилюлей мини-плеера, широкий остров табов, открытое поле поиска) и `BAR_SIDE_INSET_COLLAPSED` (×1.5 = 36; пилюля сложена в однострочный ряд) за те же `BAR_MORPH_DURATION_MS` (300). Прогресс публикует модульный `oneLineBarMorphDriver` (`src/widgets/tab-bar/model/oneLineBarMorphDriver.ts`, фабрика `createAtomMorphDriver`) от `isOneLineBarAtom` (= `isBarCollapsedAtom && !isSearchFieldVisibleAtom`, `src/widgets/tab-bar/model/barMorph.ts`); паддинг строки анимирует `useRowInsetStyle` через longhand-свойства `paddingLeft`/`paddingRight` (shortform `paddingHorizontal` Reanimated на web не анимирует), а рестинг-слой отдаёт settled-инсет, чтобы морф не красил целевую геометрию на кадр раньше. Поэтому контент строки (остров табов + зазор + круг поиска) начинается от `getColumnSideInset(screenWidth, 0, CONTENT_COLUMN_WIDTH) + getBarSideInset(...)` и занимает `min(экран, CONTENT_COLUMN_WIDTH) − 2 × getBarSideInset(...)`; на эти же края опирается развёрнутая пилюля мини-плеера (см. [player.md](./player.md)), поэтому её левый/правый край совпадают с краями острова и круга поиска на любой ширине.

Фон острова и круга поиска — общий стеклянный рецепт `src/shared/ui/glass/` (`GlassSurface` + `createGlassStyles`), тот же, что у пилюли мини-плеера и пилюли поиска: полупрозрачная заливка, блюр и 1px светлая рамка; значения и платформенные оговорки — в [theme.md](./theme.md#стеклянные-нижние-острова-frosted-glass). Теней у нижних островов нет вовсе: глубину читает сама полупрозрачная заливка стекла и 1px рамка (см. [theme.md](./theme.md#стеклянные-нижние-острова-frosted-glass)). Градиентная подложка `BarBackdropShade` под нижним хромом удалена. На Android `elevation: 12` у ряда островов, а не у контейнера табов: острова остаются над контентом экранов. На Android 12+ острова размывают реальный контент страницы: `BlurTargetProvider` над навигатором (`app/(tabs)/_layout.tsx` и `app/admin/(tabs)/_layout.tsx`) публикует target активного маршрута, а корень каждого экрана с видимой нижней строкой обёрнут в `BlurBackdrop` — табы (включая `/search`), вложенные маршруты стеков «Слушать» и `search` и табы админки; таб-бар при этом остаётся сиблингом target — потомком одной из страниц он не становится, поэтому blur не захватывает сам себя. Все поверхности нижнего хрома — остров, пилюля поиска и мини-пилюля — берут backdrop через `usePageBlurTarget`: это target страницы текущего маршрута (страница поиска публикует свой target с непрозрачным фоном темы), один и тот же в любом состоянии. Отдельного target'а у подложки больше нет — `ShadeBlurTarget`, ключ `BOTTOM_CHROME_SHADE_KEY` и `getChromeBlurTarget` удалены: хром, размывавший собственный градиент, получал плоский серый тон и на странице поиска выглядел иначе (светлее в тёмной теме, темнее в светлой), чем на остальных экранах. Во время морфов (остров табов, пилюля поиска и мини-плеер) живой блюр продолжается на всех платформах, включая Android 12+ с реальным target: статичного фолбэка больше нет, эталон — web, где стекло всегда живое (сплошная заливка фоном на морфе читалась как белая/чёрная плита; подробности и условие возможного возврата полупрозрачного фолбэка — [theme.md](./theme.md#стеклянные-нижние-острова-frosted-glass) и [debt.md](../debt.md)).

Высота острова живёт на оси D — `oneLineBarMorphDriver` от `isOneLineBarAtom`: 68 (`TAB_BAR_ISLAND_HEIGHT_EXPANDED`) в развёрнутом баре и в любом состоянии с видимым полем, 48 (`TAB_BAR_ISLAND_HEIGHT`) в однострочном ряду со скрытым полем (свёрнутая высота — не самостоятельная константа, а производная от `PLAYER_SIZES.miniPlayerHeight`: свёрнутый ряд однострочный и единой высоты). Форму и ширину двигает только ось A — `tabIslandMorphDriver` от `isTabIslandCollapsedAtom` (= `isBarCollapsedAtom || isSearchFieldVisibleAtom`, 0 = развёрнут, 1 = свёрнут): ширина интерполируется от ширины развёрнутого острова к **текущей** высоте (`interpolateSize` в `getIslandStyle`), а диаметр свёрнутого круга — это и есть текущая высота: 68×68 рядом с открытым полем, 48×48 в компактном ряду. Оси независимы (A не трогает высоту, D не трогает форму), но идут одной длительностью `BAR_MORPH_DURATION_MS`; `useTabIslandMorph` подписан на обе, слоты (`TabSlot`) берут из оси D и диаметр (ширину), и высоту — слот всегда высотой с остров; resting-двойник острова тоже двойной — высота от settled-оси D (`settledOneLine`), форма от settled-оси A (`settledCollapsed`). Круг поиска всегда остаётся идеально круглым (ширина = высота = `radius * 2`). Правило сетки: компактные 48 существуют только в однострочном ряду со скрытым полем — любое состояние с видимым полем ведёт всю строку на 68. Строка островов при этом сохраняет фиксированную высоту `BAR_ROW_MIN_HEIGHT` (76 — острову 68 остаётся 8 над кромкой, компактному 48 — 28 запаса над рядом), поэтому измеряемая высота таб-бара не скачет между состояниями.

Активный таб подсвечен капсулой: `TabButton` рисует под иконкой/подписью фон `withAlpha(currentTheme.primary, 0.18)` со скруглением `RADIUSES.round`; цвет иконки и подписи — `currentTheme.primary`; неактивные **доступные** табы — `currentTheme.text` (белый в тёмной теме, чёрный в светлой), а `currentTheme.textMuted` остаётся только у заблокированных табов (`isDisabled`, напр. «Читать») вместе с их прежним затемнением (`styles.disabledTabButton`, `opacity: 0.5`). Капсула видна только в развёрнутом баре: её прозрачность считается `getCapsuleOpacity` (1 при `progress = 0`, 0 при `progress = 1`), поэтому в свёрнутом круге остаётся только иконка активного таба без подсветки. Внутренние отступы повторяют эталонные кадры (`getIslandContentPadding`, `ISLAND_CONTENT_PADDING_HORIZONTAL = 10`, `TAB_ITEM_GAP = 8`): контент острова отступает от скруглённых краёв, между табами есть зазор 8, а капсула выходит за свой слот на `CAPSULE_HORIZONTAL_OVERHANG = 10` с каждой стороны — так подпись не прилипает к её краям. Горизонтальный padding острова анимируется тем же `progress` и в свёрнутом круге становится 0, иначе активный слот шириной с текущий диаметр круга не поместился бы в него и иконка уехала бы из центра; ширина слота в развёрнутом состоянии — `(ширина острова − 2 × padding) / число табов`, а `getTabSlotStyle` держит `minWidth = MIN_TOUCH_TARGET` (48) с затуханием к 0 вместе со скрытыми слотами (в свёрнутом круге слот и есть тач-таргет размером с текущий диаметр — 68×68 рядом с открытым полем, 48×48 в компактном ряду, — а контент таб-элемента — `getTabItemHeight` от оси D: 60 (68 − 2 × 4) в развёрнутом баре и в круге при открытом поле, 40 (48 − 2 × 4) в компактном ряду при иконке 28). Вертикальная геометрия острова (высота слота и таб-элемента) следует оси D, поэтому в круге при открытом поле (ось A схлопнута, ось D развёрнута) иконка центрирована, а горизонтальные отступы элемента по-прежнему читают ось формы A. Свёрнутый остров делает неактивные слоты неинтерактивными (`pointerEvents='none'` на `TabSlot`, `isCollapsed` из `useTabIslandMorph`): нулевая ширина слота не мешает его дочерним pressable-элементам вылезать за край острова, и без этого гейта невидимая кнопка «Ещё» перехватывала тапы по правой половине круга активного таба. Тап по кругу целиком принадлежит активному слоту. Отступы самого таб-элемента тоже анимируются: `getTabItemHorizontalMargin` гасит горизонтальный полу-зазор до 0 в свёрнутом круге (иначе остаточные 4dp сдвигали иконку вправо), а `getTabItemVerticalMargin` держит одинаковые компактные 4dp в обоих состояниях, поэтому капсула заполняет ужатый остров (Issue #153). Сами анимированные стили собирают `getIslandContentStyle`/`getTabItemStyle` (`src/widgets/tab-bar/lib/getBarMorphStyles.ts`) и используют только longhand-свойства (`paddingLeft`/`marginTop`, а не `paddingHorizontal`/`marginVertical`): Reanimated обновляет web-стили через `createReactDOMStyle` из react-native-web, минуя `preprocess`, поэтому shortform в анимированном стиле залипает на значении первого рендера (8dp padding и 4dp margin оставались в свёрнутом круге — иконка прилипала к правому краю), тогда как `width`/`height`/`opacity` продолжали анимироваться.

Свёртывание (см. `isBarCollapsedAtom`, драйвер `useBarCollapseOnScroll`): остров плавно (300 мс, `BAR_MORPH_DURATION_MS`) сжимается из полной ширины строки в круг, диаметр которого равен текущей высоте острова, оставляя только активный таб — иконку без подписи. **Высоту острова и таб-элемента задаёт только анимированный стиль** (`getIslandStyle`, `getTabItemHeight`): статический `height` в том же массиве стилей перекрывает анимированный на устройстве (остров залипал на компактных 48 и не дорастал до 68 — ниже круга поиска), а `flex: 1` на таб-элементе обнуляет flex-basis и сжимает иконку с подписью до контентной высоты. Поэтому в `styles.ts` у `floatingIsland`/`tabItem` нет ни статической высоты, ни `flex`. Клип контента острова живёт на внутренней обёртке `islandContent` (`overflow: hidden` + `borderRadius: round`), а не на host `floatingIsland` (у него `overflow` нет вовсе — стекло клипает себя само в `GlassSurface`, та же структура, что у поискового круга): на iPad Safari host-клип с `border-radius` не обрезает композитных детей (иконки с `translateY`, подписи с `opacity`), и залипший mid-morph контент рисовался вне пилюли (Issue #152). Подпись таба позиционирована абсолютно и не участвует в раскладке слота: иконка остаётся единственным flex-центрированным содержимым и не «уезжает» вверх в свёрнутом круге. В развёрнутом баре иконка поднята на фиксированный offset (`getTabIconOffset`) и уступает место подписи снизу, а при морфе плавно возвращается в центр; высота самого таб-элемента (`getTabItemHeight`) растёт вместе с островом, поэтому между иконкой и подписью остаётся чистый вертикальный зазор. Неактивные табы не размонтируются, а плавно уходят по ширине и прозрачности (`getTabSlotStyle`), чтобы не было мигания при морфе. У каждого слота, как и у самого острова, есть committed resting-слой: `TabSlot` кладёт `getTabSlotStyle` от settled-флагов (`settledCollapsed` — форма, `settledOneLine` — диаметр, оба из `useTabIslandMorph`) последним элементом массива стилей — на iPad Safari animated-стиль слота мог залипнуть на развёрнутой геометрии в середине морфа (Issue #152), и React-коммит на settle возвращает финальную геометрию, даже если animated-слой так и не ожил. Пока поле поиска видимо (`isSearchFieldVisibleAtom` — поиск открыт и бар развёрнут либо запрос активен), остров принудительно показан в свёрнутом виде даже без скролла. Фокус поля — сильнейшее состояние строки: по `isSearchFieldFocusedAtom` остров уходит из неё целиком — `getIslandStyle` гасит ширину и прозрачность до нуля (`focusProgress`), а `GlassIsland` на этом же флипе получает `pointerEvents='none'`, чтобы невидимый остров не перехватывал тапы; вне фокуса host острова — `pointerEvents='box-none'`, потому что он только позиционирует кнопки табов и не должен глотать драги по списку между ними. Когда бар свёрнут, а запрос пуст, поле поиска скрыто — остров остаётся свёрнутым по состоянию бара, а в строке снова видны круг поиска и компактный мини-плеер. Геометрия морфа вынесена в чистые хелперы `src/widgets/tab-bar/lib/getIslandStyle.ts` и хук `useTabIslandMorph`. При каждом монтировании корневого лейаута бар стартует развёрнутым: `useLaunchBarState` (`widgets/expandable-player`, вызов из `app/_RootLayout.tsx`) сбрасывает `isBarCollapsedAtom` и снапит общий драйвер «одной линии» (`oneLineBarMorphDriver.snap`) в render-фазе корня — до того, как дочерний хром заполнит `settled` из атома, — поэтому render-phase seed'ы (`useAtomMorphDriver`) читают уже развёрнутый атом: мини-пилюля не показывает свёрнутую геометрию и не проигрывает слайд запуска. Коррекция нужна на каждом монтировании, а не один раз за процесс: на Android JS-процесс переживает свайп из «недавних» (медиа-сервис), и новое открытие монтирует корень со старым флагом (см. [updates.md](./updates.md)).

**Морф стартует из подписки на атом, а не из render-эффекта.** Цель острова — вычисляемый `isTabIslandCollapsedAtom` (`isBarCollapsedAtom || isSearchFieldVisibleAtom`, `src/widgets/tab-bar/model/barMorph.ts`); модульный `tabIslandMorphDriver` (`widgets/tab-bar/model/tabIslandMorphDriver.ts`, фабрика `createAtomMorphDriver` из `shared/lib/hooks/atomMorphDriver.ts`) подписывается на него и запускает `withTiming` в том же тике, что и изменение атома. Раньше `withTiming` стоял в `useEffect` по булеву из рендера: на Android dev-сборка тратила ~130 мс на React-коммит до эффекта, и строка заметно замирала перед началом движения (на web коммит дешёвый, поэтому там задержки не было). Мини-пилюля (та же ось «одной линии»: `isOneLineBarAtom` = `isBarCollapsedAtom && !isSearchFieldVisibleAtom`, читается кросс-слайсом через `widgets/tab-bar/@x/morph`) и поле поиска (`SearchIslandMorph`, `openProgress` оси B от `isSearchOpenAtom`) стартуют так же, поэтому все поверхности движения начинаются синхронно в одном кадре. React-состояние (`isCollapsed`) по-прежнему приходит позже и обслуживает **только** гейтинг ввода, а не геометрию: скрытые слоты перестают ловить тапы на самом флипе, а тактильный отклик активного таба включается только в свёрнутом круге — `TabButton` гейтит гаптику по живому флагу (`hapticDisabled={isActive && !isBarVisuallyCollapsed}`), поэтому тап по кружку, который разворачивает бар, отзывается в пальце. Resting-геометрию кормит settled-флаг из `useAtomMorphDriver`, запаздывающий до завершения морфа: на флипе он коммитит СТАРТОВОЕ состояние новой анимации, а цель — только по completion (см. [theme.md](./theme.md)). Все оси морфа идут через модульные драйверы (фабрика `createAtomMorphDriver`, `shared/lib/hooks/atomMorphDriver.ts`; React-обёртка `useAtomMorphDriver.ts`): **A** — форма и ширина острова табов (его высота — на оси D; `widgets/tab-bar/model/tabIslandMorphDriver.ts`, атом `isTabIslandCollapsedAtom`), **B** — открытие поиска (`widgets/search-island/model/searchOpenDriver.ts`, `isSearchOpenAtom`), **C** — фокус поля (`.../searchFocusDriver.ts`, `isSearchFieldFocusedAtom`), **✕** — внешний крестик (`.../searchCloseDriver.ts`, `isSearchCloseVisibleAtom`), **D** — «одна линия» (`widgets/tab-bar/model/oneLineBarMorphDriver.ts`, `isOneLineBarAtom`) — одна ось двигает паддинг ряда островов, высоту таб-острова и его слотов, поле поиска и геометрию мини-пилюли. Оси B/C/✕ отдаются наружу кросс-импортом `widgets/search-island/@x/morphDrivers.ts`, оси A и D — `widgets/tab-bar/@x/morph.ts`. Каждая поверхность читает один и тот же инстанс своей оси, поэтому дрейфа между поверхностями нет.

**Часы морфа хранят JS-зеркала.** `createAtomMorphClock` (`shared/lib/hooks/atomMorphClock.ts`) держит `isAnimatingFlag` и `generationCounter` в обычном JS рядом с Reanimated shared values, потому что на нативе запись shared value из JS применяется на UI-потоке асинхронно (Reanimated 4.7 shareables), и чтение в том же тике возвращает устаревшее кэшированное значение. Пока активация кадровых хостов и защита от устаревшего settle читали `isAnimating.value`/`generation.value` сразу после записи, они видели старое состояние: хосты деактивировались в том же тике, `frameStep` не запускался, и все морфы нижней панели (остров, пилюля поиска, мини-плеер) залипали в стартовой позе. Правило: **никогда не принимать решения по `sv.value` сразу после записи из JS** — писать shared value для worklet и читать JS-зеркало; `frameStep` по-прежнему читает shared values на UI-потоке, где они свежие.

Скролл-драйвер подключён к основным скроллам «Слушать» (`ListenScreen`, `Animated.ScrollView` секций) и списку выдачи страницы поиска (`SearchResultsList`, через `useBarCollapseOnScroll`), а также к истории (`HistoryScreen`), офлайну (`OfflineScreen`) и сворачивающимся шапкам плейлистов (`pages/playlist/lib/useCollapsingHeader.ts`, `widgets/playlist-list/lib/useCollapsingHeader.ts`). Драйвер приостанавливается (`isSuspended`), пока развёрнут плеер (`isPlayerExpandedAtom`), **нет активной проповеди** (`currentAudioAtom === null` — без мини-плеера свёрнутая строка оставила бы мёртвый зазор на его месте) **или** активен маршрут поиска — на любой запрос, включая пустой (`isSearchBarCollapseSuspendedAtom` = `isSearchOpenAtom`; открытая страница поиска владеет экраном, а вложенные `/search/*` входят в тот же активный маршрут, поэтому драйвер остаётся приостановленным). Все три условия собирает хук `useIsBarCollapseSuspended` (`src/features/sermon-search/lib/useIsBarCollapseSuspended.ts`, наружу отдаётся кросс-импортом `features/sermon-search/@x/suspension`); его читают все перечисленные драйверы (`SearchResultsList` — тоже). `currentAudioAtom` и `isPlayerExpandedAtom` реэкспортированы через `entities/player/@x/sheet`, чтобы экраны и виджеты не тянули barrel `entities/player` с expo-audio в модульный граф списков (падали тесты экранов); `useIsSearchBarCollapseSuspended` — внутренний хелпер фичи, внешних экспортов у него нет. Пока поиск открыт, прокрутка его списков (выдачи и недавних) бар не сворачивает. Оба списка при этом ставят `keyboardDismissMode='on-drag'`: драг по строке, оказавшейся под нижним хромом, опускает клавиатуру и одновременно прокручивает список, а позы страницы от фокуса не зависят, поэтому blur на драге ничего не перестраивает. Касаниям пройти сквозь полосу помогает гейтинг слоёв: `floatingContainer` и `islandsRow` — `box-none`, host таб-острова — `box-none` в покое и `none` в фокусе поля, кадр `SearchIslandMorph` — `box-none` (интерактивны только его дети: поле с микрофоном/очисткой, тап-слой закрытого круга и «✕»), слой мини-плеера — `box-none`. Поэтому скролл начинается на любой точке полосы, кроме самих контролов (тап/драг ровно по пилюле, «✕» или кнопкам табов по-прежнему принадлежит им). Драйвер подписан на `isBarCollapsedAtom` и зеркалит внешние изменения в свой UI-thread snapshot: тап по свёрнутому кружку разворачивает бар без события скролла, и без синхронизации следующий скролл вниз считал бы бар уже свёрнутым и не сворачивал бы его до пересечения верхнего порога. При этом драйвер запоминает последний обработанный offset: повторный `onScroll` с тем же offset (перестройка layout/клавиатуры, вызванная самим тапом) не считается скроллом и не сворачивает только что развёрнутый бар — иначе первый тап по кругу поиска или активного таба в свёрнутой строке визуально «не срабатывал». Реальный скролл (offset изменился) сворачивает бар как раньше. Работает одинаково на нативе и web: `onScroll` читает `event.contentOffset.y`, который react-native-web поставляет так же.

Изменение offset бывает и не жестом: когда над вьюпортом монтируется/размонтируется контент (на «Слушать» при активации поискового запроса секции заменяются списком результатов, при очистке — возвращаются), scroll anchoring браузера сдвигает `scrollTop` на высоту этого блока и присылает обычный `onScroll` — например, 600 → 552. Раньше драйвер принимал такой сдвиг за скролл и сворачивал только что развёрнутый бар: первый тап по кругу поиска из свёрнутой строки открывал поле и тут же прятал его обратно (визуально «тап не сработал»), а закрытие ✕ или тап по кругу активного таба из закрытой поисковой сессии снова сворачивали бар. Поэтому смена высоты контента помечает следующий изменённый offset как layout-сдвиг: он только перебазирует драйвер (`lastOffset`) без пересечения порогов, а следующее настоящее событие скролла снова сворачивает/разворачивает бар. Сигналов два, и они не зависят от порядка доставки: `onContentSizeChange` от скролла (на «Слушать» подключён к `Animated.ScrollView`) и `contentSize` самого события `onScroll`. Второй обязателен на web: react-native-web присылает anchoring-`onScroll` в шаге рендера, а `onContentSizeChange` — это `onLayout` контент-контейнера, который доезжает только следующим React-коммитом. Без сравнения `contentSize` из самого события с сохранённой высотой драйвер видел сдвинутый offset раньше смены высоты и сворачивал бар — тот же «первый тап не сработал». Замер высоты при монтировании (до первого скролла) перебазированием не считается, иначе первый скролл пользователя после запуска экрана терялся бы. Дельта меньше пикселя считается округлением layout, а не сменой контента.

**Ретракт острова по фокусу поля (`searchFocusMorphDriver`).** Пока поле в фокусе, остров табов уходит из строки целиком: `getIslandStyle` гасит его ширину и прозрачность до нуля по `focusProgress` (`searchFocusMorphDriver` от `isSearchFieldFocusedAtom`), а пилюля поиска растягивается до левого внутреннего края. При открытом маршруте без фокуса строка читается как `[круг активного таба][поле]`: остров остаётся кругом, пилюля занимает слот справа от него. Обе поверхности идут одной длительностью `BAR_MORPH_DURATION_MS`, поэтому не рассинхронизируются. Мини-плеер при этом остаётся **отделённым** от строки: `isOneLineBarAtom` требует «бар свёрнут **и** поле не видимо», а тюк пилюли под фокусом — отдельная анимация по `searchFocusMorphDriver` (`translateY` + fade в `CollapsedMiniPlayer`), поэтому в фокусе пилюля плеера уезжает под строку поиска, а не сворачивается в неё. Когда тюк полностью осел (слайд + задержанный фейд, 480 мс), пилюля **полностью убирается из дерева** (`useMiniPlayerMount`), чтобы её кнопка play/pause не ловила клики под полем. На возврате пилюля монтируется сразу, но остаётся pointer-inert (`pointerEvents='none'` по `settled` морфа) до приземления обратного морфа.

Пилюля поиска `SearchIslandMorph` (`src/widgets/search-island/`) — один постоянно смонтированный стеклянный кадр (`GlassSurface`, `zIndex: 20` поверх острова), который в закрытом состоянии стоит кругом поиска у правого внутреннего края строки, а при открытом маршруте `/search` морфит из круга в пилюлю поля. Геометрию даёт `getSearchIslandGeometry`: `left`/`width` от `openProgress` (ось B, `searchOpenDriver` от `isSearchOpenAtom`; 0 — круг, 1 — слот справа от круга активного таба), высота/радиус — от однострочной оси D и `openProgress` (закрытый чип 68/48, открытое поле всегда 68), низ — от `tabBarHeight` (минус `BAR_ROW_MIN_HEIGHT`), кап — `CONTENT_COLUMN_WIDTH`; `focusProgress` (ось C от `isSearchFieldFocusedAtom`) растягивает пилюлю до левого внутреннего края и освобождает слот внешнего «✕»; `closeProgress` (ось ✕ от `isSearchCloseVisibleAtom`) резервирует под него круг диаметром с поле. Лупа 32 смонтирована всегда, размер постоянный (глиф не масштабируется — уменьшенный глиф Android обрезал по границам пилюли). Своей тени у кадра нет (теней у нижних островов нет вовсе). Внутрь кадра — `SearchBar` с полем, микрофоном при пустом запросе и ⊗ очистки при непустом; закрытый круг — прозрачный тап-слой с целью онбординга `listen.search-toggle`: его обработчик `openSearch` (`useOpenSearch`) одной транзакцией Reatom разворачивает бар (`setBarCollapsed(false)`) и поднимает `isSearchOpenAtom`, и только затем вызывает `router.navigate('/search')` — морф круга в пилюлю стартует из подписки на атом в том же тике и не ждёт коммита маршрута. Внешний «✕» (`SearchIslandCloseSlot`, контент того же кадра) виден, пока поле в фокусе или запрос непустой, и закрывает поиск: `resetSearchSession` + `Keyboard.dismiss` + `router.back()` (fallback `router.navigate('/listen')`). Перехода видимости нет — кадр не фейдится и не размонтируется, геометрия морфится; кроссфейдится только контент по `openProgress`. Строка таб-бара и её контейнер помечены `pointerEvents='box-none'`, чтобы пустая область строки не перехватывала тапы; живая сессия голосового ввода абортится на blur поля, очистке ⊗ и сбросе сессии. При скрытом поле (другой таб) поле блюрится, чтобы клавиатура не висела над невидимым полем (`useSearchInputFocus`).

Строка табов имеет фиксированную высоту `BAR_ROW_MIN_HEIGHT` (76) плюс нижний отступ `getBarBottomPadding(insets.bottom)` (`src/shared/ui/layout/bottomBarLayout.ts`) — этого хватает развёрнутому острову (68) с запасом, а свёрнутый остров (48 в компактном ряду, 68 при видимом поле) умещается в той же строке. Высота самой строки не зависит от морфа острова (меняется только остров внутри), поэтому измеренная высота таб-бара не скачет между состояниями. На админских табах (`app/admin/(tabs)/_layout.tsx`) кнопка поиска скрыта пропом `hideSearch`.

**Клавиатура.** В edge-to-edge (RN 0.88) `windowSoftInputMode="adjustResize"` больше не уменьшает окно, поэтому нижняя строка сама не поднимается над системной клавиатурой — ни на Android, ни на iOS. `useKeyboardBottomInsetSync()` (`src/shared/ui/layout/lib/keyboardInset.ts`) смонтирован один раз в `app/_layout.tsx`, слушает `keyboardDidShow`/`keyboardDidHide` и пишет высоту клавиатуры в общий Reanimated shared value `keyboardBottomInsetSv`; на web подписки нет (визуальным вьюпортом занимается браузер, поведение прежнее). Каждый контейнер нижней строки применяет `translateY = −keyboardBottomInsetSv` к своему внешнему pass-through слою: `CustomTabBar` (`floatingContainer`, а внутри него и `SearchIslandMorph` вместе с кругом «✕») и мини-плеер (`CollapsedMiniPlayer` для пилюли, `ContainerView` для контейнера-подложки). Полноэкранный плеер не сдвигается: в `ContainerView` lift включается только при `expanded === false`, а `progress`-анимация разворота остаётся прежней. Высота строки измеряется через `onLayout` и от `transform` не зависит, поэтому `tabBarHeightAtom` и геометрия островов не пересчитываются при появлении клавиатуры. Поле поиска, результаты и мини-пилюля остаются видимыми над клавиатурой.

Подписи табов не переносятся и почти не масштабируются шрифтом: в `TabButton.tsx` у текста заданы `numberOfLines={1}` и `maxFontSizeMultiplier={1.2}` (фикс «сломанного» таб-бара на узких экранах / крупном системном шрифте, Issue #53).

Тап по уже активному табу в развёрнутом баре «молчалив»: без хаптик-отклика и без нажимного затемнения (blink) — `TabButton` передаёт `hapticDisabled={isActive && !isBarVisuallyCollapsed}` в `TouchableButton` и `activeOpacity={1}` для активного таба; навигация для активного таба и так пропускается в `useTabPress` (кроме режима активного `/search`, см. ниже). В свёрнутом баре виден только круг активного таба, и тап по нему **разворачивает бар** (`setBarCollapsed(false)`, тот же морф 300 мс), не навигируя: мини-плеер поднимается автоматически, потому что его геометрия читает тот же `isBarCollapsedAtom`. Этот тап получает обычный хаптик нажатия (ранний пульс и `hapticLight` на отпускании), как любое «возвратное» нажатие: свёрнутость (`isBarVisuallyCollapsed` из `useTabIslandMorph`) снимает `hapticDisabled` с активного таба. Бар не открывает и не закрывает поиск: тап по кругу обрабатывает тап-слой пилюли (`useOpenSearch`: разворот бара и флаг одной транзакцией, затем `router.navigate('/search')`), закрытие — внешний «✕», «Назад» или смена таба, а сброс сессии — `useClearSearchOnLeave`.

**Пока активен маршрут `/search`, бар подсвечивает последний видимый таб.** Активный слот `CustomTabBar` берёт не из `state.index` (там стоит `search`, у которого нет кнопки), а из `useActiveTabRouteKey` (`src/widgets/tab-bar/lib/useActiveTabRouteKey.ts`): хук запоминает ключ последнего нефильтрованного таба и, пока `/search` в фокусе, отдаёт именно его — иконка и капсула остаются на месте, бар не выглядит пустым. Запоминание идёт setState во время рендера, поэтому ключ готов на кадре фокуса `/search`, а не следующим эффектом; прямой deep link на `/search` без предыдущего таба откатывается к первому видимому. Тап по этому табу (и по любому другому) в таком состоянии **навигирует**, а не молчит: `useTabPress` при `isSearchFocused` не применяет no-op активного таба (иначе пользователь заперт в поиске), эмитит `tabPress` и вызывает `navigateToTab`, а смена пути запускает `useClearSearchOnLeave` — запрос, фокус и ввод сбрасываются одной транзакцией, поиск закрывается.

На web кнопки табов (`TabButton`) и вложенный таб-бар (`shared/lib/tab-bar/renderTabBar.tsx`) рендерятся как настоящие `<button>` — у них задан `accessibilityRole='button'` (иначе RNW отдаёт `<div tabindex="0">`, который не получает Vimium-хинты). Подробнее — [web.md](./web.md#настоящие-button-для-vimium-хинтов).

Нижний внутренний отступ таб-бара задаётся динамически через `useBarBottomPadding()` (`src/shared/ui/layout/lib/useBarBottomPadding.ts`; приложение рендерится edge-to-edge): при реальном системном инсете (3-кнопочная или жестовая навигация, home indicator на iOS) острова стоят **вровень с линией safe-area** — без дополнительного зазора над ней; чистая формула — `getBarBottomPadding(insets.bottom)` в `src/shared/ui/layout/bottomBarLayout.ts`, где пол `BAR_BOTTOM_INSET_MIN = 12` действует на всех экранах без инета: на desktop-web (мышь — основной ввод) и в мобильных браузерах, чтобы острова не прилипали к краю экрана (Issue #56; в мобильном браузере снизу остаётся хром браузера/системных панелей), и на нативе в первые кадры, пока insets ещё нулевые. Сами острова при этом привязаны к нижней кромке content-бокса строки (не центрируются), поэтому их силуэт касается линии паддинга в обоих состояниях бара. Так как высота строки таб-бара измеряется через `onLayout` (см. ниже) и фиксирована между развёрнутым/свёрнутым состояниями, при росте таб-бара мини-плеер и экраны адаптируются автоматически — через `tabBarHeightAtom`.

Тот же принцип применён к нижнему отступу контролов полноэкранного плеера: `useBarBottomPadding()` — формула повторяет таб-бар, поэтому контролы встают на одном уровне с кнопками таб-бара и на жестовой навигации, и на 3-кнопочной (Issue #105).

Высота строки таб-бара (`BAR_ROW_MIN_HEIGHT` + `getBarBottomPadding(insets.bottom)`) измеряется через `onLayout` на строке островов и записывается в `tabBarHeightAtom` (`src/shared/ui/layout`, экшен `setTabBarHeight`) — это единственный источник правды о высоте таб-бара. Неположительная высота — не измерение: `onLayout` игнорирует `height <= 0` и не публикует её (неактивный экран табов на web рендерится с `display: none` и измеряется как 0×0), поэтому в атом попадает только реальный замер. Высота строки не зависит от морфа острова (остров внутри меняет высоту 68 ⇄ 48 (48 — только в однострочном ряду со скрытым полем), но строка остаётся 76), поэтому повторного измерения на каждом кадре морфа нет и высота не скачет между свёрнутым и развёрнутым состояниями. Начальное значение атома — приближение `PLAYER_SIZES.tabBarHeight` из темы, только до первого измерения. Потребители высоты (мини-плеер, нижние отступы экранов) читают атом, константу напрямую больше не используют — см. [player.md](./player.md) и [state.md](./state.md).

## Анимации и Reduce Motion

Все морфы нижней строки — остров табов, пилюля/поле поиска и мини-плеер — идут через Reanimated, чьи анимации по умолчанию используют `ReduceMotion.System`. Если ОС или браузер сообщают об уменьшении движения (Android → «Удалить анимации» в специальных возможностях / `animator duration scale = 0`; `prefers-reduced-motion: reduce` в браузере), `withTiming` завершается мгновенно, без кадров: морф не проигрывается, а сразу оказывается в целевом состоянии. Это **осознанное доступное поведение** — приложение намеренно не переопределяет его глобальным `ReducedMotionConfig` (рассматривали и отклонили).

**Диагностика для агентов:** «анимации прыгают мгновенно» / «морф бара не проигрывается» → первым делом проверьте системную настройку анимаций устройства или браузера, а не ищите регресс в коде. В этом режиме приложение работает корректно, просто без промежуточных кадров.
