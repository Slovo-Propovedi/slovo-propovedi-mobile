# Навигация (Expo Router)

**Стек:** `expo-router`, настройка — `app/`
**Статус:** готов (таб «Читать» заблокирован)

## Точка входа

`app/index.tsx` — `<Redirect href='/listen' />`. Первый экран приложения — таб «Слушать».

## Корневой стек

`app/_RootLayout.tsx` (`_RootLayout`) — содержит `Stack`:

- `index` и `(tabs)` — без шапки (`headerShown: false`);
- `settings` — заголовок «Настройки»;
- `about` — заголовок «О приложении»;
- `history` — заголовок «История прослушивания», вход из вкладки «Ещё» (`router.push('/history')`);
- `offline` — заголовок «Офлайн», вход из вкладки «Ещё» (`router.push('/offline')`);
- `share` — заголовок «Поделиться приложением» (см. [`../screens/share.md`](../screens/share.md)).
- цвет фона контента и шапки — из `currentTheme`; `headerTitleAlign: 'center'` в `screenOptions` — заголовок центрирован в шапке, а не прижат к кастомной кнопке «Назад» (см. ниже).

Список пяти под-экранов (`settings`/`history`/`offline`/`about`/`share`) — константа `SUB_SCREENS` в `src/shared/routing/rootStackScreens.ts` (вынесена из `_RootLayout.tsx`, чтобы файл уложился в лимит 130 строк ESLint).

**Кнопка «Назад» в шапке (`headerLeft`)** — кастомный `HeaderBackButton` (`src/widgets/sub-screen-header-back/ui/HeaderBackButton.tsx`) вместо стандартной кнопки react-navigation, используется в двух местах:

- пять под-экранов корневого стека (`settings`/`history`/`offline`/`about`/`share`, `_RootLayout.tsx`) — фолбэк `/more` (экран «Ещё», логический родитель всех пяти);
- стек «Слушать» (`playlist`/`playlist-list`/`my-playlists`, `app/(tabs)/listen/_layout.tsx`) — фолбэк `/listen`.

Только иконка (`Ionicons 'chevron-back'`), без текста «Назад» рядом — раньше в стеке «Слушать» использовалась нативная кнопка с `headerBackTitle: 'Назад'` (текст виден только на iOS), теперь оба стека выглядят одинаково. Контейнер 48×48 (без `hitSlop`) даёт полноразмерную область нажатия и frame для скринридеров без изменения размера иконки (24); `marginLeft: -8` сохраняет визуальное положение шеврона.

- Проп `fallbackRoute` (по умолчанию `'/more'`) задаёт, куда уходить, если истории нет — каждый стек передаёт свой через `headerLeft: props => <HeaderBackButton tintColor={props.tintColor} fallbackRoute='...' />`.
- По нажатию: если `router.canGoBack()` — `router.back()`; иначе — `router.replace(fallbackRoute)`.
- **Почему не стандартная кнопка:** на web после **полной перезагрузки страницы** (например, `F5` на `/settings`) история навигации react-navigation пуста — экран становится «корневым» в стеке, и `router.canGoBack()` возвращает `false`, поэтому системная кнопка «Назад» вообще не рендерится (react-navigation её не показывает, когда идти некуда) — пользователь не может вернуться в приложение. Кастомная кнопка рендерится всегда и в этом случае уводит на `fallbackRoute`.
- **Ограничение:** фолбэк всегда ведёт на корень стека, а не восстанавливает реальный стек навигации (например, `/listen/playlist` после релоада уйдёт на `/listen`, а не на предыдущий экран, если он был глубже). Приемлемо для текущих под-экранов; подробнее — [`debt.md`](../debt.md) → Navigation.

Глобальные элементы поверх стека: `NetworkBanner`, `ServerErrorToast`, `UpdateDialogRoot` (все — внутри `_RootLayout`).

**Аппаратная кнопка «Назад» (Android)** — обработчик `BackHandler.addEventListener('hardwareBackPress', ...)` с каскадом:

1. открыт оверлей «Подробнее» (`showDetailsAtom`) → закрыть;
2. открыто меню плеера (`showMenuAtom`) → закрыть;
3. открыты настройки звука (`showSoundSettingsAtom`) → закрыть;
4. открыта плейлист-шторка (`showPlaylistAtom`) → закрыть;
5. развёрнут плеер (`isPlayerExpandedAtom`) → `closePlayerSheetAction`;
6. открыт поиск (`isSearchOpenAtom`) → `closeSearch` (поле поиска общее для всех таб-экранов, см. ниже);
7. есть история (`router.canGoBack()`) → `router.back()`;
8. иначе — ничего (возврат `false`).

В `_RootLayout.tsx` также: подписка `subscribeToNetwork()` (модульный вызов), `checkForUpdateAction` через `setTimeout(0)` в `useEffect` (вместо `InteractionManager.runAfterInteractions`), персист позиции каждые 5с, `useUpdateNotificationResponse()`.

Провайдеры — `app/_layout.tsx`: `reatomContext.Provider` (единый `ctx`), `ThemeProvider`, `GestureHandlerRootView`, `ErrorBoundary` + `GlobalErrorHandler`. Здесь же модульные `initializePlayer()` и `initServerUrlAction(ctx)`.

### Патч expo-router: guard для `onUnhandledLinking` (удалён в SDK 58)

`patches/expo-router+57.0.28.patch` **удалён** при миграции на SDK 58: в expo-router 58.0.24 символ `onUnhandledLinking` полностью убран из сборки, поэтому и источника DEV-warning'а «Can't perform a React state update on a component that hasn't mounted yet» больше нет. В SDK 57 патч правил `build/fork/useLinking.native.js`, где `.then()` `getInitialState()` до монтирования `NavigationContainer` дёргал `onUnhandledLinking` (= `setLastUnhandledLink`, setState); патч откладывал вызов через `setTimeout(..., 0)` и пропускал его через guard `isMountedRef`. К коду приложения отношения не имел — Reatom-атомы не трогают навигационное состояние. Отдельно от этого живёт workaround cold-start гонки 150 мс — `useColdStartLinkRecovery` остаётся (см. [`../debt.md`](../debt.md) → Navigation).

## Табы

`app/(tabs)/_layout.tsx` — `Tabs` с кастомной панелью:

- 3 кнопки таба: `listen` «Слушать», `read` «Читать», `more` «Ещё» (`title` в `_layout.tsx`). Все маршруты навигатора рендерятся в баре: механизм скрытых табов (`HIDDEN_TAB_ROUTE_NAMES`) удалён вместе с единственным скрытым маршрутом.
- `tabBar` → `CustomTabBar` (`src/widgets/tab-bar/ui/CustomTabBar.tsx`) + `ExpandablePlayer` рендерятся поверх на всех табах. Морфящий поисковый компонент (`SearchIslandMorph`, круг ⇄ пилюля) смонтирован **внутри `CustomTabBar`**, а не отдельным глобальным слоем; `CustomTabBar` есть на каждом таб-экране, поэтому поле поиска доступно и на вложенных экранах стека «Слушать» (`/listen/playlist`, `/listen/playlist-list` и т.д.); страницу выдачи на всех экранах рендерит глобальный `SearchGate` (`src/pages/search/ui/SearchGate.tsx`), смонтированный в `app/(tabs)/_layout.tsx`.
- **ВАЖНО:** таб «Читать» гейтится фича-флагом `read` — при выключенном/незагруженном флаге `CustomTabBar` показывает глобальный информационный диалог через `showInfo` («Скоро будет доступно», `useTabPress` → `shared/model/info-dialog`) и не навигирует (`isDisabled={!isTabAvailable(route.name)}`). `ReadScreen` дополнительно проверяет флаг через `useFeatureFlag` и при `false` рендерит `null` (см. [feature-flags.md](./feature-flags.md)).

## Передача параметров

Параметры передаются **строками** через `router.push({ pathname, params })` (не JSON — полный объект экран резолвит сам):

- `/listen/playlist?playlist=<UUID>` — `navigateToPlaylist` передаёт только `playlist.id`, полный `PlaylistData` экран достаёт через `usePlaylistById` (секции → кэш → API, см. [../screens/playlist.md](../screens/playlist.md));
- `/listen/playlist-edit?playlist=<UUID>` — карандаш в шапке экрана плейлиста (`PlaylistHeaderActions`) передаёт `playlist.id`; экран редактирования берёт плейлист из `myPlaylistsAtom` (см. [../screens/playlist-edit.md](../screens/playlist-edit.md));
- `/listen/playlist-list?sectionId=<строка>` — `navigateToPlaylistList` (параметр `title` в URL не передаётся, заголовок берётся из резолвнутого раздела);
- `/listen/my-playlists` — `navigateToMyPlaylists` (без параметров) — экран редактирования порядка локальных плейлистов.

Хелперы навигации:

- `useListenNavigation.ts` (`src/pages/listen/lib/`) — `navigateToPlaylist`, `navigateToPlaylistList`, `navigateToMyPlaylists`;
- `useReadNavigation.ts` (`src/pages/read/lib/`) — `navigateToBookReader` (`/read/book-reader`), `navigateToBooksList` (`/read/books-list`);
- `src/shared/routing/` — `useColdStartLinkRecovery.ts` (Android-only safety net холодного старта, см. «Android App Links» ниже), `launchPath.ts` (pure-хелперы разбора launch URL: `extractLaunchPath`, `shouldAttemptRecovery`), `rootStackScreens.ts` (`SUB_SCREENS` корневого стека), `useHeaderTitle.ts`.

## Кастомный таб-бар

`CustomTabBar` (`src/widgets/tab-bar/ui/CustomTabBar.tsx`) — плавающая нижняя строка в стиле Apple Music: остров табов с `BlurView` слева и единый морфящий поисковый компонент (`SearchIslandMorph`, Ionicons `search`, `accessibilityLabel='Поиск'`) справа. В закрытом состоянии он выглядит как прежний круг поиска, в открытом — как пилюля с полем: это один и тот же смонтированный кадр, а не две кнопки с передачей эстафеты. Остров ограничен `maxWidth: CONTENT_COLUMN_WIDTH` (600 px из `shared/ui/layout`): на планшетах и десктоп-web строка остаётся центрированной колонкой, на телефонах колонка шире экрана и ширина не меняется. Строка отступает по горизонтали на `BAR_SIDE_INSET` (`INDENTS.medium`, 16 — широкие боковые поля островов), поэтому её контент (остров табов + зазор + круг поиска) начинается от `getColumnSideInset(screenWidth, 0, CONTENT_COLUMN_WIDTH) + BAR_SIDE_INSET` и занимает `min(экран, CONTENT_COLUMN_WIDTH) − 2 × BAR_SIDE_INSET`; на эти же края опирается развёрнутая пилюля мини-плеера (см. [player.md](./player.md)), поэтому её левый/правый край совпадают с краями острова и круга поиска на любой ширине.

Фон острова и круга поиска — общий стеклянный рецепт `src/shared/ui/glass/` (`GlassSurface` + `createGlassStyles`), тот же, что у пилюли мини-плеера и пилюли поиска: полупрозрачная заливка, блюр и 1px светлая рамка; значения и платформенные оговорки — в [theme.md](./theme.md#стеклянные-нижние-острова-frosted-glass). Тень у строки при этом больше не принадлежит ни одному острову: единая еле заметная градиентная подложка `BarBackdropShade` во всю ширину экрана тянется от низа (без safe-area: навбар прозрачный) до верха нижнего хрома — миниплеера при видимой пилюле, иначе ряда островов — и движется вместе с ним; её единый градиент идёт от прозрачного верха к плотному низу со стопом на середине пилюли (стыка слоёв нет), а высоту двигает общий с пилюлей морф-драйвер `barMorphProgressSv` (`widgets/expandable-player/model/barMorphDriver.ts`), поэтому градиент не отстаёт от нижнего хрома; острова табов, поиск и «✕» собственных теней не имеют (см. [theme.md](./theme.md#стеклянные-нижние-острова-frosted-glass)). Подложка рендерится первым ребёнком `floatingContainer` таб-бара — выше экранов, ниже островков, на всех платформах. На Android `elevation: 12` теперь у ряда островов, а не у контейнера табов: острова остаются над контентом экранов, а подложка плоская и рисуется в документном порядке таб-бара — ниже пилюли, поэтому не композитится поверх её мороза. Прежний elevation на контейнере проецировал градиент подложки поверх мороза пилюли — это root cause репорта 2026-11-10 (см. [theme.md](./theme.md#стеклянные-нижние-острова-frosted-glass)). Никакого settle-хендоффа тени больше нет. На Android 12+ острова размывают реальный контент страницы: `BlurTargetProvider` над навигатором (`app/(tabs)/_layout.tsx` и `app/admin/(tabs)/_layout.tsx`) публикует target активного маршрута, а корень каждого экрана с видимой нижней строкой обёрнут в `BlurBackdrop` — табы, вложенные маршруты стека «Слушать» и табы админки; таб-бар при этом остаётся сиблингом target — потомком одной из страниц он не становится, поэтому blur не захватывает сам себя. Исключение — открытая страница поиска: хром размывает постоянную градиентную подложку `BarBackdropShade` под островами (`ShadeBlurTarget`, ключ `BOTTOM_CHROME_SHADE_KEY` в реестре); `getChromeBlurTarget` отдаёт её приоритетно, пока поиск открыт, поэтому переходы и диалоги не меняют backdrop. Сам `SearchGate` при этом регистрирует target своей страницы (с непрозрачным фоном темы внутри), но его читает только мини-пилюля через `usePageBlurTarget`: она плавает над страницей, а не над подложкой, и морозит именно страницу — shade дал бы ей светло-серый мороз в тёмной теме. На остальных экранах хром и пилюля по-прежнему размывают target страницы. Во время морфов (остров табов, пилюля поиска и мини-плеер) живой блюр продолжается на всех платформах, включая Android 12+ с реальным target: статичного фолбэка больше нет, эталон — web, где стекло всегда живое (сплошная заливка фоном на морфе читалась как белая/чёрная плита; подробности и условие возможного возврата полупрозрачного фолбэка — [theme.md](./theme.md#стеклянные-нижние-острова-frosted-glass) и [debt.md](../debt.md)).

Высота острова и диаметр круглой кнопки поиска зависят от состояния бара: в развёрнутом виде — `TAB_BAR_ISLAND_HEIGHT_EXPANDED` / `BAR_CIRCLE_SIZE_EXPANDED` (76), в свёрнутом — `TAB_BAR_ISLAND_HEIGHT` / `BAR_CIRCLE_SIZE` (64). Оба размера анимируются тем же `progress`-значением (0 = развёрнут, 1 = свёрнут) и той же длительностью `BAR_MORPH_DURATION_MS`, что и ширина острова: круг поиска всегда остаётся идеально круглым (ширина = высота = `radius * 2`), а высота острова интерполируется в `getIslandStyle`. Строка островов при этом сохраняет фиксированную высоту `BAR_ROW_MIN_HEIGHT` (84 — хватает развёрнутому острову 76 с запасом), поэтому измеряемая высота таб-бара не скачет между состояниями.

Активный таб подсвечен капсулой: `TabButton` рисует под иконкой/подписью фон `withAlpha(currentTheme.primary, 0.18)` со скруглением `RADIUSES.round`; цвет иконки и подписи — `currentTheme.primary`; неактивные **доступные** табы — `currentTheme.text` (белый в тёмной теме, чёрный в светлой), а `currentTheme.textMuted` остаётся только у заблокированных табов (`isDisabled`, напр. «Читать») вместе с их прежним затемнением (`styles.disabledTabButton`, `opacity: 0.5`). Капсула видна только в развёрнутом баре: её прозрачность считается `getCapsuleOpacity` (1 при `progress = 0`, 0 при `progress = 1`), поэтому в свёрнутом круге остаётся только иконка активного таба без подсветки. Внутренние отступы повторяют эталонные кадры (`getIslandContentPadding`, `ISLAND_CONTENT_PADDING_HORIZONTAL = 12`, `TAB_ITEM_GAP = 10`): контент острова отступает от скруглённых краёв, между табами есть зазор 10, а капсула выходит за свой слот на `CAPSULE_HORIZONTAL_OVERHANG = 10` с каждой стороны — так подпись не прилипает к её краям. Горизонтальный padding острова анимируется тем же `progress` и в свёрнутом круге становится 0, иначе активный слот шириной 64 не поместился бы в круг и иконка уехала бы из центра; ширина слота в развёрнутом состоянии — `(ширина острова − 2 × padding) / число табов`, а `getTabSlotStyle` держит `minWidth = MIN_TOUCH_TARGET` (48) с затуханием к 0 вместе со скрытыми слотами. Свёрнутый остров делает неактивные слоты неинтерактивными (`pointerEvents='none'` на `TabSlot`, `isCollapsed` из `useTabIslandMorph`): нулевая ширина слота не мешает его дочерним pressable-элементам вылезать за край острова, и без этого гейта невидимая кнопка «Ещё» перехватывала тапы по правой половине круга активного таба. Тап по кругу целиком принадлежит активному слоту. Отступы самого таб-элемента тоже анимируются: `getTabItemHorizontalMargin` гасит горизонтальный полу-зазор до 0 в свёрнутом круге (иначе остаточные 6dp сдвигали иконку вправо), а `getTabItemVerticalMargin` даёт развёрнутой капсуле чуть больше вертикального воздуха (6dp против компактных 4dp у свёрнутого круга). Сами анимированные стили собирают `getIslandContentStyle`/`getTabItemStyle` (`src/widgets/tab-bar/lib/getBarMorphStyles.ts`) и используют только longhand-свойства (`paddingLeft`/`marginTop`, а не `paddingHorizontal`/`marginVertical`): Reanimated обновляет web-стили через `createReactDOMStyle` из react-native-web, минуя `preprocess`, поэтому shortform в анимированном стиле залипает на значении первого рендера (12dp padding и 5dp margin оставались в свёрнутом круге — иконка прилипала к правому краю), тогда как `width`/`height`/`opacity` продолжали анимироваться.

Свёртывание (см. `isBarCollapsedAtom`, драйвер `useBarCollapseOnScroll`): остров плавно (300 мс, `BAR_MORPH_DURATION_MS`) сжимается из полной ширины строки в круг `BAR_CIRCLE_SIZE`, оставляя только активный таб — иконку без подписи. **Высоту острова и таб-элемента задаёт только анимированный стиль** (`getIslandStyle`, `getTabItemHeight`): статический `height` в том же массиве стилей перекрывает анимированный на устройстве (остров залипал в свёрнутых 64 при раскрытом баре — ниже круга поиска), а `flex: 1` на таб-элементе обнуляет flex-basis и сжимает иконку с подписью до контентной высоты. Поэтому в `styles.ts` у `floatingIsland`/`tabItem` нет ни статической высоты, ни `flex`. Подпись таба позиционирована абсолютно и не участвует в раскладке слота: иконка остаётся единственным flex-центрированным содержимым и не «уезжает» вверх в свёрнутом круге. В развёрнутом баре иконка поднята на фиксированный offset (`getTabIconOffset`) и уступает место подписи снизу, а при морфе плавно возвращается в центр; высота самого таб-элемента (`getTabItemHeight`) растёт вместе с островом, поэтому между иконкой и подписью остаётся чистый вертикальный зазор. Неактивные табы не размонтируются, а плавно уходят по ширине и прозрачности (`getTabSlotStyle`), чтобы не было мигания при морфе. Пока поле поиска видимо (`isSearchFieldVisibleAtom` — поиск открыт и бар развёрнут либо запрос активен), остров принудительно показан в свёрнутом виде даже без скролла. Фокус поля — сильнейшее состояние строки: по `isSearchFieldFocusedAtom` остров уходит из неё целиком — `getIslandStyle` гасит ширину и прозрачность до нуля (`focusProgress`), а `GlassIsland` на этом же флипе получает `pointerEvents='none'`, чтобы невидимый остров не перехватывал тапы; вне фокуса host острова — `pointerEvents='box-none'`, потому что он только позиционирует кнопки табов и не должен глотать драги по списку между ними. Когда бар свёрнут, а запрос пуст, поле поиска скрыто — остров остаётся свёрнутым по состоянию бара, а в строке снова видны круг поиска и компактный мини-плеер. Геометрия морфа вынесена в чистые хелперы `src/widgets/tab-bar/lib/getIslandStyle.ts` и хук `useTabIslandMorph`. При новом запуске/перезапуске процесса бар всегда стартует развёрнутым: корневой layout сбрасывает `isBarCollapsedAtom` на монтировании (процесс может переживать свайп из «недавних» из-за медиа-сервиса, см. [updates.md](./updates.md)).

**Морф стартует из подписки на атом, а не из render-эффекта.** Цель острова — вычисляемый `isTabIslandCollapsedAtom` (`isBarCollapsedAtom || isSearchFieldVisibleAtom`, `src/widgets/tab-bar/model/barMorph.ts`); `useAtomMorphProgress` (`src/shared/lib/hooks/useAtomMorphProgress.ts`) подписывается на него и вызывает `withTiming` в том же тике, что и изменение атома. Раньше `withTiming` стоял в `useEffect` по булеву из рендера: на Android dev-сборка тратила ~130 мс на React-коммит до эффекта, и строка заметно замирала перед началом движения (на web коммит дешёвый, поэтому там задержки не было). Мини-пилюля (`isMiniPillCollapsedAtom` = `isBarCollapsedAtom && !isSearchFieldVisibleAtom && !isSearchFieldFocusedAtom`) и поле поиска (`SearchIslandMorph`, `openProgress` от `isSearchFieldVisibleAtom`) стартуют так же, поэтому все три поверхности движения начинаются синхронно в одном кадре. React-состояние (`isCollapsed`) по-прежнему приходит позже и обслуживает **только** гейтинг ввода, а не геометрию: скрытые слоты перестают ловить тапы на самом флипе, а тактильный отклик активного таба включается только в свёрнутом круге — `TabButton` гейтит гаптику по живому флагу (`hapticDisabled={isActive && !isBarVisuallyCollapsed}`), поэтому тап по кружку, который разворачивает бар, отзывается в пальце. Resting-геометрию кормит settled-флаг из `useAtomMorph`, запаздывающий до завершения морфа: на флипе он коммитит СТАРТОВОЕ состояние новой анимации, а цель — только по completion (см. [theme.md](./theme.md)). Собственный `withTiming` у острова табов и поля поиска при этом остаётся раздельным (`useTabIslandMorph` / `SearchIslandMorph`), а общий `barMorphDriver` двигает только пилюлю и подложку — между островами возможен микродрейф, см. [debt.md](../debt.md).

Скролл-драйвер подключён к основным скроллам «Слушать» (`ListenScreen`, `Animated.ScrollView` секций) и списку выдачи страницы поиска (`SearchResultsList`, через `useBarCollapseOnScroll`), а также к истории (`HistoryScreen`), офлайну (`OfflineScreen`) и сворачивающимся шапкам плейлистов (`pages/playlist/lib/useCollapsingHeader.ts`, `widgets/playlist-list/lib/useCollapsingHeader.ts`). Драйвер приостанавливается (`isSuspended`), пока развёрнут плеер (`isPlayerExpandedAtom`), **нет активной проповеди** (`currentAudioAtom === null` — без мини-плеера свёрнутая строка оставила бы мёртвый зазор на его месте) **или** открыт поиск — на любой запрос, включая пустой (`isSearchBarCollapseSuspendedAtom` = `isSearchOpenAtom`; открытая страница поиска владеет экраном). Все три условия собирает хук `useIsBarCollapseSuspended` (`src/features/sermon-search/lib/useIsBarCollapseSuspended.ts`, наружу отдаётся кросс-импортом `features/sermon-search/@x/suspension`); его читают все перечисленные драйверы (`SearchResultsList` — тоже). `currentAudioAtom` и `isPlayerExpandedAtom` реэкспортированы через `entities/player/@x/sheet`, чтобы экраны и виджеты не тянули barrel `entities/player` с expo-audio в модульный граф списков (падали тесты экранов); `useIsSearchBarCollapseSuspended` — внутренний хелпер фичи, внешних экспортов у него нет. Пока поиск открыт, прокрутка его списков (выдачи и недавних) бар не сворачивает. Оба списка при этом ставят `keyboardDismissMode='on-drag'`: драг по строке, оказавшейся под нижним хромом, опускает клавиатуру и одновременно прокручивает список, а позы страницы от фокуса не зависят, поэтому blur на драге ничего не перестраивает. Касаниям пройти сквозь полосу помогает гейтинг слоёв: `floatingContainer` и `islandsRow` — `box-none`, подложка `BarBackdropShade` — `none`, host таб-острова — `box-none` в покое и `none` в фокусе поля, кадр `SearchIslandMorph` — `box-none` (интерактивны только его дети: поле с микрофоном/очисткой, тап-слой закрытого круга и «✕»), слой мини-плеера — `box-none`. Поэтому скролл начинается на любой точке полосы, кроме самих контролов (тап/драг ровно по пилюле, «✕» или кнопкам табов по-прежнему принадлежит им). Драйвер подписан на `isBarCollapsedAtom` и зеркалит внешние изменения в свой UI-thread snapshot: тап по свёрнутому кружку разворачивает бар без события скролла, и без синхронизации следующий скролл вниз считал бы бар уже свёрнутым и не сворачивал бы его до пересечения верхнего порога. При этом драйвер запоминает последний обработанный offset: повторный `onScroll` с тем же offset (перестройка layout/клавиатуры, вызванная самим тапом) не считается скроллом и не сворачивает только что развёрнутый бар — иначе первый тап по кругу поиска или активного таба в свёрнутой строке визуально «не срабатывал». Реальный скролл (offset изменился) сворачивает бар как раньше. Работает одинаково на нативе и web: `onScroll` читает `event.contentOffset.y`, который react-native-web поставляет так же.

Изменение offset бывает и не жестом: когда над вьюпортом монтируется/размонтируется контент (на «Слушать» при активации поискового запроса секции заменяются списком результатов, при очистке — возвращаются), scroll anchoring браузера сдвигает `scrollTop` на высоту этого блока и присылает обычный `onScroll` — например, 600 → 552. Раньше драйвер принимал такой сдвиг за скролл и сворачивал только что развёрнутый бар: первый тап по кругу поиска из свёрнутой строки открывал поле и тут же прятал его обратно (визуально «тап не сработал»), а закрытие ✕ или тап по кругу активного таба из закрытой поисковой сессии снова сворачивали бар. Поэтому смена высоты контента помечает следующий изменённый offset как layout-сдвиг: он только перебазирует драйвер (`lastOffset`) без пересечения порогов, а следующее настоящее событие скролла снова сворачивает/разворачивает бар. Сигналов два, и они не зависят от порядка доставки: `onContentSizeChange` от скролла (на «Слушать» подключён к `Animated.ScrollView`) и `contentSize` самого события `onScroll`. Второй обязателен на web: react-native-web присылает anchoring-`onScroll` в шаге рендера, а `onContentSizeChange` — это `onLayout` контент-контейнера, который доезжает только следующим React-коммитом. Без сравнения `contentSize` из самого события с сохранённой высотой драйвер видел сдвинутый offset раньше смены высоты и сворачивал бар — тот же «первый тап не сработал». Замер высоты при монтировании (до первого скролла) перебазированием не считается, иначе первый скролл пользователя после запуска экрана терялся бы. Дельта меньше пикселя считается округлением layout, а не сменой контента.

**Фокус поля (`isSearchFieldFocusedAtom`) растягивает пилюлю на всю строку.** Пока клавиатура владеет полем, круг активного таба не нужен: `getSearchIslandGeometry` принимает `focusProgress` (0..1), и слот активного таба в формуле `tabSlot = (BAR_CIRCLE_SIZE + BAR_OUTER_GAP) × (1 − focusProgress)` уезжает в ноль, поэтому левый край пилюли доходит до `rowInnerLeft` — левого внутреннего края строки (за вычетом слота внешнего «✕», пока он показан). Морф идёт той же длительностью `BAR_MORPH_DURATION_MS` и тем же `useAtomMorph`, что и у острова. Мини-плеер при этом остаётся **отделённым** от строки: `isMiniPillCollapsedAtom` требует «бар свёрнут, поле не видимо **и** не в фокусе», поэтому в фокусе пилюля плеера висит над строкой поиска, а не сворачивается в неё.

Пока поле поиска видимо (`isSearchFieldVisibleAtom`), тот же морфящий кадр `SearchIslandMorph` (`src/widgets/search-island/`, смонтирован внутри `CustomTabBar`, поэтому доступен на всех таб-экранах и вложенных плейлистах) растягивается из круга в пилюлю на месте поля. Круг не скрывается и не размонтируется — он и есть этот кадр. Видимость поля — единая формула: поиск открыт **и** (бар развёрнут **или** запрос активен после `trim`, ≥ `MIN_QUERY_LENGTH`). Отсюда матрица: открыт + пустой запрос + развёрнутый бар → поле видно; открыт + пустой + свёрнутый → поле скрыто, строка `[круг активного таба][компактный плеер][круг поиска]`; открыт + активный запрос + свёрнутый → поле видно и закреплено (результаты — отдельная скролл-область). Низ строки при видимом поле превращается в единую полосу `[круг активного таба][поле поиска]` (в фокусе — одна пилюля во всю строку, см. выше): пилюля абсолютно позиционирована по геометрии строки (`BAR_SIDE_INSET`, `BAR_CIRCLE_SIZE`, `BAR_OUTER_GAP`, `TAB_BAR_ISLAND_HEIGHT`, кап `CONTENT_COLUMN_WIDTH`, `getSearchIslandGeometry`) и растёт из круга поиска в свой слот с той же длительностью `BAR_MORPH_DURATION_MS`, что и морф острова: один общий progress от `isSearchFieldVisibleAtom` двигает `left`/`width` (0 — пилюля ровно на месте круга поиска у правого внутреннего края строки, 1 — слот справа от круга активного таба), а `barProgress` задаёт высоту/радиус (76⇄64, как у острова) и низ. Закрытие — обратный геометрический морф в круг: кадр никогда не фейдится (`opacity` контейнера не анимируется вовсе), поэтому нет fade-out с застрявшим последним кадром. Кроссфейдится только контент: иконка-лупа — всегда смонтированный первый ребёнок кадра фиксированного размера 32 (глиф не масштабируется — уменьшенный 32→22 глиф Android обрезал по границам пилюли; с открытием едет только его левый inset), поле поиска и кнопки плавно проявляются/гаснут по `openProgress`. Пока поле в фокусе, справа от пилюли виден отдельный круглый «✕» (`SearchIslandCloseSlot`, контент того же компонента): пилюля уступает ему место, уменьшаясь влево на `BAR_CIRCLE_SIZE + BAR_OUTER_GAP`, правый край круга совпадает с правым краем круга поиска, появление круга и сдвиг пилюли идут с `BAR_MORPH_DURATION_MS` (`getSearchIslandGeometry` принимает `closeProgress`). Своей `boxShadow` у «✕» нет: теней у островов и поиска больше нет вовсе — единая градиентная подложка живёт в `BarBackdropShade`. Закрытие поиска проигрывает обратный морф (геометрия 1→0 за `BAR_MORPH_DURATION_MS`), поэтому пилюля садится ровно на круг поиска, а не исчезает скачком; в скрытом состоянии контейнер остаётся смонтированным (это тот же круг), но поле внутри с `pointerEvents='none'`, скрыто от скринридеров и не держит фокус (при скрытии поле блюрится, чтобы клавиатура не висела над свёрнутой строкой). Тап по кругу поиска в свёрнутой строке вызывает `openSearch`, который разворачивает бар (`setBarCollapsed(false)`) и показывает поле, даже если поиск уже был открыт. Переход на другой таб и аппаратная кнопка «Назад» закрывают поиск. Строка таб-бара и её контейнер помечены `pointerEvents='box-none'`, чтобы пустая область строки не перехватывала тапы по полю поиска. Внутри пилюли при пустом запросе справа всегда виден микрофон (`SearchBarMicButton`, `accessibilityLabel 'Голосовой ввод'`) на любой платформе: при поддержке распознавателя он запускает web-распознавание/Android-intent, а без него (iOS, Firefox и любой web без Web Speech API) показывает информационный диалог «Голосовой ввод недоступен на этом устройстве». Финальный web-транскрипт идёт тем же локальным путём, что и печать (`handleChangeText` → `inputValue` + `searchQueryAtom`), а живая сессия абортится через `useVoiceInput.stopListening` на blur поля, очистке ⊗ и закрытии поиска (✕, `Escape`, смена таба). При непустом запросе микрофон уступает место ⊗ очистки.

Строка табов имеет фиксированную высоту `BAR_ROW_MIN_HEIGHT` (84) плюс нижний отступ `Math.max(insets.bottom, BAR_BOTTOM_INSET_MIN = 12)` — этого хватает развёрнутому острову (76) с запасом, а свёрнутый остров (64) центрируется в той же строке. Высота самой строки не зависит от морфа острова (меняется только остров внутри), поэтому измеренная высота таб-бара не скачет между состояниями. На админских табах (`app/admin/(tabs)/_layout.tsx`) кнопка поиска скрыта пропом `hideSearch`.

**Клавиатура.** В edge-to-edge (RN 0.88) `windowSoftInputMode="adjustResize"` больше не уменьшает окно, поэтому нижняя строка сама не поднимается над системной клавиатурой — ни на Android, ни на iOS. `useKeyboardBottomInsetSync()` (`src/shared/ui/layout/lib/keyboardInset.ts`) смонтирован один раз в `app/_layout.tsx`, слушает `keyboardDidShow`/`keyboardDidHide` и пишет высоту клавиатуры в общий Reanimated shared value `keyboardBottomInsetSv`; на web подписки нет (визуальным вьюпортом занимается браузер, поведение прежнее). Каждый контейнер нижней строки применяет `translateY = −keyboardBottomInsetSv` к своему внешнему pass-through слою: `CustomTabBar` (`floatingContainer`, а внутри него и `SearchIslandMorph` вместе с кругом «✕») и мини-плеер (`CollapsedMiniPlayer` для пилюли, `ContainerView` для контейнера-подложки). Полноэкранный плеер не сдвигается: в `ContainerView` lift включается только при `expanded === false`, а `progress`-анимация разворота остаётся прежней. Высота строки измеряется через `onLayout` и от `transform` не зависит, поэтому `tabBarHeightAtom` и геометрия островов не пересчитываются при появлении клавиатуры. Поле поиска, результаты и мини-пилюля остаются видимыми над клавиатурой.

Подписи табов не переносятся и почти не масштабируются шрифтом: в `TabButton.tsx` у текста заданы `numberOfLines={1}` и `maxFontSizeMultiplier={1.2}` (фикс «сломанного» таб-бара на узких экранах / крупном системном шрифте, Issue #53).

Тап по уже активному табу в развёрнутом баре «молчалив»: без хаптик-отклика и без нажимного затемнения (blink) — `TabButton` передаёт `hapticDisabled={isActive && !isBarVisuallyCollapsed}` в `TouchableButton` и `activeOpacity={1}` для активного таба; навигация для активного таба и так пропускается в `useTabPress`. В свёрнутом баре виден только круг активного таба, и тап по нему **разворачивает бар** (`setBarCollapsed(false)`, тот же морф 300 мс), не навигируя: мини-плеер поднимается автоматически, потому что его геометрия читает тот же `isBarCollapsedAtom`. Этот тап получает обычный хаптик нажатия (ранний пульс и `hapticLight` на отпускании), как круг поиска: свёрнутость (`isBarVisuallyCollapsed` из `useTabIslandMorph`) снимает `hapticDisabled` с активного таба. Если при этом сессия поиска была открыта (`isSearchOpenAtom`, например после прокрутки с пустым запросом), тот же тап **закрывает поиск** (`closeSearchAndExpand`): сброс сессии и разворот бара выполняются одной атомарной транзакцией, поэтому строка возвращается к обычному развёрнутому бару без пилюли поиска и без кадра, где пустое поле успевает показаться. Свёрнутость для этого тапа берётся из визуального состояния (`isBarCollapsedAtom || isSearchFieldVisibleAtom`), а не только из атома бара: видимое поле поиска принудительно держит остров в форме круга, даже когда живой запрос приостановил скролл-драйвер и `isBarCollapsedAtom` остался `false`. Иначе тап по кругу в этой позе уходил в «молчаливый» `tabPress` активного таба.

На web кнопки табов (`TabButton`) и вложенный таб-бар (`shared/lib/tab-bar/renderTabBar.tsx`) рендерятся как настоящие `<button>` — у них задан `accessibilityRole='button'` (иначе RNW отдаёт `<div tabindex="0">`, который не получает Vimium-хинты). Подробнее — [web.md](./web.md#настоящие-button-для-vimium-хинтов).

Нижний внутренний отступ таб-бара задаётся динамически: `Math.max(insets.bottom, BAR_BOTTOM_INSET_MIN = 12)` через `useSafeAreaInsets` (`react-native-safe-area-context`; приложение рендерится edge-to-edge). На навигации жестами/web/desktop, где системный inset не больше пола, острова сидят низко с небольшим нижним зазором 12; на 3-кнопочной навигации контент приподнимается над системными кнопками (Issue #56). Так как высота строки таб-бара измеряется через `onLayout` (см. ниже) и фиксирована между развёрнутым/свёрнутым состояниями, при росте таб-бара мини-плеер и экраны адаптируются автоматически — через `tabBarHeightAtom`.

Тот же принцип применён к нижнему отступу контролов полноэкранного плеера: `Math.max(bottomInset, BAR_BOTTOM_INSET_MIN)` через `getFullscreenPlayerBottomPadding` (`widgets/expandable-player/lib/getFullscreenPlayerBottomPadding.ts`) — формула повторяет таб-бар, поэтому контролы встают на одном уровне с кнопками таб-бара и на жестовой навигации, и на 3-кнопочной (Issue #105).

Высота строки таб-бара (`BAR_ROW_MIN_HEIGHT` + `Math.max(insets.bottom, BAR_BOTTOM_INSET_MIN)`) измеряется через `onLayout` на строке островов и записывается в `tabBarHeightAtom` (`src/shared/ui/layout`, экшен `setTabBarHeight`) — это единственный источник правды о высоте таб-бара. Неположительная высота — не измерение: `onLayout` игнорирует `height <= 0` и не публикует её (неактивный экран табов на web рендерится с `display: none` и измеряется как 0×0), поэтому в атом попадает только реальный замер. Высота строки не зависит от морфа острова (остров внутри меняет высоту 76 ⇄ 64, но строка остаётся 84), поэтому повторного измерения на каждом кадре морфа нет и высота не скачет между свёрнутым и развёрнутым состояниями. Начальное значение атома — приближение `PLAYER_SIZES.tabBarHeight` из темы, только до первого измерения. Потребители высоты (мини-плеер, нижние отступы экранов) читают атом, константу напрямую больше не используют — см. [player.md](./player.md) и [state.md](./state.md).

## Анимации и Reduce Motion

Все морфы нижней строки — остров табов, пилюля/поле поиска и мини-плеер — идут через Reanimated, чьи анимации по умолчанию используют `ReduceMotion.System`. Если ОС или браузер сообщают об уменьшении движения (Android → «Удалить анимации» в специальных возможностях / `animator duration scale = 0`; `prefers-reduced-motion: reduce` в браузере), `withTiming` завершается мгновенно, без кадров: морф не проигрывается, а сразу оказывается в целевом состоянии. Это **осознанное доступное поведение** — приложение намеренно не переопределяет его глобальным `ReducedMotionConfig` (рассматривали и отклонили).

**Диагностика для агентов:** «анимации прыгают мгновенно» / «морф бара не проигрывается» → первым делом проверьте системную настройку анимаций устройства или браузера, а не ищите регресс в коде. В этом режиме приложение работает корректно, просто без промежуточных кадров.
