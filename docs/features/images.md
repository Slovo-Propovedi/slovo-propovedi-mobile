# Кэширование и рендеринг изображений

**Слой:** `shared/ui/cover-image`
**Статус:** готов

## CoverImage

Компонент `CoverImage` (`src/shared/ui/cover-image/cover-image.tsx`) — обёртка над `expo-image`, обеспечивающая единый рендер обложек плейлистов и проповедей во всём приложении.

Композиция — контейнер (`View` с `overflow: 'hidden'`, фоном-скелетоном и переданным `style`) и абсолютно позиционированный `Image` внутри; `children` рендерятся соседями поверх изображения. Причина: `expo-image` `Image` **не поддерживает `children`** — на web они отбрасываются с предупреждением в консоли, на нативе монтируются субвью внутреннего image-view и ломают отрисовку битмапа. Такая композиция починила оверлей заголовка/описания «на карточке» в слайдерах (web и натив) и `TouchableImageBackground` на web.

### Props

| Prop         | Тип                     | По умолчанию | Описание                                                                                          |
| ------------ | ----------------------- | ------------ | ------------------------------------------------------------------------------------------------- |
| `uri`        | `string?`               | —            | URL изображения; при отсутствии/пустоте используется `IMAGE_PLACEHOLDER` (иконка приложения)      |
| `eager`      | `boolean`               | `false`      | `true` → `loading='eager'`, `priority='high'` (обложки плеера); на web `loading` всегда `'eager'` |
| `imageStyle` | `StyleProp<ImageStyle>` | —            | Стиль изображения внутри контейнера; применяется поверх `StyleSheet.absoluteFill`                 |
| `style`      | `StyleProp<ViewStyle>`  | —            | Стиль контейнера (размеры, радиусы, позиционирование); `overflow: 'hidden'` клипует изображение и `children` |
| `children`   | `ReactNode`             | —            | Оверлей поверх изображения: рендерится соседом абсолютно позиционированного `Image`, не его ребёнком |
| `testID`     | `string`                | —            | Тестовый идентификатор                                                                            |
| `transition` | `number`                | `200`        | Длительность crossfade `expo-image` (мс); квадратная обложка полноэкранного плеера передаёт `0` — без crossfade |

### Режимы загрузки

- **Lazy** (`eager=false`): `loading='lazy'`, `priority='normal'` — отложенная загрузка (HTML-атрибут `<img>`). **В этом приложении — только натив:** на web `loading` принудительно `'eager'` независимо от пропа (см. «Lazy-загрузка и web»). Используется для обложек в слайдерах (`slider-item`, `list-item`, `TracksListItem`, `touchable-image-background`, `PlaylistListItem`, `SermonSearchRow`).
- **Eager** (`eager=true`): `loading='eager'`, `priority='high'` — изображение загружается немедленно. Используется для обложек плеера (`PlaylistHeader`, `MiniPlayer`, `ExpandablePlayer`), где обложка всегда на виду. На web совпадает с режимом по умолчанию (`loading='eager'`), отличается только `priority='high'`.

### Типичные миграции

| Компонент                  | Режим | Причина                                           |
| -------------------------- | ----- | ------------------------------------------------- |
| `SliderItem`               | lazy  | Обложки в горизонтальном слайдере, видны по одной |
| `ListItem`                 | lazy  | Элементы вертикального списка                     |
| `TracksListItem`           | lazy  | Треки в плейлисте                                 |
| `TouchableImageBackground` | lazy  | Карточки плейлистов                               |
| `PlaylistListItem`         | lazy  | Элементы экрана playlist-list                     |
| `PlaylistHeader`           | eager | Шапка полноэкранного плеера, всегда на виду       |
| `MiniPlayer`               | eager | Мини-плеер внизу экрана, всегда на виду           |
| `ExpandablePlayer`         | eager | Развёрнутый плеер                                 |
| `SermonSearchRow`          | lazy  | Результаты поиска                                 |

## Фон полноэкранного плеера из обложки

`CoverImage` не получил нового публичного API для фона: развёрнутый плеер рисует **не изображение**, а сплошной цвет, выведенный из доминирующего цвета обложки (`useArtworkDominantColor`, `src/shared/lib/useArtworkDominantColor.ts`), поверх — затемняющая плёнка `rgba(0, 0, 0, 0.3)`. Сама обложка в полноэкранном плеере — квадрат (`fullscreenArtwork` в `expandedLayoutStyles`). Геометрия и поведение — в [player.md](./player.md) → «Визуал полноэкранного плеера: квадратная обложка и цветной фон».

Извлечение цвета — fail-soft: URI без протокола не скачивается (`hasUriProtocol`), а ошибка (на web — отсутствие CORS-заголовков у CDN обложек, из-за чего canvas не может прочитать пиксели; на нативе — недоступная картинка) уходит в `reportError`, фон остаётся `currentTheme.surface`. Неудачи не кешируются, поэтому временный сбой CORS/сети лечится сам при следующем монтировании или смене трека.

## Кэширование

### Уровни кэша

`expo-image` использует двухуровневый кэш:

- **Memory cache** — оперативная память, мгновенный доступ пока приложение активно.
- **Disk cache** — файловый кэш в каталоге `Caches/` ОС. Переживает рестарт приложения (iOS: `Library/Caches`, Android: `internal/.../cache`).

`cachePolicy='memory-disk'` — политика по умолчанию в `CoverImage`: сначала memory, потом disk, при отсутствии — загрузка с сети.

### Lazy-загрузка и «массовый prefetch»

В этом приложении `loading='lazy'` — **нативный режим** (на web он заменён на `'eager'`, см. ниже). Важно: у `expo-image` `loading` — это HTML-атрибут `<img>`, поэтому на нативе он фактически не ограничивает загрузку; «дальние» обложки не грузятся за счёт **виртуализации** слайдеров (off-screen элементы `FlatList` размонтируются). Продуктовое решение: **массовый prefetch ~300 плейлистов не выполняется** — это экономит трафик и память, но означает, что обложки в «дальних» слайдах подгружаются при прокрутке.

### Lazy-загрузка и web

На web `CoverImage` **всегда** ставит `loading='eager'` — `loading='lazy'` там не применяется. Причина: стартовый сплэш скрывает `#root` (`visibility: hidden`) в момент, когда уже смонтирован кэш секций из AsyncStorage; браузерный lazy `<img>` не считает такой контейнер видимым и откладывает загрузку до следующего ре-рендера (сетевого обновления секций), из-за чего кэшированные обложки «висят» пустыми. `priority` проп по-прежнему различает `high`/`normal`, но `loading` на web от него не зависит. Подробнее о сплэше — [web.md](./web.md#стартовый-сплэш).

### Жизненный цикл кэша

- Кэш изображений **физически отделён** от аудио-кэша (`document/audio-cache`). Операции с аудио-кэшем (скачивание, очистка) не затрагивают изображения.
- Кэш **НЕ очищается** при удалении проповеди/плейлиста из аудио-кэша.
- Кэш **НЕ очищается** кнопкой «Очистить офлайн» в меню экрана «Офлайн» (`audioCacheService.clearCache()` удаляет только `.mp3` файлы в `document/audio-cache`).
- Дисковый кэш **OS-purgeable** (iOS `Caches/` dir): ОС может удалить файлы при нехватке дискового пространства. При следующем открытии приложения обложки загрузятся повторно.

## Тестирование

### Мок `expo-image`

`__mocks__/expo-image.js` — проксирует `source` на `View` для тестов:

```typescript
// jest.config.ts
setupFiles: [
  // ...
  './__mocks__/expo-image.js',
]
```

Тесты компонентов с `CoverImage` ассертят `source` через `screen.getByTestId()` + `props.source` или `toJSON()` с обходом дерева, не тестируя нативный рендеринг `Image`.

## Чек-лист ручной приёмки

1. **Рестарт приложения** → обложки появляются мгновенно с диска (без мерцания/скелетона).
2. **Airplane mode после первой сессии** → обложки отображаются из disk cache.
3. **Network-лог** → запрашиваются **только видимые обложки** слайдеров (нет массовых запросов).
4. **«Очистить офлайн» в меню экрана «Офлайн»** → обложки остаются (чистится только аудио-кэш).
