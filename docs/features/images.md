# Кэширование и рендеринг изображений

**Слой:** `shared/ui/cover-image`
**Статус:** готов

## CoverImage

Компонент `CoverImage` (`src/shared/ui/cover-image/cover-image.tsx`) — обёртка над `expo-image`, обеспечивающая единый рендер обложек плейлистов и проповедей во всём приложении.

Композиция — контейнер (`View` с `overflow: 'hidden'`, фоном-скелетоном и переданным `style`) и абсолютно позиционированный `Image` внутри; `children` рендерятся соседями поверх изображения. Причина: `expo-image` `Image` **не поддерживает `children`** — на web они отбрасываются с предупреждением в консоли, на нативе монтируются субвью внутреннего image-view и ломают отрисовку битмапа. Такая композиция починила оверлей заголовка/описания «на карточке» в слайдерах (web и натив) и `TouchableImageBackground` на web.

### Props

| Prop         | Тип                     | По умолчанию | Описание                                                                                                                                                                                                              |
| ------------ | ----------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `uri`        | `string?`               | —            | URL изображения; при отсутствии/пустоте используется `IMAGE_PLACEHOLDER` (иконка приложения)                                                                                                                          |
| `eager`      | `boolean`               | `false`      | `true` → `loading='eager'`, `priority='high'` (обложки плеера); на web `loading` всегда `'eager'`                                                                                                                     |
| `imageStyle` | `StyleProp<ImageStyle>` | —            | Стиль изображения внутри контейнера; применяется поверх `StyleSheet.absoluteFill`                                                                                                                                     |
| `style`      | `StyleProp<ViewStyle>`  | —            | Стиль контейнера (размеры, радиусы, позиционирование); `overflow: 'hidden'` клипует изображение и `children`                                                                                                          |
| `children`   | `ReactNode`             | —            | Оверлей поверх изображения: рендерится соседом абсолютно позиционированного `Image`, не его ребёнком                                                                                                                  |
| `testID`     | `string`                | —            | Тестовый идентификатор                                                                                                                                                                                                |
| `transition` | `number`                | `200`        | Длительность crossfade `expo-image` (мс); фон полноэкранного плеера передаёт `0` — он уже фейдится Reanimated-прозрачностью, а crossfade перезапускался бы на каждом кадре анимации размера (видимое мигание обложки) |

### Режимы загрузки

- **Lazy** (`eager=false`): `priority='low'`, загрузка через **очередь обложек** (не больше 5 одновременно, см. «Очередь загрузки обложек»); на web — дополнительно только у вьюпорта (`useNearViewport`), сам `<img>` там `loading='eager'`; на нативе `loading='lazy'` (атрибут фактически ни на что не влияет). Используется для обложек в слайдерах (`slider-item`, `list-item`, `TracksListItem`, `touchable-image-background`, `PlaylistListItem`, `SermonSearchRow`).
- **Eager** (`eager=true`): `loading='eager'`, `priority='high'`, **вне очереди** и без проверки вьюпорта — изображение загружается немедленно. Используется для обложек плеера (`PlaylistHeader`, `MiniPlayer`, `ExpandablePlayer`), где обложка всегда на виду.

### Типичные миграции

| Компонент                  | Режим | Причина                                           |
| -------------------------- | ----- | ------------------------------------------------- |
| `SliderItem`               | lazy  | Обложки в горизонтальном слайдере, видны по одной |
| `ListItem`                 | lazy  | Элементы вертикального списка                     |
| `TracksListItem`           | lazy  | Треки в плейлисте                                 |
| `TouchableImageBackground` | lazy  | Карточки плейлистов                               |
| `PlaylistListItem`         | lazy  | Элементы экрана playlist-list                     |
| `PlaylistHeader`           | eager | Шапка полноэкранного плеера, всегда на виду       |
| `MiniPlayer`               | eager | Мини-плеер внизу экрана, всегда на виду           |
| `ExpandablePlayer`         | eager | Развёрнутый плеер                                 |
| `SermonSearchRow`          | lazy  | Результаты поиска                                 |

## Кэширование

### Уровни кэша

`expo-image` использует двухуровневый кэш:

- **Memory cache** — оперативная память, мгновенный доступ пока приложение активно.
- **Disk cache** — файловый кэш в каталоге `Caches/` ОС. Переживает рестарт приложения (iOS: `Library/Caches`, Android: `internal/.../cache`).

`cachePolicy='memory-disk'` — политика по умолчанию в `CoverImage`: сначала memory, потом disk, при отсутствии — загрузка с сети.

### Lazy-загрузка и «массовый prefetch»

В этом приложении `loading='lazy'` — **нативный режим** (на web вьюпорт отслеживает `useNearViewport`, см. «Очередь загрузки обложек»). Важно: у `expo-image` `loading` — это HTML-атрибут `<img>`, поэтому на нативе он фактически не ограничивает загрузку; «дальние» обложки не грузятся за счёт **виртуализации** слайдеров (off-screen элементы `FlatList` размонтируются). Продуктовое решение: **массовый prefetch ~300 плейлистов не выполняется** — это экономит трафик и память, но означает, что обложки в «дальних» слайдах подгружаются при прокрутке.

### Превью обложек (`thumbs/`)

Бэкенд хранит рядом с каждой загруженной картинкой превью `files/thumbs/<uuid>.webp` (WebP, длинная сторона ≤ 640 px — десятки КБ вместо 1–1,7 МБ оригинала; существующие картинки дозаполняются фоновой задачей при старте бэкенда). Это соглашение об именах, а не поле API: `getThumbnailUri` (`shared/ui/cover-image/getThumbnailUri.ts`) выводит адрес превью из `artwork` вида `…/files/<uuid>.<jpg|jpeg|png|webp>`, для прочих адресов (внешние, плейсхолдер) — `null`. `useCoverSource` отдаёт превью **не-eager** обложкам (слайдеры, списки); eager-обложки плеера остаются оригиналами (показываются крупно). Если превью не загрузилось (`onError`), обложка навсегда переключается на оригинал и заново встаёт в очередь. Контракт превью — бэкенд, `docs/modules/minio.md` → «Превью изображений».

### Очередь загрузки обложек

Оригиналы обложек тяжёлые (часто 1–1,7 МБ, ~1000 px; на «Слушать» ~94 уникальных, ~26 МБ), и даже превью лучше не грузить все сразу. Если запустить их все разом, они забивают сеть и устройство: на первом визите web обложки минутами оставались серыми, а запросы к API ждали за ними. Поэтому не-eager `CoverImage`:

1. **Ждёт приближения к вьюпорту (web).** `useNearViewport.web.ts` — `IntersectionObserver` на контейнере с запасом `300px` (`rootMargin` + `scrollMargin`, чтобы учитывалась и обрезка горизонтального слайдера); после первого пересечения остаётся `true`. Работает по геометрии, поэтому не зависит от скрытого сплэшем `#root` (именно из-за этого браузерный `loading='lazy'` не годился — он откладывал загрузку до постороннего ре-рендера). На нативе `useNearViewport.ts` всегда `true`: дальние элементы отсекает виртуализация `FlatList` слайдеров.
2. **Берёт слот в общей очереди** (`useCoverLoadSlot`, `MAX_CONCURRENT_COVERS = 5`, FIFO по порядку запроса — сверху вниз и слева направо): одновременно грузятся (из сети **или** дискового кэша) не больше 5 обложек, следующая стартует по `onLoad`/`onError` предыдущей. Слот освобождается и при размонтировании, смене `uri` и по таймауту `15 c` (если загрузка не сообщила о себе — очередь не встаёт). Очередь — общий `createSlotQueue` (`shared/lib/concurrency`).
3. **Грузится с `priority='low'`** (`fetchpriority=low` на web) — API-запросы, шрифты и иконки идут раньше.

Пока слот не выдан, виден фон-скелетон (`currentTheme.skeleton`). Замер на прод-сборке web (сеть 400 КБ/с, чистый кэш): запрошено 10 обложек вместо 42, одновременно ≤ 5, все видимые — на экране за ~20 с вместо ~45 с.

**Ограничение натива:** вертикальный `ScrollView` «Слушать» монтирует все секции, поэтому видимые первыми колонки нижних секций тоже встают в очередь (после верхних — порядок FIFO). Полная вертикальная отсечка потребовала бы виртуализации списка секций.

### Жизненный цикл кэша

- Кэш изображений **физически отделён** от аудио-кэша (`document/audio-cache`). Операции с аудио-кэшем (скачивание, очистка) не затрагивают изображения.
- Кэш **НЕ очищается** при удалении проповеди/плейлиста из аудио-кэша.
- Кэш **НЕ очищается** кнопкой «Очистить офлайн» в меню экрана «Офлайн» (`audioCacheService.clearCache()` удаляет только `.mp3` файлы в `document/audio-cache`).
- Дисковый кэш **OS-purgeable** (iOS `Caches/` dir): ОС может удалить файлы при нехватке дискового пространства. При следующем открытии приложения обложки загрузятся повторно.

## Тестирование

### Мок `expo-image`

`__mocks__/expo-image.js` — проксирует `source` на `View` для тестов:

```typescript
// jest.config.ts
setupFiles: [
  // ...
  './__mocks__/expo-image.js',
]
```

Мок вызывает `onLoad` после монтирования (как настоящая картинка) — иначе слоты очереди обложек не освобождались бы и в тестах с > 5 обложками остальные не рендерились бы. Тесты компонентов с `CoverImage` ассертят `source` через `screen.getByTestId()` + `props.source` или `toJSON()` с обходом дерева, не тестируя нативный рендеринг `Image`.

## Чек-лист ручной приёмки

1. **Рестарт приложения** → обложки появляются мгновенно с диска (без мерцания/скелетона).
2. **Airplane mode после первой сессии** → обложки отображаются из disk cache.
3. **Network-лог** → запрашиваются **только видимые обложки** слайдеров (нет массовых запросов).
4. **«Очистить офлайн» в меню экрана «Офлайн»** → обложки остаются (чистится только аудио-кэш).
