# Выбор контекста воспроизведения («Где воспроизвести проповедь?»)

Тап по проповеди на экранах, где контекст прослушивания неоднозначен, открывает
диалог выбора плейлиста. Кандидаты собираются **только из локальных данных**:
выбор работает без сети и не показывает скелетонов. Если реальных плейлистов
нет, воспроизведение стартует сразу в фолбэк-плейлисте, без диалога.

**Файлы:**

- `src/features/playback-choice/index.ts` — публичный API (`usePlaybackChoice`)
- `src/features/playback-choice/lib/usePlaybackChoice.tsx` — экранный хук:
  состояние диалога, готовый элемент `dialog`, вход `openChoice`
- `src/features/playback-choice/lib/collectPlaybackCandidates.ts` — сбор
  кандидатов (чистая функция)
- `src/features/playback-choice/ui/PlaybackChoiceDialog.tsx` — модалка со списком
  плейлистов
- `src/features/playback-choice/ui/PlaybackChoiceRow.tsx` — строка-кандидат
  (подсветка и подпись исходного плейлиста)

## API хука

`usePlaybackChoice({ errorMessage, getFallbackPlaylist, getOfflinePlaylist?, originLabel? })`
возвращает `{ dialog, openChoice }`:

- `openChoice(sermon, originPlaylist?)` — вход из строки списка; `originPlaylist` —
  плейлист, из которого сделан тап (если он есть у экрана);
- `errorMessage` — текст ошибки для `reportError`, если запуск упал;
- `getFallbackPlaylist(sermon, originPlaylist)` — **обязательный**: плейлист,
  который играет при нуле кандидатов; может вернуть `Promise` (история резолвит
  полный плейлист по секциям); `undefined` → ничего не запускается;
- `getOfflinePlaylist()` — **опциональный**: когда задан, в диалоге появляется
  первая строка «Все офлайн-проповеди», и она же играется по выбору;
- `originLabel` — **опциональный**: подпись исходного плейлиста. Когда задан и в
  `openChoice` передан `originPlaylist`, кандидат с тем же `id` подсвечивается
  (primary-тинт и рамка) и получает эту подпись второй строкой. Если исходный
  плейлист синтетический (в кандидатах его нет), подсветки не будет; без
  `originLabel` (экран «Офлайн») диалог выглядит как раньше.

Состояние диалога живёт на экране, поэтому на список монтируется **один**
`dialog`, а не по одному на строку. Колбэки должны быть стабильными
(`useCallback` на стороне экрана): `openChoice` уходит в `memo`-строки.

## Сбор кандидатов

`collectPlaybackCandidates(localPlaylists, sermon, originPlaylist?)` не делает
запросов. Порядок и состав:

1. **исходный плейлист** (`originPlaylist`), если он не синтетический;
2. **рефы `sermon.playlists`** с непустым `sermons` — лёгкие рефы (`sermons: []`)
   отбрасываются: их разворот требует API, а выбор обязан оставаться локальным;
3. **локальные плейлисты** из `myPlaylistsAtom`, содержащие проповедь, — они
   мапятся в `PlaylistData` (`artwork: null`, `description: ''`, название и
   снапшоты проповедей сохраняются).

Дедупликация — по `id`, исходный плейлист всегда первым.

**Синтетический плейлист — не контекст.** `buildManualPlaylist`
(`entities/listening-history`) создаёт плейлист с `id` = id проповеди, ровно с
одной этой проповедью. Такой снапшот приходит из истории/реестра и не означает,
что пользователь выбрал какой-то плейлист, поэтому в кандидаты он не попадает.

## Поведение

- **Кандидатов нет** → `await getFallbackPlaylist(sermon, originPlaylist)`:
  разрешённый плейлист играет сразу, диалог не открывается; `undefined` —
  запуска нет.
- **Кандидаты есть** → открывается `PlaybackChoiceDialog`: заголовок «Где
  воспроизвести проповедь?», опционально первая строка «Все офлайн-проповеди»,
  ниже — каждый плейлист с обложкой и названием. Исходный плейлист (совпадает по
  `id` с `originPlaylist`) при заданном `originLabel` подсвечивается primary-тинтом
  с рамкой и подписью «Плейлист, в котором было прослушано» (история). Список
  ограничен по высоте, backdrop закрывает диалог без воспроизведения.
- Выбор строки играет проповедь в этом плейлисте (`usePlayNewSermon`): очередь
  строится из него. Локальный плейлист даёт полную очередь с авто-переходом;
  снапшот записи истории хранит только эту проповедь (`buildContextPlaylist`),
  поэтому очередь из него однотрековая.
- Ошибка запуска ловится в try/catch и показывается через
  `reportError(error, errorMessage)`.

## Потребители

| Экран                       | `getFallbackPlaylist`                                                 | `getOfflinePlaylist`              | `originLabel`                         |
| --------------------------- | --------------------------------------------------------------------- | --------------------------------- | ------------------------------------- |
| «Офлайн» (`pages/offline`)  | все офлайн-проповеди (`buildOfflinePlaylist(items)`)                  | то же — первая строка диалога     | не передаётся — подсветки нет         |
| «История» (`pages/history`) | полный плейлист по секциям → снапшот (`resolveEntryFallbackPlaylist`) | не передаётся — офлайн-пункта нет | «Плейлист, в котором было прослушано» |

- **«Офлайн»** (`src/pages/offline/ui/OfflineScreen.tsx`): фолбэк и офлайн-строка —
  один и тот же псевдо-плейлист `offline-list` («Офлайн»), порядок — как в списке
  экрана. Ноль кандидатов → играет вся скачанная коллекция, а не один трек
  (подробнее — [screens/offline.md](../screens/offline.md)).
- **«История»** (`src/pages/history/ui/HistoryScreen.tsx`): офлайн-пункта нет и
  «история как плейлист» не предлагается; плейлист записи подсвечивается с
  подписью «Плейлист, в котором было прослушано» (если попал в кандидатов). При
  нуле кандидатов фолбэк асинхронно резолвит полный плейлист записи
  (`resolvePlaylistBySermon`: live `dynamicSectionsAtom` → sections-cache →
  снапшот), поэтому очередь и авто-переход сохраняются, а снапшот записи остаётся
  последним резервом (подробнее — [screens/history.md](../screens/history.md)).

## Почему кандидаты только локальные

Экран «Офлайн» обязан работать без сети, а экран истории не должен превращать
тап в сетевой запрос. Поэтому лёгкие рефы не разворачиваются, а недостающие
плейлисты просто не предлагаются: выбор остаётся мгновенным и предсказуемым, а
при нуле кандидатов поведение экрана не меняется.
