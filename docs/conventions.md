# Договорённости (conventions)

Этот документ описывает **процессные договорённости людей** — то, что нельзя (или нецелесообразно) проверить машиной. Машино-проверяемые правила (стиль, границы FSD) живут в ESLint + steiger и задокументированы в [`AGENTS.md`](../AGENTS.md) — здесь они не дублируются.

## Git

- **Ветки:** feature-ветки от `main`. Именование — на усмотрение команды, но MR должен быть маленьким и самодостаточным.
- **Формат коммита:** conventional commits. Типы и правила — в [`AGENTS.md`](../AGENTS.md) → «Commit Convention» (`feat`, `fix`, `refactor`, `test`, `docs`, `style`, `chore`, `build`, `ci`, `perf`, `revert`). Заголовок — максимум 100 символов. Валидация — commitlint.
- **Язык коммитов:** сообщения коммитов — только на английском (заголовок и body).
- **Pre-commit:** Husky + lint-staged прогоняют `lint:staged` и `check:types` (см. [`AGENTS.md`](../AGENTS.md)).
- **MR-процесс:** каждый MR сопровождается описанием «что и зачем», ссылками на изменённые экраны/модули и на обновлённые документы `docs/`.

## Работа с AI-агентами

- Задача даётся через ссылки на `docs/screens/`, `docs/features/`, `docs/contracts/` — а не через ссылки на код. Агент читает нужный документ из `docs/` ПЕРЕД стартом.
- Перед реализацией агент ОБЯЗАН прочитать: `architecture.md` (для архитектурных изменений), документы затронутых экранов/модулей/контрактов, и `AGENTS.md`.
- После изменения кода агент ОБЯЗАН обновить затронутые документы `docs/` **в том же PR/коммите**. Изменение кода без обновления `docs/` — неполное изменение.
- Каждое срезанное решение фиксируется в `docs/debt.md` в том же PR (см. ниже).
- Машино-проверяемые команды агент запускает из DoD-чеклиста (ниже).
- **Роли субагентов строго по назначению:** написание/изменение кода выполняет только субагент-кодер (`coder`), документацию — `scribe`, исследование кодовой базы — `explore`, внешнее исследование — `researcher`. Оркестрирующий агент не передаёт задачу по кодированию субагенту другой роли — в том числе при сбоях (сетевых ошибках провайдера и т.п.): вместо этого повторная делегация профильному агенту или уточнение у пользователя.

### Разделение ролей: план — у оркестратора, реализация — у кодера

Задача для кодера приходит с готовым планом: какие файлы менять, что именно в них менять, выбранный подход (без взвешивания альтернатив), команды проверки и план коммитов. Исследование библиотек/`node_modules`, поиск первопричин и дизайн-решения выполняются ДО делегирования. Кодер не проводит открытого исследования архитектуры и не выбирает подходы — только реализация по плану, прогоны проверок/тестов и коммиты. Если план неверен или не хватает факта — остановиться и сообщить наверх, а не импровизировать.

### Переиспользование утилит вместо инлайн-дублей

Перед реализацией типовой/обобщённой логики агент обязан сначала проверить, есть ли переиспользуемая утилита в `shared/` (искать по концепции, а не только по имени: `shared/lib`, `shared/ui`, `shared/model`). Если есть — использовать. Если нет, но логика обобщённая — добавить в подходящий `shared`-слайс С ко-локализованным тестом и использовать её. Инлайн-реализация существующей `shared`-утилиты считается дублем и подлежит рефакторингу. Инлайн остаётся только для действительно одноразовой контекстной логики.

Типовые категории, которые почти всегда должны приводить к поиску в `shared/`:

- debounce/throttle;
- таймеры/интервалы (включая отложенный вызов с авто-сбросом на размонтировании);
- type guards для `null`/`undefined`;
- проверки пустоты коллекций/объектов;
- случайные значения;
- форматирование/парсинг (время, числа).

**knip.** Утилита живёт, только пока её реально используют фичи. Намеренно оставленные «про запас» утилиты должны быть перечислены в `ignore` файла [`knip.config.ts`](../knip.config.ts) с комментарием-обоснованием. Хранить неиспользуемое «на будущее» нельзя — knip сразу сигнализирует об этом, и такая утилита удаляется в том же цикле уборки.

**Соблюдение.** Правило соблюдается самими агентами при реализации и при code review. ESLint-правила для него пока нет — это осознанная процессная договорённость, а не машинный запрет. Дубль правила для агентов — в [`AGENTS.md`](../AGENTS.md) → «Reuse Before You Write (Utilities Policy)».

### Не экспортируй символ, пока его не импортирует другой файл/модуль

Символ (функция, тип, атом, константа, компонент) попадает в `export` только тогда, когда его реально импортирует другой файл/модуль. Хелперы, типы, атомы и внутренние компоненты, которые используются только внутри своего файла, остаются приватными: экспорт без потребителя — мёртвая публичная поверхность, её удаляют, а не хранят «на будущее». Правило расширяет «Export only public API» из раздела про barrel-файлы на **все** файлы, а не только на barrel.

**Контроль.** `yarn check:unused` (knip) показывает неиспользуемые экспорты — каждый его вывод считать ошибкой ревью: экспорт (или файл целиком, если после удаления экспортов ничего не осталось) удаляется, а не игнорируется. Намеренно оставленный «про запас» экспорт перечисляется в `ignore` файла [`knip.config.ts`](../knip.config.ts) с комментарием-обоснованием — как и «про запас» утилиты выше.

### Если тип props не переиспользуется — инлайнь его в сигнатуру компонента

Тип пропсов компонента, который нигде больше не используется (другие компоненты, тесты, собирающие объект пропсов), не выносится в отдельный `interface`/`type` — он пишется инлайн в сигнатуре компонента. Отдельный `interface`/`type` заводится только при реальном переиспользовании; тест, который собирает объект пропсов, считается переиспользованием.

**Контроль.** Проверяется при code review глазами: пустой набор потребителей типа (grep по имени) означает, что тип должен быть инлайновым.

## Ведение документации docs/

- **Язык:** русский. Технические термины и кодовые идентификаторы — английским как есть.
- **Структура каждого типа документа** предсказуема и задана в [`README.md`](./README.md) (карта) — новый документ создаётся по тому же шаблону, что и соседние.
- **Перекрёстные ссылки** между документами и на конкретные пути в коде (`src/entities/player/model.ts`) — обязательны и относительные (`[architecture.md](./architecture.md)`).
- **Не выдумывать факты.** Если факт неизвестен — посмотреть в коде или оставить пометку `<!-- TODO: уточнить -->` и записать в `debt.md`.
- **Решения не стираются:** отменённое решение помечается зачёркиванием с объяснением в `decisions.md` (секция Superseded), а не удаляется.
- **Формат долга** (в `debt.md`): `- [ ] <что> — <где (пути файлов)> — <когда вернуться>`.
- **Закрытие долга:** закрытые записи удаляются из `docs/debt.md` в том же PR, где закрыты (не помечаются `[x]` и не копятся). Знание из записи переносится в профильный `docs/features|contracts`-документ (правило №2), а история закрытия остаётся в git (body коммита). `docs/debt.md` — только открытый бэклог.

## Стиль кода

Полный свод правил — в [`AGENTS.md`](../AGENTS.md) → «Code Style Guidelines». Ключевое, чтобы не нарушать:

- отсутствие точек с запятой, одинарные кавычки, 2 пробела, до 130 строк на файл;
- именованные экспорты в `src/`, `export default` только в `app/`;
- абсолютные импорты по слоям FSD, сортировка импортов (perfectionist);
- разложение больших файлов, а не удаление пустых строк для впихивания в лимит.
- **Запрет `as` в продакшн-коде:** `as Type` запрещён в `src/` (кроме `as const` и `as unknown` перед zod-валидацией). Вместо `as` — чинить типы на границах: нормализовать API-ответы в мапперах (`artwork: apiSermon.artwork ?? null`), конструировать новые объекты с narrowed-типами (`{ ...sermon, audioUrl: sermon.audioUrl }`), корректировать zod-схемы (`.nullable()` для полей, которые API отдаёт как null). В тестах `as` допустим, но минимален. Обоснование: `as` подавляет проверку типов — код компилируется, но крашится в рантайме (корневая причина Issue #45).
- **Валидация на границе JS→натив:** URI-значения проверяются (`hasUriProtocol`), нативные вызовы, способные бросить, — в try-catch; данные AsyncStorage — нелегитимный ввод (переживают апдейты). Подробнее: [`contracts/native-modules.md`](./contracts/native-modules.md).
- **Вызов JS из ворклетов:** `runOnJS` из `react-native-reanimated` устарел (deprecated) в Reanimated v4 — в новом коде не использовать. Для вызова JS-функций (сеттеры React-состояния, колбэки) из ворклетов и анимационных колбэков (`withTiming` completion, `useAnimatedReaction`, gesture handlers) используй `scheduleOnRN` из `react-native-worklets`. Сигнатура — `scheduleOnRN(fn, ...args)`, не каррированная (в отличие от `runOnJS(fn)(args)`). Синхронный вызов JS из ворклета падает с «Tried to synchronously call a Remote Function» (инцидент BoundaryHint, 2026-08).

## Расположение компонентов

- **UI-компоненты слайса** живут в папке `ui/` сегмента слайса (например `src/pages/history/ui/`), **не** в корне слайса. Тесты компонентов лежат рядом с компонентами в той же папке `ui/`.
- **Один компонент или хук на файл:** вспомогательные компоненты (например `HistorySeparator`, `SearchRowSeparator`) обязаны быть в собственном файле, а не объявлены внутри файла другого компонента.

## Barrel-файлы

- **Один barrel на слайс** (`index.ts` в корне слайса). Сегментные barrel-файлы (`ui/index.ts`, `lib/index.ts`) запрещены.
- **Именованные реэкспорты** вместо `export *` (включая форму `export * as NS`). `export *` скрывает реальную публичную поверхность и обезвреживает knip — barrel-файлы перечисляют экспортируемые символы явно. Barrel экспортирует только то, что действительно используется внешними потребителями; неиспользуемые символы, внутренние helper-функции и внутренние атомы наружу не экспортируются (`export *` к тому же противоречит правилу «Export on demand»: он автоматически затягивает мёртвую поверхность обратно). **Исключение:** barrel'ы `src/shared/api/generated/**` и реэкспорт `shared/api/index.ts` из них сохраняют `export *` / `export * as NS` — эта поверхность сгенерирована Orval и принадлежит генератору; поддерживать именованные списки над сгенерированным кодом вручную — трение и рассинхронизация. Правило именованных реэкспортов действует для всех рукописных barrel-файлов.
- **Запрет реэкспортов `shared/*` через верхние слои.** Слои `entities`, `features`, `widgets`, `pages` никогда не реэкспортируют ничего из `shared/*` — ни через shim-файлы, ни через строки в barrel (`export { X } from 'shared/...'`), ни значения, ни типы. Потребители импортируют из `shared/*` напрямую в месте использования. Исключения: сам `src/shared/**`, реэкспорты экранов в `app/` (expo-router), `@x`-сегменты. Мотивация и примеры — [`architecture.md`](./architecture.md) → «Запрет реэкспортов shared через верхние слои».
- **@x-сегменты** — узкие кросс-слойные точки входа (например, `@x/player.ts`), создаваемые по мере необходимости. Подробнее — [`architecture.md`](./architecture.md) → «@x cross-import».

## Циклические зависимости

- **Гвард:** `yarn check:circular` — прогон dependency-cruiser по `src/` на циклические зависимости (Metro require cycles). Конфиг — `.dependency-cruiser.cjs` в корне репозитория.
- **Когда запускать:** перед коммитами, затрагивающими импорты — новые файлы, реэкспорты, перемещения модулей, изменения barrel-файлов.
- **Политика:** новые циклы — `error` (команда завершается с ненулевым кодом); циклы, существовавшие на момент введения гварда (2026-08, book-reader), — `warn` и не блокируют. Список pre-existing циклов и исключения — в комментарии к конфигу.
- **Исключения из правила:** `src/shared/api/generated/**` (Orval-генерация), тест-файлы `*.test.ts(x)` и `__mocks__`.
- **Правило:** цикл не «подавляется» — новый цикл разрывается рефакторингом, а не добавлением в исключения.

## Тестирование

- Тест-файлы лежат рядом с компонентом/модулем: `ComponentName.test.tsx`.
- Покрываем: ключевые модели (например, `src/entities/playlist/model.test.ts`, `src/entities/player/model.ts` через `download-model`), hooks, утилиты (`timeConverters`, `version-check`, `sections-cache`), UI-компоненты (`PlayerControls`, `button`, `radio`, `modal`).
- **Accessibility-first в тестах:** для поиска элементов предпочитай средства доступности — текст (`getByText`), роль/метку (`getByRole`, `getByLabelText`, `aria-label`), а не `testID`. `testID` стараемся избегать: он дублирует идентичность, которая уже выражена через доступное имя/роль, и не проверяет реальную доступность компонента. `testID` допустим только когда текст/роль однозначно не подходят (например, безымянный контейнер без текста). Дополнительно: расширенные матчеры (`toHaveStyle`, `toBeDisabled`, `toBeExpanded`, …) встроены в `@testing-library/react-native` v12.4+ и подключаются автоматически при импорте (отдельный `extend-expect` не нужен); моки внешних зависимостей и hooks, `beforeEach` для сброса. Детали и пример — в [`AGENTS.md`](../AGENTS.md) → «Testing».
- **`fireEvent.press` (и другие `fireEvent.*`) — асинхронные в `@testing-library/react-native` `^14`.** В этой версии `fireEvent` возвращает `Promise` и требует `await fireEvent.press(...)` — без `await` синхронный `setState`-колбэк внутри обработчика может не успеть отфлашиться до следующего assert'а (тест «проходит» на неверном допущении, например читает состояние ДО ре-рендера). Симптом: `queryByText`/`getByText` после press видит старое состояние без явной ошибки. Всегда `await fireEvent.press(...)`; для эффектов, довершающихся после микротаска (например, `await` внутри обработчика — как в `CopyLinkButton.handleCopy`), дополнительно `await act(async () => {})` после press.
- Запуск: `yarn test` (watch, changed since main), `yarn testFinal` (все), `yarn testDebug` (локальные изменения), `yarn updateSnapshots`.
- Что не покрыто — фиксировать в `debt.md` (секция Tests).

## Порядок исправления ошибок линтинга

Исправление линтинговых ошибок — строго по escalations-лестнице:

1. `yarn lint:fix` — автоФикс всего, что умеет ESLint;
2. `yarn prettier:write` — прогон форматирования;
3. Всё, что осталось — ручные правки агента (извлечение компонентов/хелперов, НЕ сжатие строк и не удаление пустых строк).
4. После шагов 1–3: `yarn lint` для проверки, затем `yarn check:types`.

## Definition of Done (DoD)

Чеклист перед завершением PR:

- [ ] `yarn lint` — без ошибок;
- [ ] `yarn check:types` — без ошибок;
- [ ] `yarn check:fsd` (steiger) — без ошибок;
- [ ] `yarn testFinal` — тесты проходят;
- [ ] `docs/` обновлены в том же PR (затронутые `screens/`, `features/`, `contracts/`, `architecture.md` при необходимости);
- [ ] срезанные углы записаны в `docs/debt.md`;
- [ ] новые зависимости — только через `docs/decisions.md` (Approved stack);
- [ ] коммиты — conventional commits, заголовок ≤ 100 символов.

## Версионирование и релизы

- Версия управляется скриптом `node scripts/bump-version.mjs` (`yarn bump-version`). Также есть `version-major` / `version-minor` / `version-patch` (`yarn version --*`).
- Версия приложения читается в рантайме из `expoConfig.version` (`src/shared/config/version.ts`), используется в UI («О приложении») и для проверки обновлений.
- `android.versionCode` и `ios.buildNumber` (= `String(versionCode)`) выводятся из `pkg.version` в `app.config.ts`; `android.versionCode` проверяется в CI после prebuild.
- Сборки нативных билдов: `build:android`, `build:ios`, `build:all` (EAS).
